# 面试题维护：按概念收敛，不按公司复制

这套题库维护“面试演练层”。已有算法讲义和论文精读负责长篇原理，逐题回答包含口述、可独立理解的原理拆解、必要白板、追问、误区与项目证据。面经中的问题方向和技术答案分开核对。

1. 先查 `content/questions/interview/` 和统一清单中的 `concept`；相近题优先合并，补新题源和追问。`concept` 的去重是精确 key 检查，语义重叠需要人工判断。
2. 执行 `npm run new -- pt-your-topic interview`，生成独立草稿并预填下一个题号。使用 `category: interview`、稳定英文 ID 和 `Q21 · 问题` 格式标题。不要复制旧题文件后保留旧 ID，也不要随意重排已有题号。多个草稿并行时，正式登记前确认题号没有冲突。
3. 固定包含“60–90 秒回答、白板与例子、追问怎么接、项目怎么联系、容易答错的点、原理拆解”六个二级标题。公式定义条件、采样分布和归约；例子明确标为教学算例。
4. 在 `content/research/post-training-interview-practice-sources.json` 的 `questions` 登记稳定题号、唯一概念 key、主题组、来源 ID、关联原理笔记。题源可为公开题型改写或项目自拟；新题型只在一处维护题目正文和标题。
5. `sources` 集中记录链接、核对日期、用途和类型。社区面经另外记录帖子所标公司、经历自述/汇总/公开问答的证据范围以及全文/片段/摘要的可读范围。时间不完整就保留不完整，不补造年份。公司归类不代表招聘真实性或题目频率。
6. 技术解释回到原论文、官方代码/文档和独立推导；引用代码时固定核对 revision。面经里的参考答案可能错误，不能自动继承。不要绕过付费或登录限制，也不把整理页当官方题库。

每题末尾以及目录页预留这一对标记，标记间的内容由程序生成，不手工修改：

```markdown
[//]: # (interview-generated-start)

[//]: # (interview-generated-end)
```

```bash
npm run interviews:index   # 更新目录、来源、关联笔记和前后题链接
npm run interviews:check   # 重复编号/key、题页、来源及生成内容一致性
npm run topics:quality
npm test
npm run build
```

正文及 UI 变动后检查桌面和手机、搜索、公司标签、目录跳转、数学公式和直接刷新；推送后确认 Pages 部署及线上内容。构建会执行题库校验，题号、来源 ID 或题目标题变化时如未更新目录会明确失败。

三层内容的更新位置：概念定义与完整推导改原理笔记；面试表达及该题必需的推导与实现细节改对应主问题；新公司的相同问法改来源与追问。原始数据、未公开结果及个人责任信息只按可公开范围记录，不为填满模板编造实验。
