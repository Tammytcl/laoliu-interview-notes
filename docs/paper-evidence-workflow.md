# 论文收录的图表证据与发布流程

论文库一条记录对应一份可精读的论文报告。选题、下载、写五个标题、页面能加载、构建成功，任何一项单独成立都不代表精读完成。每篇必须先确定固定版本和证据，再写解释并发布；图表是论证的一部分，不是报告写完后的装饰。

## 从候选到报告

1. **Daily 记录候选，不批量发布短报告。** 记录问题、候选论文和纳入理由即可。决定精读后用 `npm run new:paper -- <id> <direction>` 建立 `draft: true` 的稳定记录。草稿不出现在论文库。
2. **固定来源并先列证据。** 把 `paper_url` 固定到 arXiv `vN`，核作者与单位；下载该版 PDF、HTML、LaTeX 到 `.paper-cache/<id>/`。先读正文和附录，做一张图表账本：方法对应哪张 Figure、实验配置对应哪张 Table、主结果/消融/失败条件对应哪些 Figure 或 Table。原文缺表时先记录缺口并停在草稿，不能找无关表格凑数。
3. **先核图表，再写结论。** `scripts/figure-crops/<id>.json` 的每个裁剪项写 PDF 页码、矩形和用途 `role`：`method`、`experiment-table`、`result-table` 或 `result-figure`。执行 `npm run papers:pdf-figures -- <id>` 后逐张与固定 PDF 对照，确认标题、坐标、图例、多子图、表头与末行完整。`figures.json` 记录原 PDF 与图文件 hash、页码、裁剪框、用途和 `visuallyVerified`。重新裁图导致字节或 PDF 版本变化时，核对状态自动重置，必须再次检查。
4. **围绕证据写五个模块。** 背景定义问题、前作和差异；方法沿输入、关键状态、训练/推理流程解释方法图；有官方代码就固定 commit 并核核心函数。实验写模型、训练数据、benchmark、指标、超参和算力账本。结果至少放两张原始图表证据，其中要有主结果与一个对照/消融/机制证据；实验或结果模块还要展示一张与论证相关的原论文表格截图。每张图表旁写清读法、条件、数值和结论边界，不能只放链接或转述几个数字。
5. **先审再发布。** `npm run papers:quality` 检查新报告和已纳入门槛的报告；`npm run papers:quality:strict` 检查所有已发布报告。然后人工核对内容事实、图意和页面布局，运行 `npm test`、`npm run build`、`npm run test:browser`，最后才把草稿改成 `draft: false`。CI 也直接运行结构门槛。自动检查能发现缺图、错位和缺出处，不能证明解释正确。

`method_figure` 必须引用正文方法模块中的 `role: method` 图片，论文库右侧才把它当方法预览。结果概览或概率曲线不能为了填满卡片而改名为方法图。`figures.json` 里的 `role` 是整理者对原图的人工分类，最终仍要对照 PDF 判定；填写字段本身不是验证。

## 历史欠账如何处理

截至 2026-10-01，[全库审查](./paper-audit-2026-09-30.md)所列 32 篇旧 OPD 报告中，GKD 与 MiniLLM 已按固定原文补齐，当前 39 篇已发布报告有 9 篇通过结构/证据初筛，30 篇仍缺必要内容。`content/metadata/paper-depth-legacy.json` 暂时只允许这 30 个**原样历史版本**继续展示，使已有链接与专题关联不失效；新增报告或改动旧短报告不能借用这个例外。`papers:quality:strict` 在旧报告全部补齐前会失败，因此不能宣称“全库精读已完成”。

32 篇旧报告对应的固定 PDF 版本、页数与校验值见[原文清单](./paper-source-inventory-2026-10-01.md)。这只完成资料定位；每篇仍须独立核对方法、表格、图意与正文。

修复历史报告按同一流程进行：先固定来源、登记真正的方法图和原表，再补背景/机制/实验，最后移出冻结名单。不要通过扩字、贴无关图、填写 `visuallyVerified: true` 或把结果图改成 `method` 来追求检查通过。现有报告中的 ESCD 和 EOS Disagreement 预览图需要重新核对用途；ESCD 当前预览实际是结果概览，不是方法图。
