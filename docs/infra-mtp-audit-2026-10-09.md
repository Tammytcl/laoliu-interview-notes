## 容易混淆的结论

- Meta 的 n 包含主 head，DeepSeek 的 D 数额外模块；训练模块数量、运行步数、候选树节点和接受长度独立计数。
- Meta Table S2 的 3.05× 相对同一个四头模型只用主 head；Table S5 的四头训练真实耗时为 NTP 的 1.07—1.22×。“无额外开销”不能覆盖这些测量。
- DeepSeek Table 4 推理时移除 MTP，衡量主模型质量；不是最终 671B 模型开启投机的测速。
- 权重说明的 MTP 独有参数是 11.5B，排除共享 embedding/output；2.4B 激活参数含共享部分，不能用激活参数计算全部存储，也不混成独立 14B 草稿权重。
- q 是实际 proposal 分布。greedy draft 对应 delta q，不能用原 softmax 代替；拒绝后直接从 p 重采有偏。
- 首个拒绝之后的候选和 KV 要撤销；纠正 token 已输出，不保证它的 KV 已计算，可能是下一轮 pending 输入。
- 最终行为概率不能用 draft head logprob 替代；API raw / processed logprob 与真实采样分布需逐项核对。

## CPU 练习

[脚本](../assets/infra/mtp-lab.py)与[实际结果](../assets/infra/mtp-lab-results.json)使用小张量、固定随机种子和 PyTorch CPU，不下载模型/数据：

- 整体 loss 与逐头调度的最大参数梯度差 `2.7755575615628914e-17`；toy 使用因果 prefix mean 与 Linear heads，真实 Transformer、FSDP 和 AMP 未复现。
- 验证两文档 offset 1/2/3 标签屏蔽；不把标签屏蔽等同 packed attention 隔离。
- p=[.2,.5,.3]、q=[.5,.3,.2]：接受率 .7，残差 [0,2/3,1/3]，解析恢复 p；100000 次采样得到 [.19884,.49939,.30177]。另核 deterministic proposal，朴素拒绝后从 p 重采得到 [.26,.45,.29]。
- 条件接受率 [.9,.9,.9] 时期望产出 3.439；假设每轮 cost 1.6/4.2，分别 2.149×/0.819×，不是 GPU benchmark。
- 4 头 logits 3.90625 GiB、单头 .9765625 GiB，仅计算张量存储，不宣称整体显存减少四倍。
