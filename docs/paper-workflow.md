# 论文收录与报告整理约定

目的：让每次收录都能服务于个人阅读、复述、连接和持续调研，而不止生成一份很长的报告。这个文档是后续整理任务的写作约定，不创建定时任务。

## 三种正文，三份模板

| 内容 | 模板 | 存放位置 | 何时使用 |
|---|---|---|---|
| 单篇精读 | `templates/paper.md` | `content/papers/<direction>/` | 准备读、觉得有价值或从 Daily 升级的论文 |
| Daily | `templates/daily-report.md` | `content/reports/daily/` | 每天开始工作时手动检索/复习与更新 |
| 专题调研 | `templates/survey-report.md` | `content/reports/surveys/` | 围绕研究问题比较多篇论文 |

单篇使用稳定 id；同一篇 arXiv 论文更新版本时仍更新原记录。Daily 每个日期一个文件，允许同一天多次追加。专题按研究问题持续更新，新增证据要说明改变了哪个判断。

## 单篇的最低完成标准

保留原文标题、作者、年份、精确版本和来源。说明为什么收录、阅读问题与先修，解释方法和关键推导，定位关键图表。按模板区分作者结论、整理者判断和待验证内容；不写没有核验的性能数字。保留局限、知识连接、本人复述问题和下一步。

`evidence: 资料整理` 表示已有阅读辅助材料；`已核原文` 应说明实际核过的段落与证据边界；`已复现` 必须有本人可核验的实验环境、配置和产物。即使资料已核验，也不意味着读者本人已经精读或复述。

## Daily 的更新方式

记录本次实际检索的来源/关键词/时间范围。候选可以收录、观察、暂缓或排除，写明理由，不要求每日新增。基础论文回读可以进入 Daily，但不要把收录日期当成论文发表日期。

挑一个主阅读，链接稳定论文记录并同步 `paper_ids`。个人尚未阅读时写“未开始”；Agent 不代填个人理解变化。实际阅读后记录读到哪里、修正了什么和下一步核验。无新增也能记录有效的阅读/复习进展。

## 专题报告的更新方式

先写一个明确研究问题和使用场景，再界定检索范围、纳入/排除规则和未覆盖路线。按机制构建方法谱系，并使用统一比较维度；模型、任务、硬件或预算不兼容时不直接排名。

引用论文库，写共识、分歧、证据强度、有条件结论、空白与最小验证。更新记录必须说明新增证据对原有结论的影响，不能只追加摘要。

## 可以交给 Agent 的任务描述

```text
请在这个仓库收录/更新以下论文（或执行一次手动 Daily、专题调研）：
目标论文/研究问题：……
重点方向和我当前想解答的问题：……
可用的原文/代码/真实实验材料：……

先查已有论文与报告，复用稳定 id，避免重复收录；按对应模板 v1 整理。
优先访问原论文和官方实现，说明实际核验范围，定位重要图表与实验条件。
解释关键机制，不仅复述摘要；区分作者结论、整理者推断与本人验证。
Daily 写实际检索范围、候选处理、主阅读和下一步；专题写范围、分类、比较和空白。
不要替我填写“我的理解”、已读状态或不存在的复现实验。
保留合上报告后能回答的问题，以及一个可验证的下一步。
完善关联链接、日期和更新记录，运行内容校验与构建。
```

## 日常使用与数据归属

页面的读前问题、复述、连接和复习日期可先写草稿，自动保存在当前浏览器；用论文模块的导出/导入迁移。它不会自动写回仓库或同步设备。需要持续积累的内容再由本人整理回 Markdown。报告正文与个人阅读状态分别维护，原有面试笔记的收藏/复习记录继续使用原备份方式。

Markdown 内容是公开仓库内容；私人阅读草稿可以只留在本地备份。不要将“AI 已经整理”当作“我已经掌握”。
