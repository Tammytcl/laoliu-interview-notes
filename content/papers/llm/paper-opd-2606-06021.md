## 1. 背景与已有工作

**阅读定位。**《OPRD: On-Policy Representation Distillation》放在 OPD 文献链条中，核心问题不是把一个最终答案从 teacher 复制给 student，而是 student 先在当前策略下生成前缀，teacher 再对这些真实会遇到的状态提供监督。这样可减少离线 teacher 轨迹与 student 部署轨迹的分布偏移，但代价是每轮都要生成、teacher 前向和更新，稳定性、概率空间以及评测预算会互相耦合。

本报告把贡献拆成“问题假设—训练信号—工程实现—证据边界”四层。与 SFT 相比，OPD 监督的是 student rollout；与 RL 相比，它通常不必为每题设计外部 reward，而以 teacher 分布或似然差为反馈；与离线 KD 相比，它能在 student 的错误前缀上纠偏。若 teacher 与 student tokenizer、终止符或能力分布不同，还会额外出现概率不可比、长度偏差或局部信号失真的问题。阅读原文时应先确认论文解决的是哪一层，而不是把所有提升笼统归因于“on-policy”。

这套定位也限定了结论：论文中的 benchmark 增益只能支持给定模型、数据和预算下的机制，不能自动外推到任意规模或任务。尤其需要区分 teacher 更强带来的上限、训练 token 更多带来的算力收益，以及新目标函数本身的贡献。后文保留原论文图表证据与负结果，避免只摘摘要中的最佳数字。

现有 OPD 大多对齐输出词表上的概率：完整词表 KL 信号丰富但显存/通信贵；只看 sampled token 便宜却信息少。OPRD 问：**student 在自己前缀上能否改学 teacher 的中间表示，而不只学最终 token 分布？** 隐状态包含许多在 LM head 映射到词表时被压缩或丢弃的信息，因而可能给小模型更丰富的结构监督。

这种“表示蒸馏”不同于固定数据上的 hidden-state matching；论文保留 on-policy 轨迹，使隐藏状态仍在 student 部署时可能遇到的前缀上计算。也不同于直接对 teacher/student 同层向量做 L2：模型隐藏维度与基底通常不同，需要一个共同桥接空间。

## 2. 方法与实现机制

![Figure 1：OPRD 与输出空间 OPD](./assets/papers/paper-opd-2606-06021/method-source.png)

原图让两条路线共享学生 on-policy rollout，然后分别从隐表示与输出概率提供教师反馈。OPRD 匹配的是表示方向，而非直接在词表维度对齐所有 logits；因此隐藏维度、监督层与尾部 token 的选择都是实现条件。图中的共享轨迹也说明它不是离线复制教师答案。 图源：[arXiv 2606.06021v1 LaTeX 源码](https://arxiv.org/src/2606.06021v1)，原始文件 `Figure/Overview.pdf`。

作为比较基线，student 轨迹记为 $y\sim\pi_\theta(\cdot\mid x)$，teacher 为 $\pi_T$。常见 token 级 on-policy 蒸馏的示意目标写成下式；它不代表本文所有变体都采用同一散度或同一梯度估计器：

$$\mathcal{L}(\theta)=\mathbb{E}_{x,\,y\sim\pi_\theta(\cdot\mid x)}\!\left[\sum_t D\!\left(\pi_\theta(\cdot\mid x,y_{<t}),\pi_T(\cdot\mid x,y_{<t})\right)\right].$$

这里最关键的是期望分布也依赖 student：参数更新后，下一批前缀会变，teacher 监督的位置随之移动。若实现先缓存 teacher 自己生成的固定答案，目标就退化为 off-policy；若 teacher 和 student 看到的模板、温度或 EOS 不一致，似然差还会混入协议偏差。散度是 reverse KL、forward KL、JS、回归损失还是经过门控的组合，会决定 mode-seeking、coverage 和梯度尺度，不能只用“KD loss”概括。

复现时建议把一次训练 step 拆成六个可审计阶段：固定 prompt 与模板；student 生成并记录 token/终止原因；teacher 在完全相同前缀上前向；构造论文定义的 token 掩码、权重或对齐；只对 student 反向；记录有效 token 数与梯度范数。对于跨 tokenizer 方法，还必须保存共同 byte/event 单元到两侧 token 的映射；对于自蒸馏，必须冻结 teacher 快照或明确同步频率；对于 verifier/多 teacher 方法，则要记录门控拒绝率与各 teacher 被选比例。

公式实现有三个常见陷阱。第一，用 batch mean 代替有效 token mean 会让长回答获得更大权重；第二，teacher logits 的温度缩放、top-k 截断和重新归一化次序会改变目标；第三，在本应 stop-gradient 的权重上反传，会引入论文没有的高方差项。最小测试应构造一个两 token 词表，手算每项概率、mask 与梯度方向，再做端到端小 batch 对照。本报告把论文原图与已有仓库线索分开：即使仓库存在，也应固定提交并逐项核对默认参数，不能用最新分支替代论文版本。

方法是否有效不能只看最终 accuracy。还要检查训练中 teacher-student KL、student 熵、回答长度、EOS 概率、有效更新 token 比例、梯度范数和 rollout 成功率。若主指标上涨却长度暴增、熵坍缩或 OOD 明显下降，应视为带代价的权衡。原文方法图、后续配置说明和结果图表共同构成可追溯链条。

OPRD 将 teacher 与 student 的隐藏状态各自投影到低秩桥接空间，比较同一 student-generated 前缀上的表示。论文用 PCA 基底构造 OPRD-Bridge，并讨论表示损失与输出空间 OPD 的结合。Table 1 对比两类“桥”：传统 logit 蒸馏以 $|V|$ 维词表单纯形作为共同空间；OPRD 用 $r$ 维低秩表示，目标是保留 LM head 之前的信息而减少大词表传输。

读公式时要逐项确认层的选取、teacher/student 隐维不同如何处理、投影基底如何估计、是否冻结、梯度是否穿过 teacher。这些决定方法是知识迁移还是让 student 迎合某个任意坐标系。文中还给出梯度方差与 LM-head 信息瓶颈的理论分析；定理的假设不等于所有实际模型都满足。

作者官方 [OPRD 仓库](https://github.com/ShenzhiYang2000/OPRD)已确认；本轮未逐函数核读，后续需把低秩投影和 hidden-state hook 的实现与公式核对。

## 3. 实验设置与算力



| 配置 | 原文设置 | 复现口径 |
|---|---|---|
| 数据 | DAPO-Math-17K | 输入 prompt 来自同一训练集 |
| 采样 | 每 prompt 2 条，温度 1.0 | 最大 response 长度 16,384 tokens |
| 批量 | 每 step 全局 8 个 prompts | 不与响应条数混记 |
| 表示监督 | 全部 28 层；最后 2,000 个 response tokens | 主实验为 OPRD-only 设置 |
| 优化 | AdamW，峰值学习率 1×10⁻⁵，500 steps | 3% 线性 warmup 后 cosine decay |
| 硬件 | 8×A100 80GB，FSDP，bf16 | 原文已披露，不能写成未知卡型 |
| 评测 | 温度 0.7，Avg@16 | AIME24/25 各 30 题，AIMO 83 题 |
| 判分 | 提取 boxed 最终答案、与官方解答 exact match | 不使用 teacher 分数代替正确性 |

配置来源：[原文第 9 页](https://arxiv.org/pdf/2606.06021v1#page=9)。三种蒸馏方式共享 rollout、每条轨迹的一次教师前向与优化日程；额外系统开销另由原文 Table 3 测量。

公平对照至少要固定 student 起点、训练 prompt、生成 token 总量和评测解码。只固定 step 不够：多 rollout、更长回答和更大 teacher 会显著增加计算。若论文没有完整 GPU 型号、卡数或 GPU-hours，本报告将其视作披露缺口；复现时需单独测量 student 生成、teacher 前向、反向传播和评测四部分 wall-clock。已有正文中的论文专属模型、数据和参数说明应与这张账本结合阅读。

统计上应报告多个随机种子或置信区间，并把 checkpoint 选择放在独立验证集。Pass@k 会随 k 和采样温度上涨，不能与 greedy accuracy 混写；LLM judge 需要固定版本与 prompt；verifier 过滤后的有效样本量也要报告。只有配置、预算和指标都对齐，结果差异才可归因于方法。

主实验使用 JustRL-1.5B teacher 与 R1-distill-1.5B student，在竞赛数学上比较 sampled-token OPD top-1、top-16 与 OPRD-Vanilla。AIME24、AIME25、AIMO 报 **Avg@16**。相同参数量不代表同等训练成本：读 teacher 中间层可能增加显存与跨卡传输，低秩桥又引入投影计算。

若复现，应固定 student rollout、响应上限与 teacher 查询次数，然后测 rank、层数、投影基底估计数据量对结果和显存的影响。论文没有给出足以覆盖每个系统设置的统一 GPU-hours，理论复杂度与真实多卡吞吐要分开。

## 4. 结果与图表解读

![Table 2：竞争数学推理 Avg@16](./assets/papers/paper-opd-2606-06021/table-2-results-pdf.png)

原表同时列出教师、未训练学生及三种 on-policy 蒸馏路线；粗体只在蒸馏方法组内比较，不能忽略教师本身的能力差异。OPRD 的质量结论建立在这些数学任务和固定模型配置上。读 Avg@16 时应保持相同采样协议，它不等价于挑选 16 次答案的 pass@16。 图表源：[arXiv 2606.06021v1 PDF，第 10 页](https://arxiv.org/pdf/2606.06021v1#page=10)，仅裁图表区域。

![Table 3：Actor 更新显存与耗时](./assets/papers/paper-opd-2606-06021/table-3-cost-pdf.png)

原表采用 batch 8、长度 16384、8 张 A100 80GB 和 FSDP。显存列测量 actor update_policy 相对起始基线增加的峰值，排除了常驻参数、优化器和梯度缓冲；时间列则是包含评测的 500-step wall-clock。两列测量范围不同，不能把显存节约比例当成总显存节约，也不能将时间列误写成单次更新耗时。 图表源：[arXiv 2606.06021v1 PDF，第 12 页](https://arxiv.org/pdf/2606.06021v1#page=12)，仅裁图表区域。

结果证据应形成闭环：主表回答“最终是否更好”，曲线回答“训练是否更稳/更快”，消融回答“哪个部件起作用”，成本表回答“是否等预算”。任一环节缺失都降低因果强度。尤其在 OPD 中，更强 teacher、更长 rollout 或更多 teacher 前向本身就可能提高分数，因此必须同时报告 teacher 调用量和生成 token。只引用平均值还会掩盖 AIME 这类小样本基准的高方差。

实践决策不能只追最高 accuracy。若目标是单次在线回答，应重视 Pass@1/Avg@k 与延迟；若允许 test-time scaling，才关注较大 k 的 Pass@k；若模型需要持续更新，还要测 OOD、遗忘和连续多轮蒸馏。本文据原图与正文只给“这些实验设置下”的结论，不把局部结果外推成普遍规律。

**Table 2** 的 AIME24：student **32.9**，OPD top-1 **42.3**，top-16 **47.1**，OPRD-Vanilla **49.8**，teacher **50.8**；AIMO 对应 **62.2/77.0/76.5/79.1/79.5**。AIME25 上 OPRD **34.6**，略低于 teacher **35.6**。这说明在所测任务上，表示监督缩小了 student-teacher 差距。top-16 在 AIME24 比 top-1 好，但在 AIMO 略低，也说明“多看几个词表 token”并不稳定覆盖所有缺失信息。

Table 1 的空间对照是解释结果的关键：从词表输出回到 hidden space，改变的不只是维度大小，还改变 teacher 给 student 的信号类型。不能只因 OPRD 分数高就说低秩永远比 full-logit 更省：实际需要保存哪些层、PCA 如何更新、投影 rank 多大，都影响总成本。

## 5. 局限、结论与后续阅读

共同局限可以归为四类：teacher 可能在 student 前缀上失准；on-policy 反复调用 teacher，训练成本高于离线 SFT；tokenizer/EOS/template 不一致会把协议差异伪装成知识差异；多数论文集中在数学或可验证任务，开放式对话、代码和长期遗忘证据仍少。OPRD: On-Policy Representation Distillation 应在这些边界内理解，不能因一个平均分提升就宣称普遍优于所有蒸馏或 RL 方法。

后续复现优先做等生成 token、等 teacher 前向和等 GPU-hours 三套对照，并报告长度、熵、KL、有效 token、梯度范数、OOD 与失败案例。阅读路线可依次对照普通 off-policy KD、标准 RKL OPD、本文专属改进以及同主题的稳定化/跨 tokenizer 工作。最终判断标准是“收益来自哪里、付出什么成本、在何种条件下失效”，而不是只复述摘要。

桥接空间的方向和秩可能对模型家族、层深、任务敏感；跨 tokenizer 虽不依赖共同词表，但仍需文本前缀对齐。当前强证据来自特定 1.5B 数学组合，尚不能证明大模型、多模态或任意推理长度有效。与 [cross-tokenizer BPM](#paper=paper-opd-2607-22334) 连读时可比较两条路：统一输出事件，还是绕过输出词表在隐藏层对齐。
