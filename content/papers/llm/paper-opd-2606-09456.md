## 1. 背景与已有工作

LLM 蒸馏中“教师给学生每个 token 的概率”有一个常被忽略的前提：两边的词表与 token 边界相同。Qwen 的一个 token 与 Llama 的某几个 token 即使拼出相同文本，也不是同一个离散动作。若只让 teacher 先写完整回答，再用 SFT 教 student，虽然跨模型族容易实现，却丢掉 teacher 的概率分布信息；若直接按 token 序号配对，两个位置的前缀文本可能不同，KL 项就没有清楚的语义。

这篇论文要解决的是：**student 已在自己的轨迹上生成了一段文本，teacher tokenizer 如何在相同文本前缀处评分，并把监督映射回 student 的 token？** 与只讨论静态语料的 cross-tokenizer KD 不同，目标状态来自当前 student 的 rollout。这是跨模型族 OPD 能否成立的基础。后续 [SimCT](#paper=paper-opd-2605-07711)、[BPM](#paper=paper-opd-2607-22334) 和 [ESCD](#paper=paper-opd-2609-34738)分别从共同监督单元、字节概率路由和不完整事件补全继续追问。

可以用同一个词的两种切法理解问题：teacher 把它写成三个 token，student 却只有一个 token。三个 teacher token 的条件 log-prob 之和能代表这整段文本在 teacher 下的联合 log-prob；但 student 那一个 token 没有“三个位置”可直接接收监督。相反，如果 teacher 一个 token 对应 student 两个 token，也不能任意把 teacher 的概率平均分给两个位置，因为两步的条件概率各自依赖此前已生成的文本。静态语料上的对齐方法 ALM/CDM 已尝试跨 tokenizer 转换，论文的新问题是怎样在 **student 当前 rollout** 上保留这种稠密信号，而不退回到离线答案模仿。

## 2. 方法与实现机制

**对齐点、chunk 与 credit assignment**

先把 student 生成的 token 序列解码成文本，再用 teacher tokenizer 重新编码。双指针从两端当前 token 向前推进，直到两边“已经解码出的文本前缀”相同，才建立一个同步点；相邻同步点之间是最小同步 chunk。设 student chunk 有 $m$ 个 token，teacher chunk 有 $n$ 个 token，它们覆盖同一段文本，却可能有 $m\ne n$。这一步的关键是**按实际文本边界对齐**，而不是按 token ID 或位置编号对齐。论文把它称为 Dual-Pointer Chunk Alignment（DPCA）。

![Figure 1 · 两种 tokenizer 的最小同步 chunk](./assets/papers/paper-opd-2606-09456/figure-1-pdf.png)

**Figure 1 解读。** teacher 的 `<think>` 是一个 token，student 将同样文本拆成 `<`、`think`、`>` 三个；红框内只有整个文本片段相等时才能建立同步点。后面的 `Okay` 两边各一个 token，可直接成为下一块。图示说明最小 chunk 怎样建立，不能把红框里的三个 student token 任意逐个对应到 teacher 的单个 token。[原图：arXiv v1 PDF，第 3 页](https://arxiv.org/pdf/2606.09456v1#page=3)。

在 chunk 级，teacher 各 token 的 log-prob 可相加，表示同一段文本在 teacher 自回归分解下的 log-prob。接下来要把这个 chunk 的学习信号分配到 student 的 token：论文 §4.2 使用 semantic prior 做 credit assignment，再在 §4.3 构成跨 tokenizer 的 OPD 更新。这里存在估计上的取舍：一段文本的概率是可比较的，而段内“哪个 student token 负责多少”并无唯一答案。对齐失败、特殊 token/chat template、Unicode 规范化和过长 teacher token 序列都可能造成监督缺失或偏差。

具体地，令 $L_T^{(c)}$ 是一个同步 chunk 内 teacher token 的 log-prob 之和，$L_S^{(c)}$ 是 student 旧策略在对应 chunk 上的 log-prob 之和。论文式 (8) 将目标信号分配为

$$
\log q_i=\frac{L_T^{(c)}}{L_S^{(c)}}\log p_i,\qquad
\hat A_i=\log q_i-\log p_i,
$$

其中 $p_i$ 是 student 在自己第 $i$ 个 token 上的旧概率。按比例缩放后，$\sum_i\log q_i=L_T^{(c)}$，同时保留 student 原本给各 token 的相对“意外程度”；这是有约束的 credit assignment，并不表示 teacher 真有每个 student token 的概率。若两边恰好一对一，优势退化为 $L_T-L_S$。在 PPO 式 clipped importance-ratio 更新中使用这个优势时，采样轨迹依然来自 student，teacher 只提供评分。式 (8) 还隐含旧策略 chunk log-prob 可用且数值稳定；极端概率和特殊 token 需要实作层的保护。

![Figure 3 · 同步 chunk 的 teacher log-prob 分配案例](./assets/papers/paper-opd-2606-09456/figure-3-pdf.png)

**Figure 3 解读。** 从上到下依次是 Qwen teacher 的 log-prob、映射后的信号、Llama student 自己的 log-prob 和二者相减得到的 advantage。蓝框是边界不匹配 chunk，灰框是直接一对一对齐。图中 teacher 把 `120` 拆成 `1,2,0`，student 把它作为单个 token；三个 teacher log-prob 相加为 −7.12，student 对 `120` 的 log-prob 为 −9.21，因此该 student token 得到约 +2.09 的优势。相反，teacher 的 `... ]` 被映射到 student 多个 token，必须再分配。这个算例让式 (8) 变得可检查，但单个算例不能证明全数据集的性能收益。[原图：PDF 第 8 页](https://arxiv.org/pdf/2606.09456v1#page=8)。

**核心源码与方法对照**

作者公开 [On-Policy-Distill](https://github.com/ivanniu/On-Policy-Distill)。静态核读 commit [`927a8264`](https://github.com/ivanniu/On-Policy-Distill/tree/927a8264f2e303b7f82c2d331a58fd4240c8805a)，主要实现位于 [`verl/workers/reward_manager/opd.py`](https://github.com/ivanniu/On-Policy-Distill/blob/927a8264f2e303b7f82c2d331a58fd4240c8805a/verl/workers/reward_manager/opd.py)。`retokenize_batch` 接收 student token ID 序列，解码文本、替换不同模型的 chat-template 标记，再用 teacher tokenizer 编码；它不是简单调用两个 tokenizer 的 `encode`，因为 special token 与结束符语义也要对齐。`_align_chunks` 用两个指针推进，比较标准化后解码文本；同步时把 teacher chunk 的 log-prob 求和，并按 student chunk 的 token 数分配给其位置。大 chunk 或 teacher 截断会被标为不可靠或跳过，说明“精确映射”也有明确的失效处理。`get_teacher_knowledge` 再把对齐后的监督接回训练 batch。以上为静态阅读，未执行分布式复现。

读代码时应沿 `retokenize_batch → teacher scoring → _align_chunks → get_teacher_knowledge` 追踪同一条序列，而不是只找一个 loss 函数。要重点检查三种长度：student token 数、teacher 重编码后的 token 数、文本字符数；它们相等的场景只是特例。对齐输出还要与 rollout 的有效 token mask 一起检查，否则 padding、EOS 或被截断位置也可能得到伪优势。上面公式给出论文定义，代码是静态实现证据；报告未声明它在所有 Unicode/chat-template 组合下已经过复现验证。

## 3. 实验设置与算力

作者测试两组 teacher→student：**Qwen3-8B → Llama-3.1-8B-SFT**，以及 **DeepSeek-R1 → DeepSeek-R1-Distill-Qwen-7B**。学生先用 OpenThoughts 的 **400K** 样本做 SFT 初始化，再在 student 自己的轨迹上做 OPD。训练 prompt 主要来自 OpenThoughts 和 DeepMath；实现基于 verl，并用独立 teacher 服务在线评分。评测覆盖 AIME24/25/26、MATH、GPQA-D 与 LiveCodeBench。

![Table 4 · SFT 初始化与 OPD 训练的原文超参数](./assets/papers/paper-opd-2606-09456/table-4-pdf.png)

**Table 4 解读。** 这是附录 A 的配置表，不是测得的“最低复现资源”。SFT 用 LLaMA-Factory、OpenThoughts、学习率 $10^{-4}$；OPD 用 VeRL、DeepMath/OpenThoughts prompt、学习率 $10^{-6}$。两阶段均为 AdamW、bf16、全局 batch 128、梯度裁剪 1.0；OPD 允许最多 1024 prompt token + 16,384 response token，并以 $T=1$、top-$p=1$、top-$k=-1$ 采样。表中没有 GPU 型号和卡数，不能由模型参数推断。[原表：PDF 第 12 页](https://arxiv.org/pdf/2606.09456v1#page=12)。

## 4. 结果与图表解读

![Table 1 · 两组 teacher/student 配对的六项 benchmark 结果](./assets/papers/paper-opd-2606-09456/table-1-pdf.png)

**Table 1 解读。** Qwen3-8B → Llama-3.1-8B-SFT 的六项平均分从 SFT 的 **35.1** 到 cross-tokenizer OPD 的 **40.7**；AIME25 从 **31.7** 到 **43.3**，但 GPQA-D 仅从 **1.5** 到 **7.6**，绝对值仍低。DeepSeek-R1 → Distill-Qwen-7B 的平均分从 **48.8** 到 **52.0**，说明收益并非只存在于一组模型。ALM/CDM 是同表的跨 tokenizer 基线，而非 teacher 原始成绩；这里可以比较方法，却不能拿两个不同 student 的 40.7 和 52.0 直接排强弱。[原表：PDF 第 6 页](https://arxiv.org/pdf/2606.09456v1#page=6)。

![Figure 2 · AIME24 上 OPD 与 SFT 外推的数据效率曲线](./assets/papers/paper-opd-2606-09456/figure-2-pdf.png)

**Figure 2 解读。** 横轴是累计训练数据（千条），纵轴是 AIME24 准确率；蓝色 OPD 曲线从 SFT-400K 起点继续增加 10K/20K 数据，灰色实线是现有 SFT 点，灰色虚线是作者外推。OPD 的 20K 增量达到 44.4%，而灰线要到更远处才相交。它直观展示的是**单项数学指标与数据点口径**，并未测出在同一 GPU 上的实际吞吐倍数。[原图：PDF 第 7 页](https://arxiv.org/pdf/2606.09456v1#page=7)。

![Table 2 · 达到 AIME24 44.4% 的估算 FLOPs 比较](./assets/papers/paper-opd-2606-09456/table-2-pdf.png)

**Table 2 解读。** Qwen3→Llama 案例中，作者估算 OPD 额外 **20K** 数据、SFT 外推需约 **482K**；按每条 16K token 的模型配置和 FLOPs 公式，表中给出约 **24.1×** 计算效率比。SFT 外推不是实际训练到 482K 新样本后测出的点，因而这个倍数同时依赖外推曲线和 FLOPs 假设；不能写成 24.1 倍实测 GPU 时间。其他 benchmark 的效率也不能由 AIME24 推出。[原表：PDF 第 8 页](https://arxiv.org/pdf/2606.09456v1#page=8)。

## 5. 局限、结论与后续阅读

论文解决的是跨 tokenizer 时如何恢复 student 自采轨迹上的 token 级监督，而非宣称任何两个 tokenizer 的概率都能无损一一对应。Chunk 的同步点、teacher 侧 chat template、特殊 token、teacher 截断和 credit 分配都可能改变有效训练样本。更细的字节前缀概率问题可接着读 [BPM](#paper=paper-opd-2607-22334)，部分 teacher token 已被 student 进入但未完成时的监督可接着读 [ESCD](#paper=paper-opd-2609-34738)。
