## 1. 背景与已有工作

这篇是 OPD 领域综述，阅读它的目的不是寻找一个新 loss，而是建立“论文为什么看起来都叫 OPD，却在解决不同问题”的地图。它从模仿学习和 student-generated state 出发，将方法按**优化目标、监督信号来源、训练稳定性**三个轴组织。外部 teacher 与自蒸馏是信号来源的第一层；外部 teacher 还需按白盒 logits、黑盒生成文本等可访问程度分开。

这个分类比只按“数学/代码”任务归类更适合读论文：同一个数学 benchmark 上，GKD 可研究前缀分布和散度，OPSD 研究特权信息自蒸馏，EOPD 研究高熵 token，MOPD 研究多专家信号。它们的对照组和代价边界都不相同。

## 2. 方法与实现机制

可把一轮 OPD 写成四个环节：student 在 prompt 上生成轨迹；teacher/自教师在这些轨迹的前缀提供概率、token 信号或上下文；一个目标函数把差异变成 student 更新；系统决定何时重采、如何传输 logits、如何控制方差。综述 Table 1 按这几个环节放置 GKD、MiniLLM、EOPD、OPSD 等方法，避免把“数据是 on-policy”误当成“loss 一定是 reverse KL”。

文章后半讨论三个实际约束。首先，teacher 可能在 student 的错误前缀上不可靠，on-policy 只是覆盖 student 状态，并不保证 teacher 回答对。其次，完整词表分布非常耗显存和带宽；sampled-token 实现更轻，却可能有更高方差。最后，跨 tokenizer、异构模型与多教师系统会让“同一 token”定义不再显然。综述也谈 GPU/通信成本与方法选择，但它汇集他人证据，不是一个统一预算的新实验。

文中引用的 Awesome-LLM-On-Policy-Distillation 列表是资料入口，不是这篇综述的训练代码。读它时应回到每篇原论文核对版本和表格，不能拿综述归纳替代原始实验。

## 3. 实验设置与算力

本论文没有统一的 student、teacher、训练集或 GPU 实验；“实验设置”应理解为**证据口径**。Table 1 将方法列的信号来源、目标粒度和主要贡献排在一张表中：例如 GKD 使用白盒 logits/逐 token 信号，MiniLLM 的重点是序列级 reverse KL，OPSD 属于自生成特权信息条件。Table 6–7 一带讨论失败模式、成本与稳定性。

为了用这篇综述选论文，可先问三件事：现有系统能否取到 teacher logits？student 和 teacher 是否共享 tokenizer？任务需要的是单教师能力迁移、自教师内化，还是多领域整合？三问的答案决定哪些论文的结果可以直接借鉴。文章不披露 GPU-hours，因为没有运行统一复现；引用中不同工作的硬件不能求平均。

## 4. 结果与图表解读

原文 **Table 1** 是阅读导航，而非“方法排行榜”。例如 GKD 与 MiniLLM都在 OPD 谱系内，但一个把采样比例和逐 token 散度统一，另一个研究序列 reverse KL；表格中的 Category 不代表性能高低。其公式分类章节把目标函数、信号来源、动态稳定三维展开，适合把本库论文放回坐标中。

综述的价值是指出多论文比较的常见陷阱：结果表可能一个报 Avg@8、一个报 Pass@16；有的包含 SFT cold start，有的从已指令化模型出发；有的只算 student 更新，有的把 teacher RL 成本算入全流程。若引用“方法 A 优于 B”，必须先看是否同 teacher/student、同 prompt、同 rollout token、同评测脚本。该综述不产生新的统一胜负结论。

## 5. 局限、结论与后续阅读

适合先读这篇确定路线，再回到目标算法原文做精读。综述截止写作时的论文覆盖受版本、开源程度与作者选择影响，新出的跨 tokenizer 和多教师工作可能改变图景。可以把它作为本专题索引，但每条复现细节仍应以具体论文与固定代码版本为准。后续阅读建议从 [GKD](#paper=paper-opd-2306-13649) 建立基本式，再根据关心问题走向 [MOPD](#paper=paper-opd-2606-30406)、[SimCT](#paper=paper-opd-2605-07711) 或 [OPSD](#paper=paper-opd-2601-18734)。
