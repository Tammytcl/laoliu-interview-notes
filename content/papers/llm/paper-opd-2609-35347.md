## 1. 背景与已有工作

把数学、代码、指令遵循三个 RL 专家交给一个 student 时，最容易注意的是“题目该由哪个 teacher 教”。[基础 MOPD](#paper=paper-opd-2606-30406)按领域标签指定 teacher；但即便标签正确，不同领域 teacher 给出的 sampled-token log-prob 差值尺度也可能相差很大。共享 student 的优化器把这些数值汇合到一批梯度中，信号大的领域可能主导更新。论文在第一批 Qwen3.5 训练数据中观察到：指令领域的 log-ratio 离散度是合并批次的 **2.3–4.4 倍**，数学约为其一半。此处离散度只是反馈数值的性质，不能直接当作教师质量。

DN-MOPD 的问题是：**在保持领域路由与 teacher 不变时，只校准每个领域的反馈尺度，能否让学生更好地保留各专家能力？** 与 [MOPD-Router](#paper=paper-opd-2609-30837)用分布信息改变 teacher 权重不同，它不重新选择 teacher，也不创造新的奖励。这个区分有助于分别定位“谁教得对”和“谁说话太大声”。

## 2. 方法与源码对照

每道 prompt 有领域 $d$。student 生成回答后，匹配的 teacher 在相同前缀上评价 student 实际采样的 token。令 $r_{i,t}=\log p_{T_d}(y_{i,t}\mid h_{i,t})-\log p_{\mathrm{roll}}(y_{i,t}\mid h_{i,t})$。在当前 batch 的有效 response token 上计算各领域标准差 $\sigma_d$，以及所有领域 token 合并后的 $\sigma_{\mathrm{all}}$；权重是

$$w_d=\operatorname{clip}(\sigma_{\mathrm{all}}/\sigma_d,\,0.25,\,4),\qquad \widetilde A_{i,t}=\operatorname{stopgrad}(w_{d_i}A_{i,t}).$$

若领域 token 少于两个或标准差退化，则回退 $w_d=1$。权重为正且只乘不减均值，因此保留每个优势原来的正负号；它匹配的是**尺度**，不是让各领域梯度范数严格相等，也不是估计能力差距。Actor 随后重算更新前的 log-prob，使用原来的 clipped OPD surrogate。因而和 label-routed 基线对比时，改动可以归结到优势缩放。

作者 [DN-MOPD 仓库](https://github.com/LiXin97/DN-MOPD/tree/fc1e569596ba32be754ff8ce47ee5b535953a3d4)将机制封装得较清楚。[`batch_statistics`](https://github.com/LiXin97/DN-MOPD/blob/fc1e569596ba32be754ff8ce47ee5b535953a3d4/dn_mopd/normalizer.py#L55)按有效 token 和领域积累计数、和与平方和，再由 `domain_multipliers_batched` 计算有界倍率；这避免 padding token 污染 $\sigma_d$。[`clipped_opd_loss_batched`](https://github.com/LiXin97/DN-MOPD/blob/fc1e569596ba32be754ff8ce47ee5b535953a3d4/dn_mopd/loss.py#L47)先对每条回答的有效 token 求均值，再对回答求均值，长回答不会只因 token 多就有更大的直接权重。仓库实现为多卡统计加入跨 rank 汇总；该静态代码核读不能替代大规模复现。

## 3. 实验设置与算力

论文分别构建 Qwen3.5-9B、4B、2B 的同尺寸专家池，三个 RL 专家对应数学、代码、IF。比较初始 student、单 teacher OPD、Uniform Pool、Dynamic Router、按标签 OPD、DN-MOPD，也报告离线 SeqKD-SFT 与参数合并。相同尺寸内固定专家、学生初始化、prompt 和 **80 次更新**，主训练 response 上限 **8,192 token**；主要结果用 seed 42，附录以 43/44 检查稳健性。

数学测 AIME25/26，代码测 LiveCodeBench v5/v6，指令测 IFEval/IFBench；每题分别采样 **64/6/16** 次，先对题目求平均，再对六个 suite 等权平均。主表评测回答上限 **16,384 token**，论文另检查较短长度。评测 cap 与训练 cap 不同，长回答被截断率必须连同准确率一起读。原文没有给出可直接比较所有方案的 GPU-hours；专家 RL、SeqKD 生成与在线 teacher 评分的成本也不同，表格的相同步数不等于全流程等算力。

## 4. 结果与图表解读

**Table 1–2** 的六任务 Total：9B 初始学生 **57.1**、Label **58.4**、DN-MOPD **59.6**；4B 的 Label **50.3**、DN-MOPD **52.5**；2B 分别 **26.6** 与 **29.0**。**Table 3** 将 DN 相对 Label 的提升列为 **+1.17/+2.24/+2.36 个百分点**，三种模型都同向，但不能误写为相对百分比增长。主收益来自数学；作者指出 Label 在 16K 评测 cap 下三个规模的数学都未超过初始 student，而 DN 在三个规模都提高。与此同时，9B 的代码并未随 DN 一起提高，说明归一化不是逐领域无损融合。

一个关键反例是离线 SeqKD-SFT：9B Total **62.6**，仍高于 DN 的 **59.6**；4B/2B 亦如此。论文的可靠结论是“在固定 label-routed OPD 设置中校准反馈改善结果”，不是“DN 超过所有融合路线”。**Table 4** 还显示 9B Label 回答触及长度上限的比例 **9.8%**，DN 为 **5.2%**；4B 为 **12.4%→5.3%**，2B 为 **20.2%→13.5%**。这提示结果可能部分来自更合理的终止与长度分布，不能只看最终精度。Figure 1 的跨规模曲线和 Figure 3 的专家能力对照，应与这张长度表一同理解。

## 5. 局限与阅读结论

DN-MOPD 解决的是一个容易被路由研究掩盖的优化问题：已经选对 teacher，还要让不同 teacher 的反馈数值有可比尺度。它没有证明 $\sigma_d$ 是最优校准统计，也未在跨 tokenizer 教师池、更多领域或极不均衡 batch 上给出同等强证据。小领域 batch 若 token 太少会回退到 1，固定的 0.25–4 截断也可能阻止完全对齐。下一步值得做的是在相同专家池中交叉比较 DN 与动态路由，并报告领域梯度范数、teacher 前向量和 GPU-hours。
