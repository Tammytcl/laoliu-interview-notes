## 1. 背景与已有工作

多教师 on-policy distillation（MOPD）通常先解决 teacher assignment：数学 prompt 交给数学 teacher，代码交给代码 teacher，指令遵循交给 IF teacher。这个视角隐含了一个不易察觉的数值假设——三位 teacher 产生的 token-level OPD 优势虽然来自不同策略，却能直接放进同一个 student optimizer 比较。若某一领域的 log-ratio 分布天然更分散，即使它的 teacher 没有更可靠，该领域也会因为梯度标量更大而主导共享参数更新。

论文在 Qwen3.5 的首个训练 batch 观察到，IF teacher 的 log-ratio spread 是合并 batch 的 **2.3–4.4 倍**，数学约只有总体的一半。这不是“IF 更重要”或“数学 teacher 更差”的能力证据，只说明三个 RL 专家相对 student 的概率尺度不同。把原始数值直接相加，就像让音量最大的专家获得更多更新预算。即使领域标签完全正确，capability integration 仍可能失败：单独训练的数学专家明显提升数学，但 label-routed student 没能保留这部分增益。

DN-MOPD 因此把研究问题从“该选谁教”改成“已经选对 teacher 后，各领域的反馈应以多大尺度进入共享更新”。它不改变 prompt 的领域标签、不混合 teacher 分布，也不训练动态 router；每条 response 仍由唯一领域 teacher 评分。与 [MOPD-Router](#paper=paper-opd-2609-30837) 的差异很关键：Router 改监督来源，DN 改监督尺度。论文还把 SeqKD-SFT、参数平均、task arithmetic、单 teacher OPD、uniform pool 和 dynamic router 放在同表，避免只与弱基线比较；但这些路线的生成、token exposure 和优化预算并不完全相同，最终总分不能自动解释为等算力效率。

## 2. 方法与实现机制

### 两套 log-prob：估计尺度与更新 actor

每个 prompt 带领域 $d$。旧 student rollout policy $\pi_u$生成回答 $y$，匹配的领域 teacher $T_d$在同一 token 前缀上打分。DN-MOPD 先从缓存 rollout log-prob 计算当前 batch 的 teacher–rollout 差：

$$
r_{i,t}=\log p_{T_{d_i}}(y_{i,t}\mid h_{i,t})-\log \pi_u(y_{i,t}\mid h_{i,t}).
$$

只在有效 response token 上统计每个领域标准差 $\sigma_d$ 与所有领域合并标准差 $\sigma_{all}$，倍率为：

$$
w_d=\operatorname{clip}\!\left(\frac{\sigma_{all}}{\sigma_d},0.25,4\right).
$$

数学反馈较窄时 $w_d>1$，IF 反馈较宽时 $w_d<1$；裁剪防止小样本或退化标准差把权重推到极端。领域有效 token 少于 2 或方差退化时回退 $w_d=1$。该权重在当前 batch 动态估计，不是从最终评测调出的固定超参数。

更新时 actor 会重算当前 log-prob，优势 $A_{i,t}=\ell_T-\ell_{actor}$，再乘对应领域倍率并 stop-gradient：

$$
\widetilde A_{i,t}=\operatorname{stopgrad}(w_{d_i}A_{i,t}).
$$

$w_d$恒正，所以每个 token 的鼓励/惩罚符号不变；它校准的是标量 spread，不会严格让不同领域的参数梯度范数相等，也不保证领域更新贡献完全均衡。actor 随后仍使用原 MOPD 的 clipped importance-ratio surrogate，DN 的最小改动只在优势缩放。

![Figure 2 · 一次 DN-MOPD 训练迭代](./assets/papers/paper-opd-2609-35347/figure-2-pdf.png)

**Figure 2 解读。** 第 1 步 student 对带领域标签 prompt rollout；第 2 步每条 response 仍只交给匹配的 frozen teacher，说明 DN 没有改 teacher assignment；第 3 步用缓存 $\ell_T-\ell_{roll}$估计 $\sigma_d/\sigma_{all}$，再把倍率施加到 actor-side $\ell_T-\ell_{actor}$；第 4 步执行原 clipped OPD。底部箭头表明倍率每轮重估。Label-routed MOPD 正是所有 $w_d=1$ 的特例。[原图：固定 PDF Figure 2](https://arxiv.org/pdf/2609.35347v1#page=3)。

### 为什么用相对 spread，而不是均值或 reward

OPD 优势的正负已经表达 teacher 相对 student 对 sampled token 的偏好；减领域均值会改变绝对基线，甚至改变 token 符号。只除以 $\sigma_d$ 又会改变全局步幅。DN 用 $\sigma_{all}/\sigma_d$，目标是把每域 spread 拉回本 batch 的 pooled reference，同时保留总体量级。由于统计基于 response mask，padding 不会进入方差；多卡训练还需要跨 rank 汇总 count、sum、square-sum，否则每张卡看到的领域构成不同会得到不一致倍率。

官方实现固定在 commit [`fc1e569`](https://github.com/LiXin97/DN-MOPD/tree/fc1e569596ba32be754ff8ce47ee5b535953a3d4)。[`batch_statistics`](https://github.com/LiXin97/DN-MOPD/blob/fc1e569596ba32be754ff8ce47ee5b535953a3d4/dn_mopd/normalizer.py#L55)按 mask 和 domain 汇总统计量，`domain_multipliers_batched`处理裁剪与退化回退；[`clipped_opd_loss_batched`](https://github.com/LiXin97/DN-MOPD/blob/fc1e569596ba32be754ff8ce47ee5b535953a3d4/dn_mopd/loss.py#L47)先对每条 response 的有效 token 求均值，再跨 response 求均值，避免长回答仅因 token 多获得更大直接权重。仓库还发布逐题正确性记录，便于核对表格不确定性；本报告只做静态源码审查，没有执行分布式复现。

## 3. 实验设置与算力

作者从 Qwen3.5-9B、4B、2B 各自构建同尺寸数学、代码、IF 三专家池；student 从同尺寸初始 checkpoint 出发。teacher 数据分别来自 DeepMath-103K、Eurus-RL-Code 与生成的 instruction-following prompts。student 训练集固定 2,700 prompts，每域 900；同一尺寸下所有方法共享初始化、专家 roster、prompt mixture 与 OPD 预算。主训练用 seed 42，另以 43/44 检查稳健性。

| 项目 | 固定配置 / 口径 |
| --- | --- |
| Student / teacher | Qwen3.5 9B、4B、2B；每个 student 学同尺寸三位领域专家 |
| Student 数据 | 2,700 prompts：math/code/IF 各 900，带领域标签 |
| 主 OPD 预算 | 80 updates；每 rollout batch 64 prompts × 8 responses = 512 responses |
| 优化器 | Adam；LR $10^{-6}$；5 warm-up updates；betas (0.9, 0.98)；weight decay 0.1；grad clip 1.0 |
| Rollout | temperature 1.0；prompt cap 2,048；training response cap 8,192 |
| SeqKD-SFT | 固定 teacher answers；84 updates；global batch 128；LR $10^{-5}\to10^{-6}$ cosine；生成 cap 16,384 |
| 数学评测 | AIME25/26 各 30 题；每题 64 answers |
| 代码评测 | LCB v5/v6，167/175 个不重叠问题；每题 6 answers |
| IF 评测 | IFEval-541、IFBench-300；每例 16 answers；strict prompt correctness |
| 评测 cap | 同一 checkpoint 在 8,192 与 16,384 两个 response cap 下评估；主表使用 16K |
| 随机性 | generation seed 42；主训练 seed 42；附录追加 43/44 |
| 计算资源 | 论文未披露 GPU/TPU 型号、卡数、GPU-hours或能耗；不能从 80 updates 推算 |

![Tables 4–5 · 回答长度、截断率与延长训练](./assets/papers/paper-opd-2609-35347/tables-4-5-pdf.png)

**Tables 4–5 解读。** Table 4 把同一评测输出的 Total、各域平均 response tokens 与触及 16K cap 的比例并列；这让读者检查精度提升是否只是生成更长。Table 5 从各方法 80-update checkpoint 延长到 160 updates（不同规模实际轨迹到 125/144/160），比较 label、DN 与 development-selected single teacher 是否只是收敛速度不同。延长后差距缩小但 DN 在三个规模仍领先；最终极限排序仍未被证明。[原表：固定 PDF Tables 4–5](https://arxiv.org/pdf/2609.35347v1#page=9)。

不同路线不完全等预算：SeqKD 复用固定 teacher corpus，OPD 每轮生成新 student response；参数合并没有在线 teacher forward；expert RL 的构建成本又在 student 融合之前发生。因此主表回答的是“按论文给定 recipe，最终能力如何”，不是端到端 FLOPs 公平竞赛。原文没有硬件信息，这一缺口必须保留，而不是用模型尺寸或 update 数自行估算。

## 4. 结果与图表解读

![Table 1 · 9B 的六任务能力整合结果](./assets/papers/paper-opd-2609-35347/table-1-pdf.png)

**Table 1 解读。** 9B initial student Total **57.1**，Label-routed MOPD **58.4**，DN-MOPD **59.6**，说明只改尺度可在相同 teacher assignment 上增加约 **1.17 个百分点**（未四舍五入差值）。DN 在 AIME25/26 和两项 IF 上高于 Label，但 LCB v5/v6 为 56.3/51.4，低于 Label 的 56.8/52.6，不能写成逐域无损融合。SeqKD-SFT **62.6**、ParamMerge-TA **60.5**仍高于 DN；论文的有效结论是改善 label-routed OPD，不是所有融合路线 SOTA。[原表：固定 PDF Table 1](https://arxiv.org/pdf/2609.35347v1#page=5)。

![Figure 3 · 三个模型规模的专家专长矩阵](./assets/papers/paper-opd-2609-35347/figure-3-pdf.png)

**Figure 3 解读。** 每行是一位专家、每列是评测领域，数值为相对同尺寸 initial student 的 16K 增益。对角线普遍最大：9B math expert 数学 +4.5、IF expert IF +6.2；4B code expert 代码 +9.3；2B code/IF expert 分别 +10.3/+9.4。这验证 teacher pool 确有可转移专长。非对角线既有正也有负，例如 9B math expert 代码 -1.7、IF expert 数学 -2.6，说明简单平均参数或信号可能发生干扰；但矩阵本身不证明 DN 是唯一解决办法。[原图：固定 PDF Figure 3](https://arxiv.org/pdf/2609.35347v1#page=7)。

![Figure 4 · 反馈尺度、领域增益与训练中倍率](./assets/papers/paper-opd-2609-35347/figure-4-pdf.png)

**Figure 4 解读。** (a) 三个规模都显示数学 spread 低于 pooled reference、IF 远高于 reference；(c) 因此数学倍率大致在 1.5–2 上下，IF 很快触及下限 1/4，虚线给出裁剪前更低的值，代码接近 1。(b) DN 相对 Label 在数学上约 **+4.0/+3.8/+3.7 pp**，代码为 **-0.8/+2.1/+2.9**，IF 为 **+0.4/+0.8/+0.5**。这支持“主要恢复数学能力、并限制 IF 大尺度支配”，也明确暴露 9B 代码回退。[原图：固定 PDF Figure 4](https://arxiv.org/pdf/2609.35347v1#page=8)。

跨规模六任务 Total 中，4B Label **50.3**、DN **52.5**；2B Label **26.6**、DN **29.0**，未四舍五入提升为 **+2.24/+2.36 pp**。长度表显示 Label 到 DN 的 at-cap 比例：9B **9.8%→5.2%**，4B **12.4%→5.3%**，2B **20.2%→13.5%**；数学平均 response 也显著缩短。因此增益不是靠更多 token 硬撑出来，反而伴随更少截断。但长度变化也是机制结果的一部分，不能把精度提升完全归因于“更均衡梯度”而忽略终止行为。

## 5. 局限、结论与后续阅读

DN-MOPD 说明正确 teacher assignment 仍不足以保证能力整合：多位独立 RL 专家的 sampled-token log-ratio 可能有系统性尺度差异，共享 student 会偏向 spread 较大的领域。用当前 batch 的 $\sigma_{all}/\sigma_d$做有界正缩放，是一个很小、可插拔且跨 9B/4B/2B 同向改善 Label 基线的修正。Figure 3 证明专家专长存在，Figure 4 把尺度、倍率与领域增益连起来，长度/延长训练表则检查两个明显混淆因素。

它没有证明标准差是最优校准统计：方差受尾部 token、领域 batch 构成与 response 长度影响；极小领域会回退为 1；固定 0.25–4 截断让 IF 在三规模长期饱和。倍率校准 scalar advantage，不直接约束参数梯度方向或各域梯度范数。实验只有三个领域、同系列同尺寸 teacher，硬件与 GPU-hours 未披露；SeqKD 仍更高，也提醒读者在线稠密监督不是唯一有效整合路线。

复现时应先验证 mask、跨 rank 统计与 response-level reduction，再记录每域 $\sigma_d$、裁剪命中率、token 占比、梯度范数和 at-cap 比例。下一步最有价值的实验是在同一专家池中正交组合 [MOPD-Router](#paper=paper-opd-2609-30837) 与 DN：前者决定每个 token“听谁”，后者决定被选信号“多大声”，并以统一 GPU-hours 比较 full-pool router、label+DN 和 router+DN。
