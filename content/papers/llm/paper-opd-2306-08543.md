## 1. 背景与已有工作

**研究问题。** 一个大 teacher 能写出很多不同但合理的答复，小 student 却只能用较少参数表达其中一部分。常见蒸馏让 student 拟合人工答案或 teacher 生成的固定答案；逐 token 的 word-level KD 给 soft label，SeqKD 则把 teacher 的整段输出当训练文本。两者都让 student 在固定前缀上学习，部署时却必须接着自己的文字往下写。如果第一句偏了，后面的前缀就可能是训练中从未出现过的状态，这就是自回归生成的训练—推理轨迹错位。

第二个问题是目标函数。固定 teacher 样本上的最大似然近似最小化 $D_{KL}(p\|q_\theta)$，其中 $p$ 是 teacher 的序列分布，$q_\theta$ 是 student。直观地说，teacher 所有常见回答模式都要求 student 给足概率；在容量不足时，student 可能把质量分摊到不理想的过渡区域。论文用玩具分布说明 forward KL 的覆盖倾向，并提出反向 $D_{KL}(q_\theta\|p)$，从 student 实际会写出的回答中挑 teacher 也认为好的部分。这里的“mode seeking”意味着优先保住主模式，也自然带来遗漏少数合理回答的风险，不能把它直接翻译成“生成质量无条件更好”。[原文第 2–3 页](https://arxiv.org/pdf/2306.08543v6#page=2)。

因此 MiniLLM 的核心是把 **数据分布** 与 **优化目标** 同时换掉：由 student 自身生成候选，在这些完整序列上用 teacher 的概率评估，并最小化序列级反向 KL。它与 [GKD](#paper=paper-opd-2306-13649) 都让 student 看到自己的轨迹，但 GKD 的主实验以位置对齐的 token 分布散度为目标，MiniLLM 则从整段序列概率之比推导 policy-gradient 更新，并专门解决估计方差、短回答偏置和奖励投机。两者不是同一实现换个名字。

论文做的是白盒 teacher/student 蒸馏。teacher 不只给可读答案，还要给 student 输出各 token 的概率；若只有只能返回文本的 API，原方法无法照搬。后面的实验以指令遵循为主，重点检验小模型是否在未见过的指令上仍有质量，以及多样性、校准和长回答是否被反向 KL 损坏。这些辅助实验是必要的，因为单个 GPT-4 评分即使提高，也无法排除模型只是输出更短、更模板化或更碰巧符合评测偏好的文字。

## 2. 方法与实现机制

设 $x$ 是指令，$y=(y_1,\ldots,y_T)$ 是完整回答。MiniLLM 的理论目标是 student 序列分布到 teacher 序列分布的反向 KL。把序列概率分解为逐 token 条件概率后，每个位置都有 $r_t=\log p(y_t\mid x,y_{<t})-\log q_\theta(y_t\mid x,y_{<t})$，整段回答的质量信号是这些差值的和：

$$
\mathcal L(\theta)=D_{KL}(q_\theta(\cdot\mid x)\|p(\cdot\mid x))
=\mathbb E_{y\sim q_\theta(\cdot\mid x)}\bigl[\log q_\theta(y\mid x)-\log p(y\mid x)\bigr].
$$

![Figure 3 · SeqKD 与 MiniLLM 的采样来源及目标对照](./assets/papers/paper-opd-2306-08543/figure-3-pdf.png)

**原图解读。** [Figure 3，第 3 页](https://arxiv.org/pdf/2306.08543v6#page=3)左侧 SeqKD 的回答来自 teacher，然后以固定样本训练 student，优化方向对应 forward KL；右侧红色路径是 student 生成 $y\sim q_\theta$，teacher 在这些样本上提供概率反馈，目标是 reverse KL。图中的红色“on-policy”不是说 teacher 代替 student 写文本，而是 student 所访问的输出分布参与训练。这里的 reverse KL 是**整段序列分布**之比，不应只拿某个 token 的 reverse KL 结果代替它。

由于离散采样不易直接反传，原文首先用 policy-gradient 展开。第 $t$ 个 token 的梯度由从该位置到结尾的累计质量 $R_t=\sum_{t'=t}^{T}r_{t'}$ 加权；这使前面一个 token 要为后续整段质量负责。好处是可以利用实际生成的完整回答，困难是 Monte Carlo 估计方差大：一条回答前面出现偶然的坏词，就会污染很多位置的梯度。原文第 3–4 页从式 (1) 推到式 (2)，再把单步项和未来长程项拆开。单步项可以对整个词表求和，精确计算而不依赖一次采样；长程项仍用采样估计。这是 **single-step decomposition**，不等于把序列目标降格为普通逐 token 监督。

论文给稳定训练加了两种措施。第一，teacher-mixed sampling 在每个 token 上用 $\tilde p=\alpha p+(1-\alpha)q_\theta$ 生成，实验取 $\alpha=0.2$。它让早期小 student 不至于只写重复、无意义或异常短的文本；但由于采样分布不再严格是 $q_\theta$，需要重要性权重修正。论文写出整段前缀比率的无偏形式，又承认连乘权重会使方差过大，实际近似为当前 token 的比率。这意味着实现是在偏差与方差之间取舍，不能宣称“混合采样后仍完全无偏”。第二，对未来奖励按剩余长度归一化，缓解短回答因累计负值较少而占优；训练还用 clipping 限制更新。

![Algorithm 1 · MiniLLM 两阶段训练和三项梯度](./assets/papers/paper-opd-2306-08543/algorithm-1-pdf.png)

**原图解读。** [Algorithm 1，第 5 页](https://arxiv.org/pdf/2306.08543v6#page=5)先要求 student 在指令—答案数据上 SFT，并以验证损失选择起点；随后循环采样 prompt、从混合分布生成回答，分别计算精确单步项、归一化长程项，还从独立预训练语料取 batch 加语言建模损失。最后三项梯度合并更新。额外 LM loss 用于维持一般语言能力，不是蒸馏损失本身。若跳过 SFT、长程项或预训练语料，只保留一个 reverse-KL 名称，复现的就不再是论文完整训练过程。

**作者源码伴读。** 在官方 [LMOps/minillm，固定代码提交 6f53ef4](https://github.com/microsoft/LMOps/tree/6f53ef41c951de0962bbf27fe3f5819eabc8ce0e/minillm) 中，[`train_minillm.py`](https://github.com/microsoft/LMOps/blob/6f53ef41c951de0962bbf27fe3f5819eabc8ce0e/minillm/train_minillm.py) 加载 teacher 并把 `Reward.reward_fn` 传给训练器。[`reward.py`](https://github.com/microsoft/LMOps/blob/6f53ef41c951de0962bbf27fe3f5819eabc8ce0e/minillm/minillm/reward.py) 在 `torch.no_grad()` 下运行 teacher，以 `gather` 取生成 token 的 logit，再减 `logsumexp` 得逐 token 的 teacher log-prob；这里并不是调用外部偏好模型打分。[`sampler.py`](https://github.com/microsoft/LMOps/blob/6f53ef41c951de0962bbf27fe3f5819eabc8ce0e/minillm/minillm/sampler.py) 生成混合轨迹和 student 轨迹，计算 teacher log-prob、student log-prob 及单 token 重要性比率；[`losses.py`](https://github.com/microsoft/LMOps/blob/6f53ef41c951de0962bbf27fe3f5819eabc8ce0e/minillm/minillm/losses.py) 的 `_get_advantages_and_returns`、`_pg_loss`、`_reg_loss` 对应长度归一化的长程项、clipped policy 更新和全词表单步正则。代码还依赖作者修改过的 Transformers 生成接口，不能把标准 Hugging Face `generate()` 直接传 `mix_in_model` 就期待可运行。此处是静态源码核读，未声称端到端训练复现。

## 3. 实验设置与算力

**训练数据和模型。** 论文从 databricks-dolly-15k 指令—答案集中划出 1,000 条验证、500 条测试，其余约 12,500 条训练；超过上下文长度的样本先过滤。为保留通用语言能力，GPT-2 家族另用 OpenWebText，其他模型用 RoBERTa 训练语料作为预训练损失的数据源。主结果包括 GPT-2 teacher 1.5B 对 120M、340M、760M student；OPT teacher 13B 对 1.3B、2.7B、6.7B student；LLaMA teacher 13B 对 7B student。原文首页 Figure 1 还补充 GPT-J 6B teacher 的尺度分析，但主表应按各家族各自的 teacher 逐组读，不能跨组把绝对分数归因于蒸馏算法。[原文第 5–6 页](https://arxiv.org/pdf/2306.08543v6#page=5)。

**评价集与指标。** DollyEval 是划出的 500 条本域测试；SelfInst 有 252 条用户指令；VicunaEval 有 80 条困难问题；Super-NaturalInstructions 的测试集约 9,000 条、覆盖 119 个任务；UnNI 从 UnnaturalInstructions 抽 10,000 条。论文用 ROUGE-L 衡量与参考答案的最长公共子序列重合，用 GPT-4 反馈比较模型与参考答案并给分，还在 SelfInst 做人工 win/tie/loss 比较。GPT-4 只用于 DollyEval、SelfInst、VicunaEval；不能把其他两列误当 GPT-4 评分。测试时 temperature=1，对每个 prompt 用五个随机种子采样，平均指标；这是多次随机生成条件，不是只取 greedy 最佳样本。

| 环节 | 原论文设置 | 复核时应留意 |
| --- | --- | --- |
| SFT 起点 | 在 Dolly 指令数据上 3 epochs，取最低验证损失 checkpoint | 与基线按 ROUGE-L 挑选 checkpoint 的准则不同 |
| MiniLLM 第二阶段 | learning rate 5e-6，mini-batch 64，5,000 steps | 不能与第一阶段的 LR 搜索混同 |
| rollout 与更新 | 每次收集 256 句，4 inner epochs，student 温度 1 | 生成开销是主要成本之一 |
| 重要性与稳定性 | teacher 混入 $\alpha=0.2$，clip $\epsilon=0.2$，最大长度 512 | 混合分布与 student 分布要分清 |
| 基线 | SFT、逐 token KD、SeqKD | 相同 student 尺寸内比较 |
| 选模 / 测试 | 第二阶段以 validation ROUGE-L 选 checkpoint；测试五种随机种子 | GPT-4 与 ROUGE-L 不是同一尺度 |

上表依据 [原文附录 B.1](https://arxiv.org/pdf/2306.08543v6#page=18)，把主文没有展开的训练配置拉到一处。小于 1.3B 的基线搜索 5e-4、1e-4、5e-5 与 batch 32/64，大模型基线搜索 5e-5、1e-5、5e-6；这些是**基线调参范围**，不能误写成 MiniLLM 第二阶段的统一设置。主表的行是不同 student 和训练法，列是不同数据集与指标；读取前必须先锁定一个模型家族和 student 尺寸。

**算力口径。** 附录 B.1 明确写 NVIDIA V100 32GB；LLaMA-13B teacher 蒸馏 LLaMA-7B student 在 **16 张 V100 上少于 10 小时**。这是该实验配置的观察，不是 GPT-2/OPT 所有实验的总预算，也不包含从零预训练 teacher 或准备数据的成本。训练需要边生成 student/teacher 混合轨迹边查询 teacher logits，所以显存、并行策略和吞吐都会影响实际复现费用。作者仓库另有 DeepSpeed、模型并行和对应启动脚本；若换成 A100/H100，应重新实测而非按卡数线性换算。[原文第 18 页](https://arxiv.org/pdf/2306.08543v6#page=18)。

## 4. 结果与图表解读

![Table 1 · GPT-2、OPT、LLaMA 的完整主结果表](./assets/papers/paper-opd-2306-08543/table-1-pdf.png)

**原表解读。** [Table 1，第 7 页](https://arxiv.org/pdf/2306.08543v6#page=7)按模型家族、student 参数量分组。以 GPT-2 120M 为例，DollyEval 的 GPT-4 分数从 SFT 的 38.6、word-level KD 的 40.3、SeqKD 的 41.2 到 MiniLLM 的 **44.7**；同组 Dolly ROUGE-L 从 23.3、22.8、22.7 到 **24.6**。SelfInst 的 GPT-4 从 SFT 26.3 到 MiniLLM 29.2，VicunaEval 的 ROUGE-L 为 16.9。读者必须先确认列名：DollyEval、SelfInst、VicunaEval 各有 GPT4 与 R-L 两列，S-NI、UnNI 只有 R-L。星号表示 student 超过对应 teacher 的**该列分数**，不是所有指标全面超过 teacher。报告旧版本把 38.6 写出来却没给出 44.7，导致无法判断提升规模；此处补齐同组对照。

主表总体显示 MiniLLM 在多数同容量比较中领先，但也能看到有些列差距很小，不应把每一个粗体都解释为显著性检验。例如 GPT-2 340M 的 Dolly ROUGE-L，SFT 为 25.5，MiniLLM 为 25.4，MiniLLM 并非该列最优。OPT 2.7B 的 Dolly GPT-4 从 SFT 55.4 到 MiniLLM 63.2，LLaMA 7B 则从 SFT 73.0 到 MiniLLM 76.4；这些是同尺寸内更清楚的跨家族例子。GPT-4 反馈使用论文附录中的打分提示词，不是现今任何新版 judge 的可直接复现数值。数字之外，还应观察开放生成是否把答案缩短以讨好指标，这正是下面消融要验证的。

![Table 4 · 去掉三项稳定策略后的质量变化](./assets/papers/paper-opd-2306-08543/table-4-pdf.png)

**原表解读。** [Table 4，第 9 页](https://arxiv.org/pdf/2306.08543v6#page=9)在 GPT-2 120M 蒸馏设置下，完整方法的验证/Dolly ROUGE-L 为 **27.4/24.6**；去掉长度归一化降为 **17.4/14.7**，去掉 teacher-mixed sampling 为 **22.3/20.4**，去掉 single-step decomposition 为 **27.0/23.7**。这说明长回答偏置校正和混合采样在该配置中尤其关键，单步分解的主价值还包括降低训练方差，不能只凭表中的较小均值差断言它“无用”。表是组件消融，不是与 SeqKD 的公平主结果；读取时也不能把 Valid. 27.4 当成 Dolly test 分数。原文 Figure 8 的 reverse-KL 曲线进一步显示：即使数值目标下降，没有稳定措施也可能学出重复、短或无意义的输出。

![Figure 6 · 随生成长度积累的 exposure-bias 误差](./assets/papers/paper-opd-2306-08543/figure-6-pdf.png)

**原图解读。** [Figure 6，第 8 页](https://arxiv.org/pdf/2306.08543v6#page=8)横轴是生成长度，纵轴 ExAccErr 是训练解码差异导致的额外误差，越低代表该指标定义下的暴露偏差越少。红线 MiniLLM 在 GPT-2 120M / Dolly 测试中整体低于 SFT、KD、SeqKD，超过约 150 token 后趋于平缓；橙色逐 token KD 则继续上升。该图支持“训练时看见自己的输出有助于控制误差积累”的解释，但它只测这一模型与指标，不代表所有长文本任务的事实正确性已经改善。附录还列出校准表和 distinct-4-gram 表：反向 KL 有模式丢失风险，因此作者单独查词汇多样性与测试语料语言建模损失，而不是把高 GPT-4 分数当成多样性证据。

## 5. 局限、结论与后续阅读

MiniLLM 的关键启发是：反向 KL 的序列级目标可以让小 student 在自己会写的答案中寻找 teacher 认可的区域，但要把它训练好，必须同时处理高方差、短输出偏置和混合采样带来的重要性校正。Figure 3 是思想差异，Algorithm 1 是实际训练环，Table 1 是整体质量，Table 4 和 Figure 6 则分别检查关键组件与轨迹错位；只看第一张漂亮的结果表会漏掉真正困难的部分。

适用边界包括同 token 空间下可访问 teacher log-prob、已有足够好的 SFT 起点，以及能承担持续采样与 teacher 前向的计算预算。论文报告的是 2023–2024 年代的 GPT-2、OPT、LLaMA 和指定评测流程，不能直接外推到今天长思维链、跨 tokenizer 或黑盒教师场景。反向 KL 的 mode-seeking 对需要多样备选回答的任务可能是代价；论文的 distinct-4-gram 结果只覆盖其评测设置，不等于证明不会 mode collapse。源码对照是静态阅读，尚未运行训练或独立复验数值。

后续可与 [GKD](#paper=paper-opd-2306-13649) 比较 token 散度和序列散度，再读 [EOPD](#paper=paper-opd-2603-07079) 对高熵位置的处理。主要来源为 [arXiv 固定 v6 原文](https://arxiv.org/abs/2306.08543v6)及[作者 LMOps 源码固定提交](https://github.com/microsoft/LMOps/tree/6f53ef41c951de0962bbf27fe3f5819eabc8ce0e/minillm)；公式与数字均据此核对。
