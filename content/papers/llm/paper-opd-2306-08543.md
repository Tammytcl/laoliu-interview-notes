## 1. 背景与已有工作

如果 student 比 teacher 小很多，直接最大化 teacher 给出的答案概率，常会逼 student 覆盖自己做不到的多模态分布。MiniLLM 把问题提到**完整回答序列**：与其在固定 teacher 答案上做 forward KL，不如让 student 生成它实际会写的回答，再用 teacher 对这些回答的序列概率提供偏好。这样既处理了训练与推理轨迹不一致，也使目标更偏向 teacher 的高概率模式。

它与 [GKD](#paper=paper-opd-2306-13649)同属 OPD 基础线，但粒度不同：GKD 强调逐 token 分布、可选择散度；MiniLLM 重点分析 sequence-level reverse KL 及其 policy-gradient 估计。两者不能仅因都提到 reverse KL 而视作相同更新规则。

## 2. 方法与实现机制

设 student 序列分布为 $q_\theta(y\mid x)$、teacher 为 $p(y\mid x)$，MiniLLM 优化 $D_{KL}(q_\theta\|p)$，期望在 student 自己的采样序列上计算。展开后包含 student 的序列 log-prob 与 teacher 的序列 log-prob；离散采样不能直接微分，论文用 REINFORCE 类估计，并加入方差降低与稳定策略。关键是 teacher 对**student 生成的答案**给分，而不是 student 只模仿 teacher 的固定答案。

核读源码时应区分序列级目标和逐 token 的实现：日志概率按时间求和，梯度却通过各位置 sampled token 的 log-prob 传回。长度归一化、奖励基线与 teacher 对低质量早期 rollout 的评分决定梯度噪声；只摘一个 reverse-KL 公式看不出这些工程选择。作者把复现代码放在 [LMOps/minillm](https://github.com/microsoft/LMOps/tree/main/minillm)；本轮确认官方入口，尚未逐函数审读，不虚构函数调用链。

## 3. 实验设置与算力

主要实验是指令遵循，使用 GPT-2、OPT 与 LLaMA 不同尺寸的 teacher/student；数据和评测覆盖 DollyEval、SelfInst、VicunaEval、Super-NI、UnNI。论文把 GPT-4 反馈与 ROUGE-L 并列，因此一个方法在词面重合度和主观有用性上可能出现不同排序。比较 SFT、word-level KD、SeqKD 与 MiniLLM 时要确认同一学生尺寸与数据设置。

Table 1 中 GPT-2 1.5B teacher→120M student 是明确的小模型压力测试；“7B student”所在的 LLaMA 组又是另一种容量差距，不能跨组把数字直接相减。原文详细训练超参数和开销另列附录，主表没有统一 GPU-hours；序列级 on-policy 方法还需要重复生成 student 样本和计算 teacher 概率。

## 4. 结果与图表解读

原文 **Table 1** 在 GPT-2 组的 DollyEval GPT-4 评分里，120M student 的无蒸馏 SFT 是 **38.6**；MiniLLM 在该组报告更高评分，且在不同模型系列的多数列优于 word-level KD/SeqKD。表格跨多个模型分块，阅读时先找到对应 student 行再比较，不把不同尺寸的 MiniLLM 行合成一个“总分”。该表同时展示了 GPT-4 评分与 ROUGE-L：二者衡量的不是同一件事，词面指标不能单独代表指令执行质量。

论文关于 reverse KL 的分析解释了为何可能得到更锐的输出分布；它同时预示 mode collapse 风险。若使用确定性解码，质量提升看起来可能更大；若需要多样采样，应读作者对多样性与覆盖的附图，而不是只看 Table 1 的均值。MiniLLM 的意义是证明序列级 reverse-KL OPD 在指令生成中可行，不等于“reverse KL 对所有任务最优”。

## 5. 局限、结论与后续阅读

这篇工作要求可查询 teacher 对 student 完整生成序列的 log-prob，黑盒只给文本时不能照搬目标。REINFORCE 的估计方差、长回答长度偏置与 teacher/student 容量差距是复现重点。后续 [EOPD](#paper=paper-opd-2603-07079) 专门讨论 reverse KL 在高熵位置压缩多样性的副作用；把两篇连读，比只背“反向 KL 更好”更有价值。
