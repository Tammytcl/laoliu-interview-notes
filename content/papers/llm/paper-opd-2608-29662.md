## 1. 背景与已有工作

**阅读定位。**《ACTD: Anchor-Based Cross-Tokenizer Distillation with Residual Regularization》放在 OPD 文献链条中，核心问题不是把一个最终答案从 teacher 复制给 student，而是 student 先在当前策略下生成前缀，teacher 再对这些真实会遇到的状态提供监督。这样可减少离线 teacher 轨迹与 student 部署轨迹的分布偏移，但代价是每轮都要生成、teacher 前向和更新，稳定性、概率空间以及评测预算会互相耦合。

本报告把贡献拆成“问题假设—训练信号—工程实现—证据边界”四层。与 SFT 相比，OPD 监督的是 student rollout；与 RL 相比，它通常不必为每题设计外部 reward，而以 teacher 分布或似然差为反馈；与离线 KD 相比，它能在 student 的错误前缀上纠偏。若 teacher 与 student tokenizer、终止符或能力分布不同，还会额外出现概率不可比、长度偏差或局部信号失真的问题。阅读原文时应先确认论文解决的是哪一层，而不是把所有提升笼统归因于“on-policy”。

这套定位也限定了结论：论文中的 benchmark 增益只能支持给定模型、数据和预算下的机制，不能自动外推到任意规模或任务。尤其需要区分 teacher 更强带来的上限、训练 token 更多带来的算力收益，以及新目标函数本身的贡献。后文保留原论文图表证据与负结果，避免只摘摘要中的最佳数字。

这篇论文与本专题有关，是因为它研究**跨 tokenizer 的知识蒸馏与多教师融合**；但其主要训练流程是离线 teacher 数据上的 ACTD，原文不应被误标为严格的 student on-policy OPD。专题保留它作边界与对照：对齐字词表、切分位置和残余概率质量的问题，在跨 tokenizer OPD 中同样会出现，但数据来源与更新状态分布不同。

ACTD 关心两个层次的不一致。词表层面，teacher 的高概率 token 不一定有一一对应的 student token；序列层面，同一文本的边界错位，让“第 $t$ 个 token 对第 $t$ 个 token”不成立。只做序列答案 SFT 会丢掉 teacher 的软分布，只靠同名 token 又损失覆盖。

## 2. 方法与实现机制

![ACTD：跨 tokenizer 对齐、锚点与残差](./assets/papers/paper-opd-2608-29662/method-source.png)

原图先处理词表与序列对齐，再计算 anchor-based loss，并对其余概率质量施加残差约束。锚点用于避免把噪声映射当成完整可靠的教师分布，残差项则防止只学习少量匹配 token 而丢失其余结构。各模块解决不同层面的问题，不是简单把教师 logits 换一套下标。 图源：[arXiv 2608.29662v1 LaTeX 源码](https://arxiv.org/src/2608.29662v1)，原始文件 `pics/method_camera_ready.pdf`。

作为比较基线，student 轨迹记为 $y\sim\pi_\theta(\cdot\mid x)$，teacher 为 $\pi_T$。常见 token 级 on-policy 蒸馏的示意目标写成下式；它不代表本文所有变体都采用同一散度或同一梯度估计器：

$$\mathcal{L}(\theta)=\mathbb{E}_{x,\,y\sim\pi_\theta(\cdot\mid x)}\!\left[\sum_t D\!\left(\pi_\theta(\cdot\mid x,y_{<t}),\pi_T(\cdot\mid x,y_{<t})\right)\right].$$

这里最关键的是期望分布也依赖 student：参数更新后，下一批前缀会变，teacher 监督的位置随之移动。若实现先缓存 teacher 自己生成的固定答案，目标就退化为 off-policy；若 teacher 和 student 看到的模板、温度或 EOS 不一致，似然差还会混入协议偏差。散度是 reverse KL、forward KL、JS、回归损失还是经过门控的组合，会决定 mode-seeking、coverage 和梯度尺度，不能只用“KD loss”概括。

复现时建议把一次训练 step 拆成六个可审计阶段：固定 prompt 与模板；student 生成并记录 token/终止原因；teacher 在完全相同前缀上前向；构造论文定义的 token 掩码、权重或对齐；只对 student 反向；记录有效 token 数与梯度范数。对于跨 tokenizer 方法，还必须保存共同 byte/event 单元到两侧 token 的映射；对于自蒸馏，必须冻结 teacher 快照或明确同步频率；对于 verifier/多 teacher 方法，则要记录门控拒绝率与各 teacher 被选比例。

公式实现有三个常见陷阱。第一，用 batch mean 代替有效 token mean 会让长回答获得更大权重；第二，teacher logits 的温度缩放、top-k 截断和重新归一化次序会改变目标；第三，在本应 stop-gradient 的权重上反传，会引入论文没有的高方差项。最小测试应构造一个两 token 词表，手算每项概率、mask 与梯度方向，再做端到端小 batch 对照。本报告把论文原图与已有仓库线索分开：即使仓库存在，也应固定提交并逐项核对默认参数，不能用最新分支替代论文版本。

方法是否有效不能只看最终 accuracy。还要检查训练中 teacher-student KL、student 熵、回答长度、EOS 概率、有效更新 token 比例、梯度范数和 rollout 成功率。若主指标上涨却长度暴增、熵坍缩或 OOD 明显下降，应视为带代价的权衡。原文方法图、后续配置说明和结果图表共同构成可追溯链条。

方法先做 **first-subtoken vocabulary alignment**，再用 **nearest monotonic boundary alignment** 保证顺序不交叉；在对齐到的共同事件上，以 teacher 高概率区域作 anchor 构造损失，对无法可靠对应的残余词表质量加正则，减少噪声监督。多教师版本将各 teacher 经过相同对齐接口再融合。读公式时应分辨“anchor 的概率”与“residual mass”的来源，不能以为后者也被精确对齐。

这种设计给跨 tokenizer OPD 的启发是：即使能映射候选字符串，也要问未映射的质量去哪了；不处理 tail 会使归一化偏差大。官方 [ACTD 仓库](https://github.com/hyhy892/ACTD)已确认；本轮未逐函数核读。若复现，先用真实 tokenizer 的 Unicode、空白、EOS 例子验证单调边界与 first-subtoken 映射。

## 3. 实验设置与算力

![Table 7：ACTD 训练超参数](./assets/papers/paper-opd-2608-29662/table-7-config-pdf.png)

原表仅包含 ACTD 的训练配置，已去掉同页其他结果表和正文。不同基线的参数在另一张表中，不能默认所有方法完全相同。跨 tokenizer 蒸馏还需要记录 teacher/student 的原生模板和对齐策略；相同 batch 数也可能对应不同数量的 student token 与 teacher token。 图表源：[arXiv 2608.29662v1 PDF，第 14 页](https://arxiv.org/pdf/2608.29662v1#page=14)，仅裁图表区域。

| 复现维度 | 必须记录的字段 | 为什么重要 |
|---|---|---|
| 模型协议 | checkpoint、tokenizer、chat template、EOS | 决定概率是否可比 |
| 采样预算 | prompts、每题 rollout、温度、top-p、最大长度 | 决定探索与成本 |
| 优化 | loss、学习率、batch、累积、step/epoch | 决定梯度尺度 |
| teacher 成本 | 前向 token、logits/top-k、缓存策略 | OPD 的主要额外开销 |
| 评测 | seed、样本数、Avg@k/Pass@k、judge | 防止口径漂移 |
| 算力 | GPU 型号、卡数、GPU-hours | 判断收益是否等预算 |

公平对照至少要固定 student 起点、训练 prompt、生成 token 总量和评测解码。只固定 step 不够：多 rollout、更长回答和更大 teacher 会显著增加计算。若论文没有完整 GPU 型号、卡数或 GPU-hours，本报告将其视作披露缺口；复现时需单独测量 student 生成、teacher 前向、反向传播和评测四部分 wall-clock。已有正文中的论文专属模型、数据和参数说明应与这张账本结合阅读。

统计上应报告多个随机种子或置信区间，并把 checkpoint 选择放在独立验证集。Pass@k 会随 k 和采样温度上涨，不能与 greedy accuracy 混写；LLM judge 需要固定版本与 prompt；verifier 过滤后的有效样本量也要报告。只有配置、预算和指标都对齐，结果差异才可归因于方法。

student 为 Qwen3-1.7B-Base，teacher 使用 DeepSeek-R1-Distill-Qwen-7B、Llama-8B、DeepSeek-R1-0528-Qwen3-8B，另加入 GLM-4-9B-Chat 检验跨模型家族。评测数学 AIME24/25、AMC23、Minerva、MATH500，以 **AVG8 / PASS8** 双指标报告；训练/评测有 **8192 token** 长度约束。比较 SeqKD、Multi-ULD、单教师/多教师 ACTD。

这里的“跨 tokenizer”是结构因素，不能把 ACTD 的结果直接当 [SimCT](#paper=paper-opd-2605-07711) 等在线方法的等预算对照；后者每轮还生成 student rollout 并实时查询 teacher。原文没有统一覆盖两类算法的 GPU-hours。

## 4. 结果与图表解读

![Table 1：多教师—学生组合的推理结果](./assets/papers/paper-opd-2608-29662/table-1-results-pdf.png)

原表分组列出异构教师与学生的推理蒸馏结果，包含不同模型族和对照路线。应先确定每一组的 teacher→student，再比较方法，避免把较强教师的提升归因于 ACTD。平均分以外还要检查弱项，并区分同 tokenizer 与异 tokenizer 条件，才能判断对齐机制的价值。 图表源：[arXiv 2608.29662v1 PDF，第 6 页](https://arxiv.org/pdf/2608.29662v1#page=6)，仅裁图表区域。

![残差系数的 Avg@8 与 Pass@8 消融](./assets/papers/paper-opd-2608-29662/residual-ablation-source.png)

原图随残差正则系数变化同时报告 Avg@8 和 Pass@8，观察概率集中与覆盖面的不同反应。最佳系数由这些实验支持，不是跨模型的常数；过弱或过强残差约束都可能改变锚点学习与全分布保留之间的权衡。两种指标不能相互替代，也不应只摘各自最高点。 图源：[arXiv 2608.29662v1 LaTeX 源码](https://arxiv.org/src/2608.29662v1)，原始文件 `pics/residual_0526.pdf`。

结果证据应形成闭环：主表回答“最终是否更好”，曲线回答“训练是否更稳/更快”，消融回答“哪个部件起作用”，成本表回答“是否等预算”。任一环节缺失都降低因果强度。尤其在 OPD 中，更强 teacher、更长 rollout 或更多 teacher 前向本身就可能提高分数，因此必须同时报告 teacher 调用量和生成 token。只引用平均值还会掩盖 AIME 这类小样本基准的高方差。

实践决策不能只追最高 accuracy。若目标是单次在线回答，应重视 Pass@1/Avg@k 与延迟；若允许 test-time scaling，才关注较大 k 的 Pass@k；若模型需要持续更新，还要测 OOD、遗忘和连续多轮蒸馏。本文据原图与正文只给“这些实验设置下”的结论，不把局部结果外推成普遍规律。

**Table 1** 的多教师 T1+T2+T3→student 组，SeqKD 五项 AVG8 均值 **20.9**，Multi-ULD **24.1**，Multi-ACTD **29.0**；PASS8 对应约 **44.3/42.1/51.1**。这说明在该多教师、异构 tokenizer 配方里，显式对齐与残余正则比简单序列模仿或已有 logit 统一方法更有利。AIME25 的绝对分数仍不高，提示难题能力迁移有限。

读图表时先锁定 teacher 组合、8K 上限和指标列；例如某 teacher 的 AIME24 强，不代表它在所有 task 都是最佳老师。论文对不同 tokenizer 距离的分析属于方法解释，但未把在线 rollout 变量加入实验，所以它不能证明 OPD 必然得到同幅收益。

## 5. 局限、结论与后续阅读

共同局限可以归为四类：teacher 可能在 student 前缀上失准；on-policy 反复调用 teacher，训练成本高于离线 SFT；tokenizer/EOS/template 不一致会把协议差异伪装成知识差异；多数论文集中在数学或可验证任务，开放式对话、代码和长期遗忘证据仍少。ACTD: Anchor-Based Cross-Tokenizer Distillation with Residual Regularization 应在这些边界内理解，不能因一个平均分提升就宣称普遍优于所有蒸馏或 RL 方法。

后续复现优先做等生成 token、等 teacher 前向和等 GPU-hours 三套对照，并报告长度、熵、KL、有效 token、梯度范数、OOD 与失败案例。阅读路线可依次对照普通 off-policy KD、标准 RKL OPD、本文专属改进以及同主题的稳定化/跨 tokenizer 工作。最终判断标准是“收益来自哪里、付出什么成本、在何种条件下失效”，而不是只复述摘要。

本条应标为**相关/边界论文：离线跨 tokenizer KD**。它提供对齐思路，不改变 on-policy 的定义。报告后续更新时应继续保留这个标注，防止读者把 2026 OPD 专题中的 35 条都看作核心 OPD 实验。
