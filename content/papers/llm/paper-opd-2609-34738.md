## 1. 背景与已有工作

**阅读定位。**《Beyond Token Alignment: Event Completion for Cross-Tokenizer On-Policy Distillation》放在 OPD 文献链条中，核心问题不是把一个最终答案从 teacher 复制给 student，而是 student 先在当前策略下生成前缀，teacher 再对这些真实会遇到的状态提供监督。这样可减少离线 teacher 轨迹与 student 部署轨迹的分布偏移，但代价是每轮都要生成、teacher 前向和更新，稳定性、概率空间以及评测预算会互相耦合。

本报告把贡献拆成“问题假设—训练信号—工程实现—证据边界”四层。与 SFT 相比，OPD 监督的是 student rollout；与 RL 相比，它通常不必为每题设计外部 reward，而以 teacher 分布或似然差为反馈；与离线 KD 相比，它能在 student 的错误前缀上纠偏。若 teacher 与 student tokenizer、终止符或能力分布不同，还会额外出现概率不可比、长度偏差或局部信号失真的问题。阅读原文时应先确认论文解决的是哪一层，而不是把所有提升笼统归因于“on-policy”。

这套定位也限定了结论：论文中的 benchmark 增益只能支持给定模型、数据和预算下的机制，不能自动外推到任意规模或任务。尤其需要区分 teacher 更强带来的上限、训练 token 更多带来的算力收益，以及新目标函数本身的贡献。后文保留原论文图表证据与负结果，避免只摘摘要中的最佳数字。

不同 tokenizer 造成的困难可以拆成两个时刻。第一，student 在某个共同文本前缀上要输出下一 token，teacher 的分布怎样对齐到学生词表？[BPM](#paper=paper-opd-2607-22334)等工作重点处理这种“进入事件”的概率路由。第二，student 已经输出了 teacher 某个 token 的一部分字节，例如 teacher 的 `Bread` 对应 student 已输出 `Br`，此时剩余 `ead` 可能由多个不同 student token 合法完成。Teacher 知道哪些字节应完成，却未必规定这些等价完成方式之间应如何分概率。这篇论文研究第二个时刻。

Event-Set Completion Distillation（ESCD）的核心问题是：**对部分进入 teacher token 的 student 中间状态，应该监督哪一个概率事件？** 若硬指定某个单独 token 的概率，可能把不同 tokenizer 的分词习惯错误地当成能力差距；若只处理共同边界，student 中间状态又没有监督。

## 2. 方法与实现机制

![ESCD：从事件入口到残余文本完成](./assets/papers/paper-opd-2609-34738/method-source.png)

原图把异构 token 对齐改写为共同文本事件：在共享前缀处积累兼容教师 token 的概率质量，再沿残余文本继续完成事件。这样能区分根节点近似与真正完成事件的概率，而不是把 token 字符串表面相同当作充分条件。图中分支与完成路径对应计算成本和监督可用性之间的权衡。 图源：[arXiv 2609.34738v1 LaTeX 源码](https://arxiv.org/src/2609.34738v1)，原始文件 `figures/method4.pdf`。

作为比较基线，student 轨迹记为 $y\sim\pi_\theta(\cdot\mid x)$，teacher 为 $\pi_T$。常见 token 级 on-policy 蒸馏的示意目标写成下式；它不代表本文所有变体都采用同一散度或同一梯度估计器：

$$\mathcal{L}(\theta)=\mathbb{E}_{x,\,y\sim\pi_\theta(\cdot\mid x)}\!\left[\sum_t D\!\left(\pi_\theta(\cdot\mid x,y_{<t}),\pi_T(\cdot\mid x,y_{<t})\right)\right].$$

这里最关键的是期望分布也依赖 student：参数更新后，下一批前缀会变，teacher 监督的位置随之移动。若实现先缓存 teacher 自己生成的固定答案，目标就退化为 off-policy；若 teacher 和 student 看到的模板、温度或 EOS 不一致，似然差还会混入协议偏差。散度是 reverse KL、forward KL、JS、回归损失还是经过门控的组合，会决定 mode-seeking、coverage 和梯度尺度，不能只用“KD loss”概括。

复现时建议把一次训练 step 拆成六个可审计阶段：固定 prompt 与模板；student 生成并记录 token/终止原因；teacher 在完全相同前缀上前向；构造论文定义的 token 掩码、权重或对齐；只对 student 反向；记录有效 token 数与梯度范数。对于跨 tokenizer 方法，还必须保存共同 byte/event 单元到两侧 token 的映射；对于自蒸馏，必须冻结 teacher 快照或明确同步频率；对于 verifier/多 teacher 方法，则要记录门控拒绝率与各 teacher 被选比例。

公式实现有三个常见陷阱。第一，用 batch mean 代替有效 token mean 会让长回答获得更大权重；第二，teacher logits 的温度缩放、top-k 截断和重新归一化次序会改变目标；第三，在本应 stop-gradient 的权重上反传，会引入论文没有的高方差项。最小测试应构造一个两 token 词表，手算每项概率、mask 与梯度方向，再做端到端小 batch 对照。作者未开源与该论文一一对应的官方代码仓库，因此这里只能依据固定版论文、公式和附录核读，不能声称函数级实现已验证。

方法是否有效不能只看最终 accuracy。还要检查训练中 teacher-student KL、student 熵、回答长度、EOS 概率、有效更新 token 比例、梯度范数和 rollout 成功率。若主指标上涨却长度暴增、熵坍缩或 OOD 明显下降，应视为带代价的权衡。原文方法图、后续配置说明和结果图表共同构成可追溯链条。

论文用 byte string 定义 teacher token 事件。Student 在共同的 root 前缀采出一个 token，若其字节是某 teacher token 字节的严格前缀，当前状态进入但未完成该事件；剩余部分称 residual。ESCD 查找能够在下一步补全 residual 的 student token，形成一个 **completion set**。多个 teacher 候选 token 若存在前缀包含关系，还需合并成相关组，并按 teacher 概率质量为对应完成事件加权。

在教学化简的单事件情形，若合法补全集合为 $C$，teacher 对该事件给出质量 $q_E$，监督的是 $\sum_{u\in C}p_\theta(u\mid x')$ 与 $q_E$ 的关系，而不是为集合里的每一个 $u$ 人为设定 $q(u)$。这里 $x'$ 是 student 输出部分字节后的状态；真实目标还结合 root 位置的概率对齐、多个前缀事件聚合及论文 §3.3 的权重，不能直接用这一行代替完整算法。


**Figure 1 解读。** 图的重点是跨不同 teacher/student 规模时的任务结果对照，并非 completion-set 构造图。方法本身建议在原文 **Figure 2/3** 对照阅读：Figure 2 展示 teacher 的一个 token 如何跨过几个 student 动作，Figure 3 把 event entry、residual 和合法补全集合串成一条路径。看 Figure 3 时要特别分清“teacher 事件的总概率”和“某个 student token 的概率”，这也是 ESCD 相对逐 token 分配的差异。[原图及方法图](https://arxiv.org/html/2609.34738v1)。

## 3. 实验设置与算力

![Table 6：小规模与大规模 OPD 配置](./assets/papers/paper-opd-2609-34738/table-6-config-pdf.png)

原表同时列出小规模和大规模实验，GPU 总数包含教师服务、学生优化和学生 rollout，不能只把它当成反向传播卡数。不同模型组合的 token 预算与服务资源也不相同；复现时应按整列读取配置，不把小模型的 batch 和大模型的并行参数拼成一套不存在的实验。 图表源：[arXiv 2609.34738v1 PDF，第 16 页](https://arxiv.org/pdf/2609.34738v1#page=16)，仅裁图表区域。

| 复现维度 | 必须记录的字段 | 为什么重要 |
|---|---|---|
| 模型协议 | checkpoint、tokenizer、chat template、EOS | 决定概率是否可比 |
| 采样预算 | prompts、每题 rollout、温度、top-p、最大长度 | 决定探索与成本 |
| 优化 | loss、学习率、batch、累积、step/epoch | 决定梯度尺度 |
| teacher 成本 | 前向 token、logits/top-k、缓存策略 | OPD 的主要额外开销 |
| 评测 | seed、样本数、Avg@k/Pass@k、judge | 防止口径漂移 |
| 算力 | GPU 型号、卡数、GPU-hours | 判断收益是否等预算 |

公平对照至少要固定 student 起点、训练 prompt、生成 token 总量和评测解码。只固定 step 不够：多 rollout、更长回答和更大 teacher 会显著增加计算。若论文没有完整 GPU 型号、卡数或 GPU-hours，本报告将其视作披露缺口；复现时需单独测量 student 生成、teacher 前向、反向传播和评测四部分 wall-clock。已有正文中的论文专属模型、数据和参数说明应与这张账本结合阅读。

统计上应报告多个随机种子或置信区间，并把 checkpoint 选择放在独立验证集。Pass@k 会随 k 和采样温度上涨，不能与 greedy accuracy 混写；LLM judge 需要固定版本与 prompt；verifier 过滤后的有效样本量也要报告。只有配置、预算和指标都对齐，结果差异才可归因于方法。

受控实验以 **Qwen3.5-2B** student 分别接 **Qwen3-32B**（同家族但 tokenizer 不同）与 **GLM-Z1-9B**（家族和 tokenizer 都不同）teacher；数学用 AIME24/25/26、HMMT26，代码用 LiveCodeBench、TACO。大规模验证包含 **Qwen3.5-397B-A17B → Qwen3-30B-A3B-Thinking** 和 **Kimi-K2.7-Code → Qwen3.6-35B-A3B**，评测 FrontierScience Olympiad-100 与 PHYRD-40。原文标注数学 avg@8/pass@8，代码 avg@2/pass@2，不能只摘一列“准确率”而不写 $k$。

原表用 Qwen3-32B 和 GLM-Z1-9B 两种教师分别蒸馏同一个 Qwen3.5-2B 学生，检验事件级对齐是否改善数学与代码任务。应在每个教师组内对照 BPM 等基线，而不是将两个教师的结果混排。不同任务的变化幅度也限定了关于监督改进的结论范围。 图表源：[arXiv 2609.34738v1 PDF，第 7 页](https://arxiv.org/pdf/2609.34738v1#page=7)，仅裁图表区域。

![Table 2：大规模异构 MoE 蒸馏](./assets/papers/paper-opd-2609-34738/table-2-results-pdf.png)

原表扩展到 397B 和 1T 级教师的异构 MoE 配置，展示方法不只在小模型对上测试。Kimi 设置中 BPM 和 ESCD 使用匹配条件，应在相同组内比较质量收益。总参数比例不是实际活跃计算量比例，不能由教师总参数规模直接推断训练成本或端到端加速。 图表源：[arXiv 2609.34738v1 PDF，第 8 页](https://arxiv.org/pdf/2609.34738v1#page=8)，仅裁图表区域。

结果证据应形成闭环：主表回答“最终是否更好”，曲线回答“训练是否更稳/更快”，消融回答“哪个部件起作用”，成本表回答“是否等预算”。任一环节缺失都降低因果强度。尤其在 OPD 中，更强 teacher、更长 rollout 或更多 teacher 前向本身就可能提高分数，因此必须同时报告 teacher 调用量和生成 token。只引用平均值还会掩盖 AIME 这类小样本基准的高方差。

实践决策不能只追最高 accuracy。若目标是单次在线回答，应重视 Pass@1/Avg@k 与延迟；若允许 test-time scaling，才关注较大 k 的 Pass@k；若模型需要持续更新，还要测 OOD、遗忘和连续多轮蒸馏。本文据原图与正文只给“这些实验设置下”的结论，不把局部结果外推成普遍规律。

在 **Table 1** 的 Qwen3-32B → Qwen3.5-2B 组，AIME24 avg@8：BPM **38.8**、ESCD **46.7**；LiveCodeBench avg@2：BPM **15.4**、ESCD **31.0**。这支持作者关于中间状态 completion supervision 有用的解释，但要把训练预算、不同 benchmark 的样本量与多次采样口径一起看。**Table 2** 的 1T Kimi teacher → 35B student 组，FrontierScience Olympiad-100 上 SFT 起点 **68.0**、BPM **69.0**、ESCD **72.0**；PHYRD-40 分别为 **66.2、69.2、74.3**。这里 ESCD 与 BPM 的同起点对照比“从未训练 base 到 ESCD”的差距更能隔离方法贡献。

论文另有一个局部覆盖率分析：在所研究的 tokenizer pair 和相关 residual 状态中，一步合法补全覆盖超过 **99%** 的被观测兼容 teacher mass。它说明该组实验的一步完成集合覆盖充分；不能扩展为任意 tokenizer、任意语言或复杂多字节字符都超过 99%。Figure 1 展示结果趋势，Figure 3 说明为什么应监督集合事件，两者提供的证据类型不同。

## 5. 局限、结论与后续阅读

共同局限可以归为四类：teacher 可能在 student 前缀上失准；on-policy 反复调用 teacher，训练成本高于离线 SFT；tokenizer/EOS/template 不一致会把协议差异伪装成知识差异；多数论文集中在数学或可验证任务，开放式对话、代码和长期遗忘证据仍少。Beyond Token Alignment: Event Completion for Cross-Tokenizer On-Policy Distillation 应在这些边界内理解，不能因一个平均分提升就宣称普遍优于所有蒸馏或 RL 方法。

后续复现优先做等生成 token、等 teacher 前向和等 GPU-hours 三套对照，并报告长度、熵、KL、有效 token、梯度范数、OOD 与失败案例。阅读路线可依次对照普通 off-policy KD、标准 RKL OPD、本文专属改进以及同主题的稳定化/跨 tokenizer 工作。最终判断标准是“收益来自哪里、付出什么成本、在何种条件下失效”，而不是只复述摘要。

ESCD 解决了跨 tokenizer OPD 的一个具体缺口：teacher 事件被 student 部分进入后，不强迫 teacher 为多种等价 student 补全分配任意的逐 token 概率。它是对 root 对齐目标的补充，不保证训练起点、teacher 质量、学生容量和长轨迹稳定性问题自动消失；论文自己的 Kimi 配置就依赖 SFT 初始化来稳定比较。
