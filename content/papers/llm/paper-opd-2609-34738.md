## 1. 背景与已有工作

不同 tokenizer 造成的困难可以拆成两个时刻。第一，student 在某个共同文本前缀上要输出下一 token，teacher 的分布怎样对齐到学生词表？[BPM](#paper=paper-opd-2607-22334)等工作重点处理这种“进入事件”的概率路由。第二，student 已经输出了 teacher 某个 token 的一部分字节，例如 teacher 的 `Bread` 对应 student 已输出 `Br`，此时剩余 `ead` 可能由多个不同 student token 合法完成。Teacher 知道哪些字节应完成，却未必规定这些等价完成方式之间应如何分概率。这篇论文研究第二个时刻。

Event-Set Completion Distillation（ESCD）的核心问题是：**对部分进入 teacher token 的 student 中间状态，应该监督哪一个概率事件？** 若硬指定某个单独 token 的概率，可能把不同 tokenizer 的分词习惯错误地当成能力差距；若只处理共同边界，student 中间状态又没有监督。

## 2. 方法与实现机制

论文用 byte string 定义 teacher token 事件。Student 在共同的 root 前缀采出一个 token，若其字节是某 teacher token 字节的严格前缀，当前状态进入但未完成该事件；剩余部分称 residual。ESCD 查找能够在下一步补全 residual 的 student token，形成一个 **completion set**。多个 teacher 候选 token 若存在前缀包含关系，还需合并成相关组，并按 teacher 概率质量为对应完成事件加权。

在教学化简的单事件情形，若合法补全集合为 $C$，teacher 对该事件给出质量 $q_E$，监督的是 $\sum_{u\in C}p_\theta(u\mid x')$ 与 $q_E$ 的关系，而不是为集合里的每一个 $u$ 人为设定 $q(u)$。这里 $x'$ 是 student 输出部分字节后的状态；真实目标还结合 root 位置的概率对齐、多个前缀事件聚合及论文 §3.3 的权重，不能直接用这一行代替完整算法。

## 4. 结果与图表解读

在 **Table 1** 的 Qwen3-32B → Qwen3.5-2B 组，AIME24 avg@8：BPM **38.8**、ESCD **46.7**；LiveCodeBench avg@2：BPM **15.4**、ESCD **31.0**。这支持作者关于中间状态 completion supervision 有用的解释，但要把训练预算、不同 benchmark 的样本量与多次采样口径一起看。**Table 2** 的 1T Kimi teacher → 35B student 组，FrontierScience Olympiad-100 上 SFT 起点 **68.0**、BPM **69.0**、ESCD **72.0**；PHYRD-40 分别为 **66.2、69.2、74.3**。这里 ESCD 与 BPM 的同起点对照比“从未训练 base 到 ESCD”的差距更能隔离方法贡献。

论文另有一个局部覆盖率分析：在所研究的 tokenizer pair 和相关 residual 状态中，一步合法补全覆盖超过 **99%** 的被观测兼容 teacher mass。它说明该组实验的一步完成集合覆盖充分；不能扩展为任意 tokenizer、任意语言或复杂多字节字符都超过 99%。Figure 1 展示结果趋势，Figure 3 说明为什么应监督集合事件，两者提供的证据类型不同。

## 5. 局限、结论与后续阅读

ESCD 解决了跨 tokenizer OPD 的一个具体缺口：teacher 事件被 student 部分进入后，不强迫 teacher 为多种等价 student 补全分配任意的逐 token 概率。它是对 root 对齐目标的补充，不保证训练起点、teacher 质量、学生容量和长轨迹稳定性问题自动消失；论文自己的 Kimi 配置就依赖 SFT 初始化来稳定比较。
