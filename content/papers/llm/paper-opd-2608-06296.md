## 1. 背景与已有工作

**阅读定位。**《On-Policy Self-Distillation without Any Supervision》放在 OPD 文献链条中，核心问题不是把一个最终答案从 teacher 复制给 student，而是 student 先在当前策略下生成前缀，teacher 再对这些真实会遇到的状态提供监督。这样可减少离线 teacher 轨迹与 student 部署轨迹的分布偏移，但代价是每轮都要生成、teacher 前向和更新，稳定性、概率空间以及评测预算会互相耦合。

本报告把贡献拆成“问题假设—训练信号—工程实现—证据边界”四层。与 SFT 相比，OPD 监督的是 student rollout；与 RL 相比，它通常不必为每题设计外部 reward，而以 teacher 分布或似然差为反馈；与离线 KD 相比，它能在 student 的错误前缀上纠偏。若 teacher 与 student tokenizer、终止符或能力分布不同，还会额外出现概率不可比、长度偏差或局部信号失真的问题。阅读原文时应先确认论文解决的是哪一层，而不是把所有提升笼统归因于“on-policy”。

这套定位也限定了结论：论文中的 benchmark 增益只能支持给定模型、数据和预算下的机制，不能自动外推到任意规模或任务。尤其需要区分 teacher 更强带来的上限、训练 token 更多带来的算力收益，以及新目标函数本身的贡献。后文保留原论文图表证据与负结果，避免只摘摘要中的最佳数字。

多数 OPD 要么有外部强 teacher，要么像 OPSD 一样给同模型 teacher 参考解。u-OPSD 进一步追问：**没有外部答案与独立 teacher，模型能否用自身多次回答形成有用的“特权信息”？** 它利用同一题多条 rollout 的内部一致性估计伪答案，再让带伪答案的 self-teacher 对 student 的错误轨迹给稠密监督。它不是无成本训练：需要多次采样与一致性筛选，只是不依赖外部标准答案。

与传统 self-training 只把多数答案拿去做 SFT 不同，u-OPSD 让 student 继续写自己的前缀，对**与多数意见相反的轨迹**进行 teacher/student 概率比较。这样旨在把稀疏的“哪些答案一致”转为逐 token 修正。

## 2. 方法与实现机制

![Figure 2：无监督 on-policy 自蒸馏](./assets/papers/paper-opd-2608-06296/method-source.png)

原图展示从学生 rollout 中选择伪标签，再以这些伪标签构造 teacher 条件，最后更新 student 的循环。与使用真实解答的 OPSD 不同，uOPSD 不依赖外部 ground truth，但伪标签选择可能带入学生原有偏差。需要明确选择策略与 teacher 更新方式，不能把整个循环等同于普通自训练。 图源：[arXiv 2608.06296v1 LaTeX 源码](https://arxiv.org/src/2608.06296v1)，原始文件 `figs/uopsd_figure_v7_p1.pdf`。

作为比较基线，student 轨迹记为 $y\sim\pi_\theta(\cdot\mid x)$，teacher 为 $\pi_T$。常见 token 级 on-policy 蒸馏的示意目标写成下式；它不代表本文所有变体都采用同一散度或同一梯度估计器：

$$\mathcal{L}(\theta)=\mathbb{E}_{x,\,y\sim\pi_\theta(\cdot\mid x)}\!\left[\sum_t D\!\left(\pi_\theta(\cdot\mid x,y_{<t}),\pi_T(\cdot\mid x,y_{<t})\right)\right].$$

这里最关键的是期望分布也依赖 student：参数更新后，下一批前缀会变，teacher 监督的位置随之移动。若实现先缓存 teacher 自己生成的固定答案，目标就退化为 off-policy；若 teacher 和 student 看到的模板、温度或 EOS 不一致，似然差还会混入协议偏差。散度是 reverse KL、forward KL、JS、回归损失还是经过门控的组合，会决定 mode-seeking、coverage 和梯度尺度，不能只用“KD loss”概括。

复现时建议把一次训练 step 拆成六个可审计阶段：固定 prompt 与模板；student 生成并记录 token/终止原因；teacher 在完全相同前缀上前向；构造论文定义的 token 掩码、权重或对齐；只对 student 反向；记录有效 token 数与梯度范数。对于跨 tokenizer 方法，还必须保存共同 byte/event 单元到两侧 token 的映射；对于自蒸馏，必须冻结 teacher 快照或明确同步频率；对于 verifier/多 teacher 方法，则要记录门控拒绝率与各 teacher 被选比例。

公式实现有三个常见陷阱。第一，用 batch mean 代替有效 token mean 会让长回答获得更大权重；第二，teacher logits 的温度缩放、top-k 截断和重新归一化次序会改变目标；第三，在本应 stop-gradient 的权重上反传，会引入论文没有的高方差项。最小测试应构造一个两 token 词表，手算每项概率、mask 与梯度方向，再做端到端小 batch 对照。本报告把论文原图与已有仓库线索分开：即使仓库存在，也应固定提交并逐项核对默认参数，不能用最新分支替代论文版本。

方法是否有效不能只看最终 accuracy。还要检查训练中 teacher-student KL、student 熵、回答长度、EOS 概率、有效更新 token 比例、梯度范数和 rollout 成功率。若主指标上涨却长度暴增、熵坍缩或 OOD 明显下降，应视为带代价的权衡。原文方法图、后续配置说明和结果图表共同构成可追溯链条。

对题目 $x$，当前模型生成一组回答，解析最终答案；若多数票形成有效共识，选一条与共识相符的回答作 teacher 的参考上下文，再选若干不同意共识的 student rollout 做蒸馏。teacher 与 student 共享模型参数，但 teacher 看到“同伴提供的伪解”，student 只看题目；两者在 student 访问的前缀上求分布损失。论文沿用 OPSD 的 forward-KL 与逐 token clip 配方，更新只通过 student 路径反传。

失败模式从方法本身就能推出：如果多数人一起答错，共识不是正确答案；如果所有 rollout 都同意，缺少有分歧的训练目标；如果解析答案失败，样本可能被丢弃。读方法图时需同时看“多数票如何形成”和“哪些轨迹进入 loss”，不能只写一句“模型教自己”。

作者 [u-opsd 仓库](https://github.com/williamium3000/u-opsd) 是官方实现入口；本轮未逐函数审读，复现时优先核对 vote 阈值、答案提取器与 teacher reference 的泄漏边界。


**图解。** student 对同一题采多条回答，投票形成伪解；teacher 看到伪解，对少数不同意的 student 轨迹给逐 token 分布。这张图解释了方法为什么不需要外部标准答案，也显示它仍依赖多次生成和共识质量。 [图源：arXiv 2608.06296v2](https://arxiv.org/html/2608.06296v2)。

## 3. 实验设置与算力



| 复现维度 | 必须记录的字段 | 为什么重要 |
|---|---|---|
| 模型协议 | checkpoint、tokenizer、chat template、EOS | 决定概率是否可比 |
| 采样预算 | prompts、每题 rollout、温度、top-p、最大长度 | 决定探索与成本 |
| 优化 | loss、学习率、batch、累积、step/epoch | 决定梯度尺度 |
| teacher 成本 | 前向 token、logits/top-k、缓存策略 | OPD 的主要额外开销 |
| 评测 | seed、样本数、Avg@k/Pass@k、judge | 防止口径漂移 |
| 算力 | GPU 型号、卡数、GPU-hours | 判断收益是否等预算 |

公平对照至少要固定 student 起点、训练 prompt、生成 token 总量和评测解码。只固定 step 不够：多 rollout、更长回答和更大 teacher 会显著增加计算。若论文没有完整 GPU 型号、卡数或 GPU-hours，本报告将其视作披露缺口；复现时需单独测量 student 生成、teacher 前向、反向传播和评测四部分 wall-clock。已有正文中的论文专属模型、数据和参数说明应与这张账本结合阅读。

统计上应报告多个随机种子或置信区间，并把 checkpoint 选择放在独立验证集。Pass@k 会随 k 和采样温度上涨，不能与 greedy accuracy 混写；LLM judge 需要固定版本与 prompt；verifier 过滤后的有效样本量也要报告。只有配置、预算和指标都对齐，结果差异才可归因于方法。

实验覆盖 Qwen3-4B、8B、30B-A3B-Instruct-2507 与 4B-Instruct-2507，前两者还分别看 thinking 与 non-thinking。训练用 OpenThoughts 约 **30K 题**，u-OPSD 只读取题目，不使用其参考解；对照含有标准答案监督的 SFT、GRPO、OPSD，以及无需标准答案的其他自训练方法。评测 AIME24/25、HMMT25、MATH500、AMC23 等，模式和采样次数要与对应表头一起读。

u-OPSD 的计算预算受每题 rollout 条数、共识有效率和 teacher 前向 token 决定。论文未给出统一所有模型的 GPU-hours，不能仅因不用标注就说训练便宜；大模型 30B-A3B 的多样采样尤其有成本。

![Qwen3-4B 的逐 checkpoint 训练曲线](./assets/papers/paper-opd-2608-06296/training-curves-source.png)

原图追踪 AIME24、AIME25 和 MATH500 上前几个 checkpoint 的表现，覆盖正文引用的 4B 配置。曲线用于区分持续改善、早期峰值和后续波动，不能把 best checkpoint 当成固定最后一步的结果。小规模数学基准的波动尤其需要结合主表的完整评测协议理解。 图源：[arXiv 2608.06296v1 LaTeX 源码](https://arxiv.org/src/2608.06296v1)，原始文件 `figs/uopsd_curves_4b_merged.pdf`。

结果证据应形成闭环：主表回答“最终是否更好”，曲线回答“训练是否更稳/更快”，消融回答“哪个部件起作用”，成本表回答“是否等预算”。任一环节缺失都降低因果强度。尤其在 OPD 中，更强 teacher、更长 rollout 或更多 teacher 前向本身就可能提高分数，因此必须同时报告 teacher 调用量和生成 token。只引用平均值还会掩盖 AIME 这类小样本基准的高方差。

实践决策不能只追最高 accuracy。若目标是单次在线回答，应重视 Pass@1/Avg@k 与延迟；若允许 test-time scaling，才关注较大 k 的 Pass@k；若模型需要持续更新，还要测 OOD、遗忘和连续多轮蒸馏。本文据原图与正文只给“这些实验设置下”的结论，不把局部结果外推成普遍规律。

**Table 1** 的 Qwen3-4B non-thinking 组，五项平均：base **40.96**、有 GT 的 GRPO **45.86**、OPSD **46.29**、u-OPSD **54.31**。AIME24 从 base **25.83** 到 u-OPSD **45.56**，MATH500 **84.10→89.55**。这里“无外部标签仍领先”是该训练与评测设置下的结果，不应从一组模型推为所有无标签任务通用。

表中的 “w/ GT.” 与无 GT 方案必须分开说明，否则读者会误以为所有基线都只用了 prompt。对 u-OPSD 还需看无共识题的比例和正确题/错误题的覆盖；只报告进入训练的样本数，会高估方法在难题上的有效性。

## 5. 局限、结论与后续阅读

共同局限可以归为四类：teacher 可能在 student 前缀上失准；on-policy 反复调用 teacher，训练成本高于离线 SFT；tokenizer/EOS/template 不一致会把协议差异伪装成知识差异；多数论文集中在数学或可验证任务，开放式对话、代码和长期遗忘证据仍少。On-Policy Self-Distillation without Any Supervision 应在这些边界内理解，不能因一个平均分提升就宣称普遍优于所有蒸馏或 RL 方法。

后续复现优先做等生成 token、等 teacher 前向和等 GPU-hours 三套对照，并报告长度、熵、KL、有效 token、梯度范数、OOD 与失败案例。阅读路线可依次对照普通 off-policy KD、标准 RKL OPD、本文专属改进以及同主题的稳定化/跨 tokenizer 工作。最终判断标准是“收益来自哪里、付出什么成本、在何种条件下失效”，而不是只复述摘要。

内部共识依赖模型起点有一定答题能力，也容易把共同偏见当作真值；开放式任务缺少可稳定解析的答案时，多数票更难定义。下一步验证应在同一多 rollout 预算下比较多数票 SFT、自教师 KL 和不使用共识的简单自训练，并按初始题目正确率分层报告。这样才能判断稠密 teacher 反馈的贡献。
