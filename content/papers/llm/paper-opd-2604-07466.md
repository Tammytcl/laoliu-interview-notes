## 1. 背景与已有工作

**阅读定位。**《Cross-Tokenizer LLM Distillation through a Byte-Level Interface》放在 OPD 文献链条中，核心问题不是把一个最终答案从 teacher 复制给 student，而是 student 先在当前策略下生成前缀，teacher 再对这些真实会遇到的状态提供监督。这样可减少离线 teacher 轨迹与 student 部署轨迹的分布偏移，但代价是每轮都要生成、teacher 前向和更新，稳定性、概率空间以及评测预算会互相耦合。

本报告把贡献拆成“问题假设—训练信号—工程实现—证据边界”四层。与 SFT 相比，OPD 监督的是 student rollout；与 RL 相比，它通常不必为每题设计外部 reward，而以 teacher 分布或似然差为反馈；与离线 KD 相比，它能在 student 的错误前缀上纠偏。若 teacher 与 student tokenizer、终止符或能力分布不同，还会额外出现概率不可比、长度偏差或局部信号失真的问题。阅读原文时应先确认论文解决的是哪一层，而不是把所有提升笼统归因于“on-policy”。

这套定位也限定了结论：论文中的 benchmark 增益只能支持给定模型、数据和预算下的机制，不能自动外推到任意规模或任务。尤其需要区分 teacher 更强带来的上限、训练 token 更多带来的算力收益，以及新目标函数本身的贡献。后文保留原论文图表证据与负结果，避免只摘摘要中的最佳数字。

跨 tokenizer 蒸馏有两种不同目标：保持模型原有能力却替换 tokenizer，或让一个 teacher 把能力迁给使用另一 tokenizer 的 student。这篇工作以**字节串**为共同语言讨论前者和后者。若只在两个词表中找同名 token，会丢掉意义相同但边界不同的字符串；若只把 teacher 的 token 概率机械映到 student id，概率也未必对应同一文本事件。

它与 [SimCT](#paper=paper-opd-2605-07711)、[BPM](#paper=paper-opd-2607-22334)相邻，但研究的问题并不完全相同：前者包含 tokenizer transfer；BPM 明确在 student 前缀上构造 byte-prefix 质量。把这篇作为“字节事件如何由 token 生成”基础读物，能避免把 tokenizer 视为仅改变字符串显示方式。

## 2. 方法与实现机制

![Figure 1：Byte-Level Distillation 两阶段框架](./assets/papers/paper-opd-2604-07466/method-source.png)

原图先为学生增加 byte-level 接口，再把教师 token 概率转换到共同 byte 空间实施蒸馏。关键不是要求两侧 token 一一对应，而是建立可比较的概率接口；因此图中的接口训练和蒸馏阶段必须分开。直接提取作者的矢量图，保留模块和箭头，不夹带论文正文。 图源：[arXiv 2604.07466v1 LaTeX 源码](https://arxiv.org/src/2604.07466v1)，原始文件 `figures/bt_tower_paper_drawings.pdf`。

作为比较基线，student 轨迹记为 $y\sim\pi_\theta(\cdot\mid x)$，teacher 为 $\pi_T$。常见 token 级 on-policy 蒸馏的示意目标写成下式；它不代表本文所有变体都采用同一散度或同一梯度估计器：

$$\mathcal{L}(\theta)=\mathbb{E}_{x,\,y\sim\pi_\theta(\cdot\mid x)}\!\left[\sum_t D\!\left(\pi_\theta(\cdot\mid x,y_{<t}),\pi_T(\cdot\mid x,y_{<t})\right)\right].$$

这里最关键的是期望分布也依赖 student：参数更新后，下一批前缀会变，teacher 监督的位置随之移动。若实现先缓存 teacher 自己生成的固定答案，目标就退化为 off-policy；若 teacher 和 student 看到的模板、温度或 EOS 不一致，似然差还会混入协议偏差。散度是 reverse KL、forward KL、JS、回归损失还是经过门控的组合，会决定 mode-seeking、coverage 和梯度尺度，不能只用“KD loss”概括。

复现时建议把一次训练 step 拆成六个可审计阶段：固定 prompt 与模板；student 生成并记录 token/终止原因；teacher 在完全相同前缀上前向；构造论文定义的 token 掩码、权重或对齐；只对 student 反向；记录有效 token 数与梯度范数。对于跨 tokenizer 方法，还必须保存共同 byte/event 单元到两侧 token 的映射；对于自蒸馏，必须冻结 teacher 快照或明确同步频率；对于 verifier/多 teacher 方法，则要记录门控拒绝率与各 teacher 被选比例。

公式实现有三个常见陷阱。第一，用 batch mean 代替有效 token mean 会让长回答获得更大权重；第二，teacher logits 的温度缩放、top-k 截断和重新归一化次序会改变目标；第三，在本应 stop-gradient 的权重上反传，会引入论文没有的高方差项。最小测试应构造一个两 token 词表，手算每项概率、mask 与梯度方向，再做端到端小 batch 对照。作者未开源与该论文一一对应的官方代码仓库，因此这里只能依据固定版论文、公式和附录核读，不能声称函数级实现已验证。

方法是否有效不能只看最终 accuracy。还要检查训练中 teacher-student KL、student 熵、回答长度、EOS 概率、有效更新 token 比例、梯度范数和 rollout 成功率。若主指标上涨却长度暴增、熵坍缩或 OOD 明显下降，应视为带代价的权衡。原文方法图、后续配置说明和结果图表共同构成可追溯链条。

论文把 tokenizer 定义为从 byte sequence 到 token sequence 的确定性映射，并给出解码回 byte sequence 的操作。对一个 student 候选 token，核心是判断 teacher 哪些 token 或 continuation 对应同一个 byte 前缀或最小编辑事件，然后在可比较的空间里做概率蒸馏。这里的“byte-level”不等于强行让 student 使用 256 个 byte token；模型仍保有原词表，只是比较事件时回到 bytes。

方法 MinED 通过构造两边都能解释的最小事件/编辑单位，将 teacher 监督传给新 tokenizer 的模型。读方法公式时重点确认三个边界：UTF-8 多字节字符有没有被中途切断；一个 teacher token 跨越 student 边界时剩余概率如何分配；重分词后的同一字符串是否出现多条 token 路径。任何一个边界处理不同，都可能改变归一化后的概率。

原文没有确认到作者公开的专门训练仓库；此处只按论文描述分析，不虚构可直接调用的对齐函数。

## 3. 实验设置与算力

原表同时列出搜索范围及各实验的实际配置，不能把 Search Space 中的候选值当成最终采用值。表中不同迁移任务的阶段设置要与方法两阶段对应；复现时先锁定目标 tokenizer 和 student，再读取相应列，避免把同表中另一个实验的学习率或 batch 拼接进来。 图表源：[arXiv 2604.07466v1 PDF，第 12 页](https://arxiv.org/pdf/2604.07466v1#page=12)，仅裁图表区域。

| 复现维度 | 必须记录的字段 | 为什么重要 |
|---|---|---|
| 模型协议 | checkpoint、tokenizer、chat template、EOS | 决定概率是否可比 |
| 采样预算 | prompts、每题 rollout、温度、top-p、最大长度 | 决定探索与成本 |
| 优化 | loss、学习率、batch、累积、step/epoch | 决定梯度尺度 |
| teacher 成本 | 前向 token、logits/top-k、缓存策略 | OPD 的主要额外开销 |
| 评测 | seed、样本数、Avg@k/Pass@k、judge | 防止口径漂移 |
| 算力 | GPU 型号、卡数、GPU-hours | 判断收益是否等预算 |

公平对照至少要固定 student 起点、训练 prompt、生成 token 总量和评测解码。只固定 step 不够：多 rollout、更长回答和更大 teacher 会显著增加计算。若论文没有完整 GPU 型号、卡数或 GPU-hours，本报告将其视作披露缺口；复现时需单独测量 student 生成、teacher 前向、反向传播和评测四部分 wall-clock。已有正文中的论文专属模型、数据和参数说明应与这张账本结合阅读。

统计上应报告多个随机种子或置信区间，并把 checkpoint 选择放在独立验证集。Pass@k 会随 k 和采样温度上涨，不能与 greedy accuracy 混写；LLM judge 需要固定版本与 prompt；verifier 过滤后的有效样本量也要报告。只有配置、预算和指标都对齐，结果差异才可归因于方法。

实验包含 Llama3.2-3B 向 Qwen2 tokenizer 的转移，也包含 BPE→byte 与跨 tokenizer distillation。student backbone 的 query/value 投影使用 LoRA，rank **64**，其余 backbone 权重冻结；这说明结果不是“从头训练新词表”的对照。评测 PiQA、ARC-C、BoolQ、MMLU、AGI-EN/AGI-ZH、IFEval 等，分别涉及常识、知识、双语与指令遵循。

要区分任务不同：tokenizer transfer 的指标是旧模型能力保留多少；跨模型蒸馏则要看 student 是否吸收 teacher。两张表不能混成统一分数。论文未给出完整 GPU-hours；对齐计算、LoRA 更新与重编码成本都应纳入复现实测。

## 4. 结果与图表解读

![Table 1：Llama3.2-3B 迁移至 Qwen2 tokenizer](./assets/papers/paper-opd-2604-07466/table-1-results-pdf.png)

原表比较替换 tokenizer 后各方法的多任务表现，original 是未迁移的原模型参照，不是同一个训练方案的 checkpoint。BLD 在 PiQA 与 AGI-ZH 上有优势，但并非每个任务都领先；结论应是减轻异构 tokenizer 迁移损失，而不是在所有测试上都恢复或超过原模型。 图表源：[arXiv 2604.07466v1 PDF，第 7 页](https://arxiv.org/pdf/2604.07466v1#page=7)，仅裁图表区域。

![Table 2：迁移到 byte-level tokenization](./assets/papers/paper-opd-2604-07466/table-2-results-pdf.png)

原表把目标接口换成 byte-level tokenization，和上一个 Qwen2 tokenizer 实验不是同一难度的任务。逐列对照 original、基线与 BLD，可以判断提升是否跨任务保持。byte 序列与原 token 序列长度不同，表中的质量收益不能直接解读成相同推理成本下的加速。 图表源：[arXiv 2604.07466v1 PDF，第 7 页](https://arxiv.org/pdf/2604.07466v1#page=7)，仅裁图表区域。

结果证据应形成闭环：主表回答“最终是否更好”，曲线回答“训练是否更稳/更快”，消融回答“哪个部件起作用”，成本表回答“是否等预算”。任一环节缺失都降低因果强度。尤其在 OPD 中，更强 teacher、更长 rollout 或更多 teacher 前向本身就可能提高分数，因此必须同时报告 teacher 调用量和生成 token。只引用平均值还会掩盖 AIME 这类小样本基准的高方差。

实践决策不能只追最高 accuracy。若目标是单次在线回答，应重视 Pass@1/Avg@k 与延迟；若允许 test-time scaling，才关注较大 k 的 Pass@k；若模型需要持续更新，还要测 OOD、遗忘和连续多轮蒸馏。本文据原图与正文只给“这些实验设置下”的结论，不把局部结果外推成普遍规律。

**Table 1** 的 Llama3.2-3B→Qwen2 tokenizer：原模型 IFEval **66.31**，普通 SFT 后 **26.74**，MinED **62.83**；PiQA 原始 **75.46**、MinED **75.35**。但 AGI-ZH 从原模型 **42.93** 到 MinED **34.76**，说明迁移并非完全无损。IFEval 的巨大差距尤其提示 tokenizer 替换会破坏特殊 token/聊天模板相关行为；不能把它只解释为语义分布匹配好坏。

读方法图时应沿一个具体字符串同时经过两种 tokenizer，检查共同 byte 事件与概率质量的对应。Table 1 证明在这些 backbone 与训练配置中能力保留更好；不证明所有 BPE/Unigram/byte tokenizer 配对都能相同效果。

## 5. 局限、结论与后续阅读

共同局限可以归为四类：teacher 可能在 student 前缀上失准；on-policy 反复调用 teacher，训练成本高于离线 SFT；tokenizer/EOS/template 不一致会把协议差异伪装成知识差异；多数论文集中在数学或可验证任务，开放式对话、代码和长期遗忘证据仍少。Cross-Tokenizer LLM Distillation through a Byte-Level Interface 应在这些边界内理解，不能因一个平均分提升就宣称普遍优于所有蒸馏或 RL 方法。

后续复现优先做等生成 token、等 teacher 前向和等 GPU-hours 三套对照，并报告长度、熵、KL、有效 token、梯度范数、OOD 与失败案例。阅读路线可依次对照普通 off-policy KD、标准 RKL OPD、本文专属改进以及同主题的稳定化/跨 tokenizer 工作。最终判断标准是“收益来自哪里、付出什么成本、在何种条件下失效”，而不是只复述摘要。

字节级共同空间原则上语言无关，但实际 tokenizer 有规范化、特殊 token、停用符与聊天模板等非普通 byte 事件。跨词表蒸馏若忽略 EOS 和空白也会出现严重差异。后续与 [EOS mismatch](#paper=paper-opd-2609-20511) 连读，可以把“词边界”问题拓展到“什么时候停止”这个独立事件。
