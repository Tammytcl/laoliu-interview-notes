## 1. 背景与已有工作

跨 tokenizer 蒸馏有两种不同目标：保持模型原有能力却替换 tokenizer，或让一个 teacher 把能力迁给使用另一 tokenizer 的 student。这篇工作以**字节串**为共同语言讨论前者和后者。若只在两个词表中找同名 token，会丢掉意义相同但边界不同的字符串；若只把 teacher 的 token 概率机械映到 student id，概率也未必对应同一文本事件。

它与 [SimCT](#paper=paper-opd-2605-07711)、[BPM](#paper=paper-opd-2607-22334)相邻，但研究的问题并不完全相同：前者包含 tokenizer transfer；BPM 明确在 student 前缀上构造 byte-prefix 质量。把这篇作为“字节事件如何由 token 生成”基础读物，能避免把 tokenizer 视为仅改变字符串显示方式。

## 2. 方法与实现机制

论文把 tokenizer 定义为从 byte sequence 到 token sequence 的确定性映射，并给出解码回 byte sequence 的操作。对一个 student 候选 token，核心是判断 teacher 哪些 token 或 continuation 对应同一个 byte 前缀或最小编辑事件，然后在可比较的空间里做概率蒸馏。这里的“byte-level”不等于强行让 student 使用 256 个 byte token；模型仍保有原词表，只是比较事件时回到 bytes。

方法 MinED 通过构造两边都能解释的最小事件/编辑单位，将 teacher 监督传给新 tokenizer 的模型。读方法公式时重点确认三个边界：UTF-8 多字节字符有没有被中途切断；一个 teacher token 跨越 student 边界时剩余概率如何分配；重分词后的同一字符串是否出现多条 token 路径。任何一个边界处理不同，都可能改变归一化后的概率。

原文没有确认到作者公开的专门训练仓库；此处只按论文描述分析，不虚构可直接调用的对齐函数。

## 3. 实验设置与算力

实验包含 Llama3.2-3B 向 Qwen2 tokenizer 的转移，也包含 BPE→byte 与跨 tokenizer distillation。student backbone 的 query/value 投影使用 LoRA，rank **64**，其余 backbone 权重冻结；这说明结果不是“从头训练新词表”的对照。评测 PiQA、ARC-C、BoolQ、MMLU、AGI-EN/AGI-ZH、IFEval 等，分别涉及常识、知识、双语与指令遵循。

要区分任务不同：tokenizer transfer 的指标是旧模型能力保留多少；跨模型蒸馏则要看 student 是否吸收 teacher。两张表不能混成统一分数。论文未给出完整 GPU-hours；对齐计算、LoRA 更新与重编码成本都应纳入复现实测。

## 4. 结果与图表解读

**Table 1** 的 Llama3.2-3B→Qwen2 tokenizer：原模型 IFEval **66.31**，普通 SFT 后 **26.74**，MinED **62.83**；PiQA 原始 **75.46**、MinED **75.35**。但 AGI-ZH 从原模型 **42.93** 到 MinED **34.76**，说明迁移并非完全无损。IFEval 的巨大差距尤其提示 tokenizer 替换会破坏特殊 token/聊天模板相关行为；不能把它只解释为语义分布匹配好坏。

读方法图时应沿一个具体字符串同时经过两种 tokenizer，检查共同 byte 事件与概率质量的对应。Table 1 证明在这些 backbone 与训练配置中能力保留更好；不证明所有 BPE/Unigram/byte tokenizer 配对都能相同效果。

## 5. 局限、结论与后续阅读

字节级共同空间原则上语言无关，但实际 tokenizer 有规范化、特殊 token、停用符与聊天模板等非普通 byte 事件。跨词表蒸馏若忽略 EOS 和空白也会出现严重差异。后续与 [EOS mismatch](#paper=paper-opd-2609-20511) 连读，可以把“词边界”问题拓展到“什么时候停止”这个独立事件。
