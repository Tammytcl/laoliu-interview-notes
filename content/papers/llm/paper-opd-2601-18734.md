## 1. 背景与已有工作

自我蒸馏并不一定是“同一个模型复制自己”。OPSD 让**同一底座模型处在两个信息条件下**：student 只看到数学题，teacher 额外看到参考解答，然后 teacher 在 student 的实际回答前缀上给逐 token 概率。它要同时保留 on-policy 数据的覆盖和细粒度监督，又避免维护一个外部大 teacher。与 GRPO 相比，二元正确/错误 reward 很稀疏；与直接 SFT 参考答案相比，后者没教模型如何从自己的错误前缀恢复。

这种“privileged context”也有危险：teacher 因提前知道答案，可能跳过正常探索过程。因此要把最终答对率与推理过程是否变短、搜索是否被压平一起看。后续 [Rethinking Self-Distillation](#paper=paper-opd-2607-05184) 专门给出了反面证据。

## 2. 方法与实现机制

每个训练样本含题目 $x$ 和参考解 $y^*$。student 从 $p_S(\cdot\mid x)$ 生成一条回答 $\hat y$；同参数的 teacher 读取 $x,y^*$，但在每个 $\hat y$ 的前缀上计算 next-token 分布 $p_T(\cdot\mid x,y^*,\hat y_{<t})$。优化只通过 student logits 反传，teacher 与 student 的参数角色在该次更新中分开。论文比较 forward KL、reverse KL 与 JSD，并发现这里 forward KL 更稳，不能把它与通常 sampled-token reverse-KL 的 OPD 配方混成一条固定规则。

**Figure 1** 画的是“双条件，同一 rollout”：右侧 teacher 没有另外生成一条完整解答，关键训练状态仍由 student 提供。Algorithm 1 把采样、teacher 评分和 student 更新顺序写清楚。官方 [OPSD 仓库](https://github.com/siyan-zhao/OPSD) 的训练器中，`generate_on_policy_outputs` 负责取得 student 轨迹，`compute_loss` 处理 teacher/student 分布，`generalized_jsd_loss` 是可选散度实现；需要连起来读，不能只把 JSD 函数当整套算法。源码已静态定位，未运行复现。

## 3. 实验设置与算力

实验使用 Qwen3-1.7B、4B、8B Instruct 版本，数学评测 AIME24、AIME25、HMMT25，报告 **Avg@12**。OPSD 与 SFT、GRPO 在原文各自训练日程下比较。作者在 Table 6 给出 GRPO/OPSD 关键配置：有效 batch **32**、LoRA rank **64**、alpha **128**、学习率 **5×10⁻⁶**；OPSD 最长生成 **1024 token**、每题 1 条、100 步，GRPO **16K token**、每题 8 条、500 步。训练 token 数明显不一样，因此“同一更新步”不是同一生成预算。

论文 Table 8 将评测最长新 token 设为 38,912，温度 1.0、每题 12 次；这个评测预算比训练 OPD 的生成长度大得多。静态核读没有得到可对照所有实验的 GPU 型号/卡数与 GPU-hours，结论应限于原文明确报告的样本与 token 效率。

## 4. 结果与图表解读

**Table 2** 中 Qwen3-1.7B 的三项平均从 base **37.1** 到 OPSD **43.4**；GRPO **37.7**、SFT **35.8**。4B 的 base/GRPO/OPSD 为 **61.2/62.7/63.6**，8B 为 **61.8/64.0/64.8**。这些是同一论文各模型的 Avg@12，不能当成一次采样 pass@1。**Figure 3** 把成绩同时按训练步和 student 生成 token 绘制，解释为何即使每步 OPD 采样更短也能产生稠密学习信号。

但 Table 3 的目标函数消融也很关键：1.7B AIME25 在 50 步，forward KL **43.9**，reverse KL **37.5**，JSD(0.5) **36.9**。Table 4 还显示 4B 的 full-vocabulary logits 比只监督 sampled token 在 AIME25/HMMT25 更好（**84.1/60.0** 对 **82.1/57.3**），代价是更大显存。图表支持的是这种条件 teacher 与目标组合，而不是所有自蒸馏都优于 RL。

## 5. 局限、结论与后续阅读

OPSD 需要训练数据提供参考答案或解题过程；teacher 的“特权信息”不是免费，也可能把答案泄露给推理风格，导致 student 学会快速断言而非搜索。后续研究在 thinking model 上看到性能下降，因此应同时记录推理长度、forking、pass@k 与长问题泛化。对代码复现，优先确认 teacher prompt 不会进入 student 的推理输入，且 teacher 权重在 student loss 中不更新。
