## 1. 背景与已有工作

大模型推理训练常见两条路线。SFT 模仿一批固定高质量解答，信号稳定但只覆盖数据作者写出的前缀；GRPO 等 RL 让模型从自己的策略采样，覆盖 on-policy 状态，却主要依赖整条答案正确与否的稀疏 reward。OPSD 试图把两者的优点组合起来：student 自己决定走到哪些前缀，teacher 在这些前缀上提供完整 next-token 分布，而 teacher 不需要是更大的外部模型。

“自蒸馏”在这里并非同一个分布复制自己。模型参数相同，但输入信息不同：student 只看到题目 $x$，teacher 额外看到参考 CoT 与答案 $y^*$。因此 $p_T(\cdot\mid x,y^*,\hat y_{<t})$ 与 $p_S(\cdot\mid x,\hat y_{<t})$可以不同。teacher 的 privileged information 类似有答案的导师，它仍在 student 实际写出的前缀上判断下一步，而不是另外生成一条顺畅解答供 student 离线模仿。这样既避免持有更大 teacher，也减少训练/推理分布错位。

这一路线的关键风险也来自 privileged context。知道答案的 teacher 可能偏好更短、更直接、缺少探索的推理；自教师的能力上限仍由同一模型决定，若模型无法利用参考解来形成可靠的局部建议，蒸馏不会凭空产生能力。后续 [Why Does Self-Distillation Sometimes Degrade Reasoning](#paper=paper-opd-2603-24472)给出这种退化的系统证据。因此本文的主张应限定为：在给定数学数据、Qwen3 尺度和训练 recipe 下，privileged teacher 的稠密分布监督比相同预算的对照更有效，而不是“所有看答案的自蒸馏都会提升推理”。

## 2. 方法与实现机制

训练集 $\mathcal S=\{(x_i,y_i^*)\}$同时提供题目和参考推理。每步先把同一模型实例化为两个条件分支：

$$
p_S(\cdot\mid x)=p_\theta(\cdot\mid x),\qquad
p_T(\cdot\mid x,y^*)=p_\theta(\cdot\mid x,y^*).
$$

student 采样 $\hat y\sim p_S(\cdot\mid x)$。在每个 student 前缀 $\hat y_{<t}$，teacher 带着 $y^*$计算 next-token logits；loss 沿 student 访问状态求分布散度：

$$
\mathcal L_{\text{OPSD}}(\theta)=
\mathbb E_{(x,y^*)\sim\mathcal S}\mathbb E_{\hat y\sim p_S(\cdot\mid x)}
\left[\frac{1}{|\hat y|}\sum_t D\!\left(p_T(\cdot\mid x,y^*,\hat y_{<t})\,\|\,p_S(\cdot\mid x,\hat y_{<t})\right)\right].
$$

teacher 分支 stop-gradient，梯度只流过 student logits。否则同一参数同时移动 target 与 prediction，目标会随更新漂移。主实验使用全词表 generalized JSD（$\beta=0.5$）；论文比较 forward KL、reverse KL 与 JSD，也比较只在 sampled token 上构造 policy-gradient 优势的轻量版本。这里不能把“自蒸馏”误写成 EMA teacher：teacher 与 student 是同一 checkpoint、不同 prompt 条件，且论文报告 in-training policy 作为 teacher 比滞后 policy 更稳定。

![Figure 1 · OPSD 的双条件、单 rollout 训练流程](./assets/papers/paper-opd-2601-18734/figure-1-pdf.png)

**Figure 1 解读。** 左侧同一个样本 $(x,y^*)$进入同一 LLM；中间 student prompt 只有 $x$，teacher prompt 包含 $x,y^*$。只有 student 生成 $\hat y$，teacher 在 $\hat y$ 的每个前缀上重新评分。右侧每 token divergence 的梯度只回到 student logits。图中的 teacher 没有单独 rollout，因此 OPSD 的覆盖仍来自 student policy，而监督密度来自 privileged teacher。[原图：固定 PDF Figure 1](https://arxiv.org/pdf/2601.18734v1#page=2)。

全词表目标能同时告诉 student 哪些未采 token 更合理，代价是每个位置保存/传输 vocabulary-sized logits。sampled-token 版本只用 $\log p_T(\hat y_t)-\log p_S(\hat y_t)$，显存较轻但丢掉其他候选。论文 Table 3 在 Qwen3-4B、2,048 生成长度下，full-vocabulary 在 AIME25/HMMT25 为 **84.1/60.0**，sampled-token 为 **82.1/57.3**，表明额外分布信息在该设置中有用；这不是说 full logits 在所有硬件预算都更划算。

官方仓库固定在 commit [`ae7d251`](https://github.com/siyan-zhao/OPSD/tree/ae7d2519e94920c4eb6206c0c26de46d9c50abae)。训练器先取得 on-policy student outputs，再为 teacher/student 两种 prompt 计算 logits，`compute_loss`选择 divergence，`generalized_jsd_loss`实现可选 JSD。源码核对的重点应是 attention mask 是否让 teacher 看到参考解但 loss 只落在 student response、teacher logits 是否 detach、序列 padding 是否排除；单独看到 JSD 函数不能证明整套 privileged-context 数据流正确。

## 3. 实验设置与算力

实验使用 Qwen3-1.7B、4B、8B Instruct，训练数据为 OpenThoughts reasoning 子集：从约 30K problem-solution pairs 中抽取，包含 chain-of-thought 参考。评测覆盖 AIME24、AIME25、HMMT25、AMO-Bench。主表评测使用每题 16 个样本的 average@16，temperature 1.2，最大生成长度约 38K；训练评测口径与训练时 completion cap 不同，不能把训练 2K cap 当成最终推理长度。

| 项目 | GRPO | OPSD |
| --- | --- | --- |
| Optimizer / LR | AdamW，$2\times10^{-5}$ | AdamW，$2\times10^{-5}$ |
| Batch / accumulation | per-device 1；accumulation 4；effective batch 32 | 相同 |
| 参数高效训练 | LoRA rank 64、alpha 128；q/k/v/o 与 MLP projections | 相同 |
| 每 prompt generations | 8 | 1 |
| Completion cap | 表中 16,000；效率图按 16,384 描述 | 2,048（另做 1,024/4,096 消融） |
| Temperature | 1.2 | 1.2 |
| 监督 | outcome reward / group relative | privileged teacher 的逐 token full-vocab divergence |
| 硬件 | 8×NVIDIA A100；gradient checkpointing；Flash Attention 2；bf16 | 相同 |
| 未披露 | 精确 A100 型号/显存、GPU-hours、功耗、多 seed 方差 | 同左 |

![Table 6 · GRPO 与 OPSD 的对照训练配置](./assets/papers/paper-opd-2601-18734/table-6-pdf.png)

**Table 6 解读。** 两者学习率、batch 与 LoRA 配置一致，但采样预算差异很大：GRPO 每 prompt 8 条、最长约 16K，OPSD 1 条、最长 2K。这个设计正是 token-efficiency 比较的对象，却不等于“更新步数相同就是等总算力”；OPSD 还需要 teacher full-vocab forward 与 divergence。论文披露 8×A100，但没有提供逐方法 GPU-hours，所以只能复述 token 生成量与相对墙钟趋势。[原表：固定 PDF Table 6](https://arxiv.org/pdf/2601.18734v1#page=13)。

SFT 基线使用 4 epochs、effective batch 64、最长 16K；GRPO/OPSD effective batch 32。评测每 prompt 16 samples，而训练 OPSD 每 prompt 只有 1 rollout。模型 scale、generation length、full-vocab vs sampled-token 是分开的消融轴；阅读结果时应避免把 8B 优势、长推理优势与 divergence 选择混为一个因素。

## 4. 结果与图表解读

![Table 2 · Qwen3 三个规模上的数学主结果](./assets/papers/paper-opd-2601-18734/table-2-pdf.png)

**Table 2 解读。** 8B 的 Base/SFT/GRPO/OPSD 平均为 **50.0/50.0/51.3/52.2**；4B 为 **48.3/49.6/49.6/50.6**；1.7B 为 **28.8/28.0/30.5/30.4**。因此 OPSD 在 8B、4B 明确高于表内 GRPO，1.7B 则低 0.1，支持作者“更有能力的模型更能利用 privileged context”的尺度解释，也阻止我们写成三规模全胜。逐列同样有例外：8B AMO-Bench 的 GRPO 14.8 高于 OPSD 14.3，4B AIME25 的 GRPO 67.1 高于 OPSD 66.9。[原表：固定 PDF Table 2](https://arxiv.org/pdf/2601.18734v1#page=6)。

![Figure 3 · 更新步数与生成 token 数下的 OPSD/GRPO 效率](./assets/papers/paper-opd-2601-18734/figure-3-pdf.png)

**Figure 3 解读。** 左图按 gradient steps 比较，OPSD 与 GRPO 早期都提升，OPSD 在多数 checkpoint 略高；右图把横轴换成累计生成 tokens，OPSD 用明显更少 token 达到相近或更高 average@16。论文据此报告 **4–8× token efficiency**。这主要来自每 prompt 1×2K 对 8×16K 的 rollout 配置，同时 OPSD 有额外 teacher logit 计算；所以“少生成 token”可靠，“端到端算力也严格 4–8×”没有 GPU-hours 支撑。[原图：固定 PDF Figure 3](https://arxiv.org/pdf/2601.18734v1#page=7)。

长度消融显示 Qwen3-4B 的 2,048 与 4,096 token 训练通常优于 1,024，尤其 pass@K；更长轨迹提供更多 teacher feedback，但也增加成本和可能的低价值尾部。论文还观察 full-vocab 优于 sampled-token。综合来看，OPSD 的收益来自三件事共同作用：student states、参考解条件化、稠密全分布监督；现有表格没有完全分离“参考解质量”和“teacher 同模型能力”的影响。

## 5. 局限、结论与后续阅读

OPSD 展示了一种不需要外部大 teacher 的 on-policy 稠密监督：同一模型在 privileged/unprivileged 两种上下文中形成师生差，沿 student 自己的错误或不完整前缀提供局部分布。三规模结果说明 4B/8B 有稳定改善，1.7B 没有超过 GRPO；token 生成量显著减少，但 full-vocab teacher forward 与 8×A100 总成本尚未量化。

方法依赖训练集含可信参考 CoT 与答案，也依赖模型会正确使用它们；teacher 和 student 参数相同限制了新知识来源。答案泄露可能压缩探索过程，后续负面分析提醒不能只看最终准确率。实验集中在竞赛数学、Qwen3 和单一训练数据，没有验证开放式任务、代码、事实知识或不同 tokenizer。主表也未给训练多 seed 均值方差。

复现验收应先做数据路径测试：同一 $x$ 下 teacher prompt 确实多出 $y^*$，两支共享 student response，teacher logits detach，loss mask 不覆盖参考解。随后分别记录 full-vocab 显存/通信、累计生成 token、teacher forward FLOPs、墙钟与 pass@K，才能判断相对 GRPO 的真实系统收益。还应加入“仅答案、无 CoT”“错误参考”“去掉 privileged context”的对照，确认提升来自可迁移推理信号而非提示格式。
