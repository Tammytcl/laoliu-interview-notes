## 1. 背景与已有工作

**阅读定位。**《Trust Region On-Policy Distillation》放在 OPD 文献链条中，核心问题不是把一个最终答案从 teacher 复制给 student，而是 student 先在当前策略下生成前缀，teacher 再对这些真实会遇到的状态提供监督。这样可减少离线 teacher 轨迹与 student 部署轨迹的分布偏移，但代价是每轮都要生成、teacher 前向和更新，稳定性、概率空间以及评测预算会互相耦合。

本报告把贡献拆成“问题假设—训练信号—工程实现—证据边界”四层。与 SFT 相比，OPD 监督的是 student rollout；与 RL 相比，它通常不必为每题设计外部 reward，而以 teacher 分布或似然差为反馈；与离线 KD 相比，它能在 student 的错误前缀上纠偏。若 teacher 与 student tokenizer、终止符或能力分布不同，还会额外出现概率不可比、长度偏差或局部信号失真的问题。阅读原文时应先确认论文解决的是哪一层，而不是把所有提升笼统归因于“on-policy”。

这套定位也限定了结论：论文中的 benchmark 增益只能支持给定模型、数据和预算下的机制，不能自动外推到任意规模或任务。尤其需要区分 teacher 更强带来的上限、训练 token 更多带来的算力收益，以及新目标函数本身的贡献。后文保留原论文页面证据与负结果，避免只摘摘要中的最佳数字。

OPD 的逆 KL 或 sampled-token log-ratio 在 teacher/student 差异过大时会出现离群 token：student 访问的某个前缀上，teacher 对已采 token 极低概率，强迫模仿可能导致高方差或坏更新。只用 teacher full-vocab forward KL 又可能让小 student 追逐自己短期学不到的模式。TrOPD 将这一矛盾写成**信任域问题**：哪些 token/状态适合按 on-policy 逆 KL 学，哪些应改用较稳的分布监督？

和 [Reopold](#paper=paper-opd-2603-11137)一样，它关心极端 token，但做法更明确地区分采样 token 的信号与截断词表分布信号；读两篇时应看触发条件、被 mask 的位置和是否补上 forward-KL 监督。

## 2. 方法与实现机制

![原论文方法证据页](./assets/papers/paper-opd-2606-01249/figure-1-pdf.png)

上图直接截取自 arXiv v1 固定 PDF。阅读时沿三条线核对：输入与 student rollout 怎样形成当前状态；teacher 在同一状态上输出 token 概率、表示或校正信号；哪些量 stop-gradient、哪些参数真正更新。整页保留公式上下文，是为了避免孤立裁图把动机曲线误当成算法流程。Trust Region On-Policy Distillation 的具体创新应以原文符号为准，已有正文随后解释其论文专属部件。

统一地，student 轨迹记为 y~pi_theta(.|x)，teacher 为 pi_T。标准 token 级 on-policy 蒸馏可写成

$$L(theta)=E_{x,y~pi_theta}[sum_t D(pi_theta(.|x,y_{<t}),pi_T(.|x,y_{<t}))].$$

这里最关键的是期望分布也依赖 student：参数更新后，下一批前缀会变，teacher 监督的位置随之移动。若实现先缓存 teacher 自己生成的固定答案，目标就退化为 off-policy；若 teacher 和 student 看到的模板、温度或 EOS 不一致，似然差还会混入协议偏差。散度是 reverse KL、forward KL、JS、回归损失还是经过门控的组合，会决定 mode-seeking、coverage 和梯度尺度，不能只用“KD loss”概括。

复现时建议把一次训练 step 拆成六个可审计阶段：固定 prompt 与模板；student 生成并记录 token/终止原因；teacher 在完全相同前缀上前向；构造论文定义的 token 掩码、权重或对齐；只对 student 反向；记录有效 token 数与梯度范数。对于跨 tokenizer 方法，还必须保存共同 byte/event 单元到两侧 token 的映射；对于自蒸馏，必须冻结 teacher 快照或明确同步频率；对于 verifier/多 teacher 方法，则要记录门控拒绝率与各 teacher 被选比例。

公式实现有三个常见陷阱。第一，用 batch mean 代替有效 token mean 会让长回答获得更大权重；第二，teacher logits 的温度缩放、top-k 截断和重新归一化次序会改变目标；第三，在本应 stop-gradient 的权重上反传，会引入论文没有的高方差项。最小测试应构造一个两 token 词表，手算每项概率、mask 与梯度方向，再做端到端小 batch 对照。本报告把论文原图与已有仓库线索分开：即使仓库存在，也应固定提交并逐项核对默认参数，不能用最新分支替代论文版本。

方法是否有效不能只看最终 accuracy。还要检查训练中 teacher-student KL、student 熵、回答长度、EOS 概率、有效更新 token 比例、梯度范数和 rollout 成功率。若主指标上涨却长度暴增、熵坍缩或 OOD 明显下降，应视为带代价的权衡。原文方法图、后续配置页和两页结果证据共同构成可追溯链条。

论文在每个 student 前缀计算 teacher 与 student 的差异，将“可靠的采样 token”保留在 reverse-KL 分支，对过大差异/越出 trust region 的位置采取另一种监督或抑制策略。目标中可见一个 mask $\mathbb M$：一支按采样 token 的 $\log p_T/p_S$ 更新，另一支用 teacher top-$k$ 分布的 forward-KL 信息。这样不是盲目把 outlier 扔掉；要看异常位置是否通过另一分支仍给了可学习方向。

Table 1 把简单 FKL、JSD、Clip/Mask Outlier 和 TrOPD 摆在一起；对照能分离“混合散度本身”与“按可靠性切换”的贡献。官方 [TrOPD 仓库](https://github.com/Xingrun-Xing2/TrOPD/tree/main)已确认；本轮未逐函数核读，复现时要检查判定阈值用的是更新前 student 还是更新中 student，top-$k$ 概率是否重新归一化，以及 mask 与 padding 如何交互。

## 3. 实验设置与算力

![原论文实验配置证据页](./assets/papers/paper-opd-2606-01249/table-2-pdf.png)

该页来自固定 PDF 中包含训练细节、超参数或附录配置的页面。它的用途是建立复现账本，而不是把所有正文数字重新抄一遍。应从页内核对模型与 teacher/student 角色、数据集划分、学习率、batch、rollout 数、最大长度、采样温度、训练步数和 checkpoint 选择规则；没有披露的项目必须明确记为“原文未披露”，不能根据模型规模猜测。

| 复现维度 | 必须记录的字段 | 为什么重要 |
|---|---|---|
| 模型协议 | checkpoint、tokenizer、chat template、EOS | 决定概率是否可比 |
| 采样预算 | prompts、每题 rollout、温度、top-p、最大长度 | 决定探索与成本 |
| 优化 | loss、学习率、batch、累积、step/epoch | 决定梯度尺度 |
| teacher 成本 | 前向 token、logits/top-k、缓存策略 | OPD 的主要额外开销 |
| 评测 | seed、样本数、Avg@k/Pass@k、judge | 防止口径漂移 |
| 算力 | GPU 型号、卡数、GPU-hours | 判断收益是否等预算 |

公平对照至少要固定 student 起点、训练 prompt、生成 token 总量和评测解码。只固定 step 不够：多 rollout、更长回答和更大 teacher 会显著增加计算。若论文没有完整 GPU 型号、卡数或 GPU-hours，本报告将其视作披露缺口；复现时需单独测量 student 生成、teacher 前向、反向传播和评测四部分 wall-clock。已有正文中的论文专属模型、数据和参数说明应与这张账本结合阅读。

统计上应报告多个随机种子或置信区间，并把 checkpoint 选择放在独立验证集。Pass@k 会随 k 和采样温度上涨，不能与 greedy accuracy 混写；LLM judge 需要固定版本与 prompt；verifier 过滤后的有效样本量也要报告。只有配置、预算和指标都对齐，结果差异才可归因于方法。

数学单域使用 DeepSeek-R1-Distill-Qwen-1.5B student、SkyWork-OR1-Math-7B teacher，不再额外做 SFT cold start；还测试多领域数学、STEM、指令遵循等设置。数学评测 AIME24、AIME25、AMC23，报告 **32 次评测平均准确率**；其他评测包括 GPQA Diamond、MMLU-Redux v2、IFBench 与 LiveCodeBench v6。论文把同组训练预算固定，才适合比较损失设计。

完整词表/top-$k$ teacher 输出与 sampled-token OPD 的显存和通信需求不同，精度比较之外应另记计算成本。主文没有统一 GPU-hours 供直接折算，尤其不能从“同训练步数”推出同资源使用。

## 4. 结果与图表解读

这页保留主结果表及其上下文。正确读法是在同一 student、teacher、训练集和生成预算下横向比较，而不是跨模型挑最大数字。粗体通常只是该表最优，并不代表统计显著；若差距小于随机种子波动，应写成“相当”而非稳定领先。已有正文给出的论文专属数字是主结论，原表用于检查是否遗漏弱项、不同指标方向或 teacher 上限。

![原论文补充结果或消融证据页](./assets/papers/paper-opd-2606-01249/figure-2-pdf.png)

第二页用于交叉验证机制，通常包含另一组结果、曲线、消融或误差分析。阅读时关注三件事：去掉关键部件后是否退化；收益是否随模型规模、任务难度或 rollout 数保持；训练稳定性、长度和 OOD 是否付出代价。若第二页只支持相关性而非因果，就不能用它证明组件“导致”提升；若存在红色负值或非最优格，应保留为结论边界。

结果证据应形成闭环：主表回答“最终是否更好”，曲线回答“训练是否更稳/更快”，消融回答“哪个部件起作用”，成本表回答“是否等预算”。任一环节缺失都降低因果强度。尤其在 OPD 中，更强 teacher、更长 rollout 或更多 teacher 前向本身就可能提高分数，因此必须同时报告 teacher 调用量和生成 token。只引用平均值还会掩盖 AIME 这类小样本基准的高方差。

实践决策不能只追最高 accuracy。若目标是单次在线回答，应重视 Pass@1/Avg@k 与延迟；若允许 test-time scaling，才关注较大 k 的 Pass@k；若模型需要持续更新，还要测 OOD、遗忘和连续多轮蒸馏。本文据原图与正文只给“这些实验设置下”的结论，不把局部结果外推成普遍规律。

**Table 1** 的数学三项均值：初始 student **41.27**，普通逆 KL OPD **46.79**，TrOPD **49.85**；AIME24 **35.83→38.54**、AIME25 **29.16→32.50**、AMC23 **75.39→78.51**。单纯 FKL 在该表几乎失败，均值 **1.40**，提醒“给所有位置换成 forward KL”不是稳健解。Clip/Mask outlier 的均值约 **47.86/47.72**，也低于 TrOPD；这为“异常位置的替代监督”提供了比只剪裁更强的实验支持。

这个结果表限于特定 teacher/student、数学数据与评测脚本。若阅读多领域表，应留意各任务的响应长度与 outlier 频率差异；一个全局阈值可能让数学与代码的有效监督比例不同。方法的价值在于明确报告 mask 命中率与两类 loss 的实际占比。

## 5. 局限、结论与后续阅读

共同局限可以归为四类：teacher 可能在 student 前缀上失准；on-policy 反复调用 teacher，训练成本高于离线 SFT；tokenizer/EOS/template 不一致会把协议差异伪装成知识差异；多数论文集中在数学或可验证任务，开放式对话、代码和长期遗忘证据仍少。Trust Region On-Policy Distillation 应在这些边界内理解，不能因一个平均分提升就宣称普遍优于所有蒸馏或 RL 方法。

后续复现优先做等生成 token、等 teacher 前向和等 GPU-hours 三套对照，并报告长度、熵、KL、有效 token、梯度范数、OOD 与失败案例。阅读路线可依次对照普通 off-policy KD、标准 RKL OPD、本文专属改进以及同主题的稳定化/跨 tokenizer 工作。最终判断标准是“收益来自哪里、付出什么成本、在何种条件下失效”，而不是只复述摘要。

TrOPD 依赖能取得 teacher 的 top-$k$ 概率；只返回最终文本的黑盒 teacher 无法直接复制。trust-region 判定本身可能被 tokenizer、温度和 student 冷启动水平改变。下次复现宜报告每个任务的离群比例、被切换 token 的错误类型，以及相同 teacher 计算预算下的结果。
