## 1. 背景与已有工作

**阅读定位。**《When EOS Tokens Disagree: Understanding Length Inflation in On-Policy Distillation》放在 OPD 文献链条中，核心问题不是把一个最终答案从 teacher 复制给 student，而是 student 先在当前策略下生成前缀，teacher 再对这些真实会遇到的状态提供监督。这样可减少离线 teacher 轨迹与 student 部署轨迹的分布偏移，但代价是每轮都要生成、teacher 前向和更新，稳定性、概率空间以及评测预算会互相耦合。

本报告把贡献拆成“问题假设—训练信号—工程实现—证据边界”四层。与 SFT 相比，OPD 监督的是 student rollout；与 RL 相比，它通常不必为每题设计外部 reward，而以 teacher 分布或似然差为反馈；与离线 KD 相比，它能在 student 的错误前缀上纠偏。若 teacher 与 student tokenizer、终止符或能力分布不同，还会额外出现概率不可比、长度偏差或局部信号失真的问题。阅读原文时应先确认论文解决的是哪一层，而不是把所有提升笼统归因于“on-policy”。

这套定位也限定了结论：论文中的 benchmark 增益只能支持给定模型、数据和预算下的机制，不能自动外推到任意规模或任务。尤其需要区分 teacher 更强带来的上限、训练 token 更多带来的算力收益，以及新目标函数本身的贡献。后文保留原论文图表证据与负结果，避免只摘摘要中的最佳数字。

在 sampled-token OPD 中，teacher 只评价 student **实际采到的 token**。若 teacher 与 student 用不同的 EOS 表示“停止”，就会出现反直觉梯度：student 采到自己的 EOS，teacher 对这个表面 token 概率低，OPD 把 student 的停止行为压下去；但 teacher 其实把高概率给了另一个等价 EOS。结果可能是学生已答对却继续写冗余内容，直到触发生成长度上限。

这类错误不能靠“多登记一个停止 token”彻底修复，因为解码器停止规则与 loss 的概率信号是两条路径。论文把特殊 token 匹配从普通 tokenizer 对齐中单独拿出来，是整个跨模型 OPD 工作流都该注意的边界条件。

## 2. 方法与实现机制

![EOS 机制诊断：末端终止 token 概率](./assets/papers/paper-opd-2609-20511/eos-diagnostic-source.png)

原图测量每条 rollout 最后生成位置的终止 token 概率，并区分自然结束和长度截断。它是 EOS 分歧的诊断图，不是新算法流水线；需要结合 teacher/student 的原生模板解释终止偏好。末端位置的统计不能代表整条轨迹所有状态，但足以揭示协议差异可能污染局部蒸馏信号。 图源：[arXiv 2609.20511v1 LaTeX 源码](https://arxiv.org/src/2609.20511v1)，原始文件 `fig/eos_prob.png`。

作为比较基线，student 轨迹记为 $y\sim\pi_\theta(\cdot\mid x)$，teacher 为 $\pi_T$。常见 token 级 on-policy 蒸馏的示意目标写成下式；它不代表本文所有变体都采用同一散度或同一梯度估计器：

$$\mathcal{L}(\theta)=\mathbb{E}_{x,\,y\sim\pi_\theta(\cdot\mid x)}\!\left[\sum_t D\!\left(\pi_\theta(\cdot\mid x,y_{<t}),\pi_T(\cdot\mid x,y_{<t})\right)\right].$$

这里最关键的是期望分布也依赖 student：参数更新后，下一批前缀会变，teacher 监督的位置随之移动。若实现先缓存 teacher 自己生成的固定答案，目标就退化为 off-policy；若 teacher 和 student 看到的模板、温度或 EOS 不一致，似然差还会混入协议偏差。散度是 reverse KL、forward KL、JS、回归损失还是经过门控的组合，会决定 mode-seeking、coverage 和梯度尺度，不能只用“KD loss”概括。

复现时建议把一次训练 step 拆成六个可审计阶段：固定 prompt 与模板；student 生成并记录 token/终止原因；teacher 在完全相同前缀上前向；构造论文定义的 token 掩码、权重或对齐；只对 student 反向；记录有效 token 数与梯度范数。对于跨 tokenizer 方法，还必须保存共同 byte/event 单元到两侧 token 的映射；对于自蒸馏，必须冻结 teacher 快照或明确同步频率；对于 verifier/多 teacher 方法，则要记录门控拒绝率与各 teacher 被选比例。

公式实现有三个常见陷阱。第一，用 batch mean 代替有效 token mean 会让长回答获得更大权重；第二，teacher logits 的温度缩放、top-k 截断和重新归一化次序会改变目标；第三，在本应 stop-gradient 的权重上反传，会引入论文没有的高方差项。最小测试应构造一个两 token 词表，手算每项概率、mask 与梯度方向，再做端到端小 batch 对照。作者未开源与该论文一一对应的官方代码仓库，因此这里只能依据固定版论文、公式和附录核读，不能声称函数级实现已验证。

方法是否有效不能只看最终 accuracy。还要检查训练中 teacher-student KL、student 熵、回答长度、EOS 概率、有效更新 token 比例、梯度范数和 rollout 成功率。若主指标上涨却长度暴增、熵坍缩或 OOD 明显下降，应视为带代价的权衡。原文方法图、后续配置说明和结果图表共同构成可追溯链条。

作者先在 Qwen3 base student / post-trained teacher 上诊断：base 偏好 `<|endoftext|>`，teacher 也把 `<|im_end|>` 作为会话终止，并在实际终止前缀更偏好后者。student 对后者概率可低至约 $10^{-11}$，单纯在 decoding stop set 加它几乎等于没用；sampled-token 训练也几乎采不到它，却不断压低 native EOS。

论文比较四种修正。Fix 1 只统一解码停止集合，作为失败对照；Fix 2 把 teacher 对所有等价 EOS 的概率质量汇到 student 的 canonical EOS；Fix 3 把等价 EOS 看作一个语义动作 “stop”；Fix 4 同时给 student 构造单一 EOS 行为空间。读 Figure 2 要沿**同一终止前缀**比较 EOS 类总概率，而不是只比两个 token id。Fix 2 在所测 Qwen3 情况已足够，但它要求知道哪几个 token 真正语义等价。

原文没有对应的作者官方训练仓库；其中 Qwen 文档链接是 tokenizer/模型说明，不能当成 EOS 修复代码。本文只做公式与实验核读。

## 3. 实验设置与算力

![Table 2：主要实验训练超参数](./assets/papers/paper-opd-2609-20511/table-2-config-pdf.png)

原表给出训练阶段的 batch、长度、采样和优化设置；同页 Table 3 的 checkpoint 评测采样参数是另一套协议，这里没有将二者混在一起。研究 EOS 时尤其要保留停止条件与最大长度，达到长度上限的样本不等于自然生成 EOS，二者混记会直接改变诊断结论。 图表源：[arXiv 2609.20511v1 PDF，第 17 页](https://arxiv.org/pdf/2609.20511v1#page=17)，仅裁图表区域。

| 复现维度 | 必须记录的字段 | 为什么重要 |
|---|---|---|
| 模型协议 | checkpoint、tokenizer、chat template、EOS | 决定概率是否可比 |
| 采样预算 | prompts、每题 rollout、温度、top-p、最大长度 | 决定探索与成本 |
| 优化 | loss、学习率、batch、累积、step/epoch | 决定梯度尺度 |
| teacher 成本 | 前向 token、logits/top-k、缓存策略 | OPD 的主要额外开销 |
| 评测 | seed、样本数、Avg@k/Pass@k、judge | 防止口径漂移 |
| 算力 | GPU 型号、卡数、GPU-hours | 判断收益是否等预算 |

公平对照至少要固定 student 起点、训练 prompt、生成 token 总量和评测解码。只固定 step 不够：多 rollout、更长回答和更大 teacher 会显著增加计算。若论文没有完整 GPU 型号、卡数或 GPU-hours，本报告将其视作披露缺口；复现时需单独测量 student 生成、teacher 前向、反向传播和评测四部分 wall-clock。已有正文中的论文专属模型、数据和参数说明应与这张账本结合阅读。

统计上应报告多个随机种子或置信区间，并把 checkpoint 选择放在独立验证集。Pass@k 会随 k 和采样温度上涨，不能与 greedy accuracy 混写；LLM judge 需要固定版本与 prompt；verifier 过滤后的有效样本量也要报告。只有配置、预算和指标都对齐，结果差异才可归因于方法。

主实验覆盖 Qwen3，另在 Llama 3.2、Gemma 3 上检验终止错配；Table 1 列出各 checkpoint 的 EOS 配置，Table 2–3 给训练与采样参数。评估不能只报正确率，还需同时记录平均回答长度、达到 cap 的比例和“已经答对后是否继续输出”。EOS 修正若减少无效长回答，吞吐也可能改善，但要区分训练时和推理时的节约。

文章没有一个统一的 GPU-hours 表。对于长推理模型，即使精度表变化不大，大量生成到 cap 也会显著浪费推理 token；复现要把 max response 长度固定，并比较长度分布，而非每组使用不同截断。

## 4. 结果与图表解读

![四种 EOS 校正的 Qwen3 对照](./assets/papers/paper-opd-2609-20511/eos-corrections-source.png)

原图比较四种终止校正策略下的训练行为，检查不同校正是否消除长度漂移。判断方法不能只看输出更短：也要检验是否恢复正常终止并保持任务表现。该面板对应 Qwen3 设置，不能直接替代 Gemma 的共享 EOS 集实验；不同家族的终止协议需要分别处理。 图源：[arXiv 2609.20511v1 LaTeX 源码](https://arxiv.org/src/2609.20511v1)，原始文件 `fig/fixed_cmp.png`。

![有无 EOS 校正时的模板依赖评测](./assets/papers/paper-opd-2609-20511/template-evaluation-source.png)

原图在 Qwen3-4B→Qwen3-1.7B-Base 的 DAPO 蒸馏设置下，对照评测模板与 EOS 校正。任务分数和输出行为会受模板影响，因此只改评测 prompt 就可能改变表面排名。这里的证据支持把训练、教师评分和评测协议分别记录，而不是宣称某一个模板适用于所有模型。 图源：[arXiv 2609.20511v1 LaTeX 源码](https://arxiv.org/src/2609.20511v1)，原始文件 `fig/baseline_eval.png`。

结果证据应形成闭环：主表回答“最终是否更好”，曲线回答“训练是否更稳/更快”，消融回答“哪个部件起作用”，成本表回答“是否等预算”。任一环节缺失都降低因果强度。尤其在 OPD 中，更强 teacher、更长 rollout 或更多 teacher 前向本身就可能提高分数，因此必须同时报告 teacher 调用量和生成 token。只引用平均值还会掩盖 AIME 这类小样本基准的高方差。

实践决策不能只追最高 accuracy。若目标是单次在线回答，应重视 Pass@1/Avg@k 与延迟；若允许 test-time scaling，才关注较大 k 的 Pass@k；若模型需要持续更新，还要测 OOD、遗忘和连续多轮蒸馏。本文据原图与正文只给“这些实验设置下”的结论，不把局部结果外推成普遍规律。

**Figure 1(a)** 显示 vanilla OPD 训练中回答长度和截断率上升；Figure 1(b) 的样例说明模型常在正确答案后继续写。**Figure 4(a)** 的 Fix 1 曲线接近 vanilla OPD，直接证明“改停止集合”没有改掉模型分布里 EOS 的学习信号。Figure 2 显示 native EOS 与 teacher-preferred EOS 概率质量错位，给长度膨胀提供机制解释。

Fix 2–4 在所测 Qwen3 消融中接近，说明修正概率层面的终止事件比只改解码更重要。作者还讨论其它模型里 student 对 teacher EOS 有非忽略概率的情况：表面形式可以被学到，但后续仍可能出现长度问题，因此要同时观察“学会用哪个 EOS”和“是否按时停止”。


**图解。** 四幅曲线以训练步数为横轴，分别在两种聊天模板下追踪 student 与 teacher 对 `endoftext`、`im_end` 的终止概率。student 自己的 EOS 概率逐渐下降，而 teacher 偏好的另一个 EOS 并未被 student 有效学到；这比只看最终平均长度更接近失效机制。 [图源：arXiv 2609.20511v1](https://arxiv.org/html/2609.20511v1)。

## 5. 局限、结论与后续阅读

共同局限可以归为四类：teacher 可能在 student 前缀上失准；on-policy 反复调用 teacher，训练成本高于离线 SFT；tokenizer/EOS/template 不一致会把协议差异伪装成知识差异；多数论文集中在数学或可验证任务，开放式对话、代码和长期遗忘证据仍少。When EOS Tokens Disagree: Understanding Length Inflation in On-Policy Distillation 应在这些边界内理解，不能因一个平均分提升就宣称普遍优于所有蒸馏或 RL 方法。

后续复现优先做等生成 token、等 teacher 前向和等 GPU-hours 三套对照，并报告长度、熵、KL、有效 token、梯度范数、OOD 与失败案例。阅读路线可依次对照普通 off-policy KD、标准 RKL OPD、本文专属改进以及同主题的稳定化/跨 tokenizer 工作。最终判断标准是“收益来自哪里、付出什么成本、在何种条件下失效”，而不是只复述摘要。

EOS 等价类需要根据具体模型与 chat template 定义；强行合并并非所有特殊 token 都安全，尤其工具调用结束、消息结束与整段生成结束可能是不同动作。跨 tokenizer OPD 实验若没有报告 EOS 映射、长度和 cap-hit，精度结论可能被隐藏的终止失效污染。后续可把本论文与 [BPM](#paper=paper-opd-2607-22334) 的字节前缀对齐一起读：普通文本字节对齐之后，特殊动作仍需单独建模。
