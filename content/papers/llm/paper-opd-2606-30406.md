## 1. 背景与已有工作

模型后训练常会把任务分成数学、指令遵循、代码或软件工程。对其中一个领域做强化学习（RL）能得到很强的专长模型，但用户需要的是同一个模型同时拥有这些能力。最直接的联合训练是把所有任务放进 Mix-RL；问题是不同任务的奖励、轨迹长度和更新节奏会相互牵制。Cascade RL 依次训练领域，后一个阶段可能遗忘前一个阶段。把各领域 teacher 生成的答案做离线 SFT，学生学习的是 teacher 已经走过的轨迹；部署时学生走到自己的错误前缀，训练数据不一定覆盖。参数合并则要求多个 RL checkpoint 的权重变化能够直接组合，效果依赖合并系数。

这篇论文的研究问题因此很具体：**能否让数学、指令遵循、软件工程的专长 teacher 独立训练，然后让单一 student 在自己的轨迹上吸收它们的能力？** 论文把这个流程称为 Multi-Teacher On-Policy Distillation（MOPD）。这里“多教师”指多个领域 RL 模型；[另一篇同缩写的 Multi-Rollout MOPD](#paper=paper-opd-2605-12652)则是同一题的成功/失败 student rollout 互相提供上下文，二者不能混为一种算法。

原文的出发点与 [GKD](#paper=paper-opd-2306-13649)相通：训练时取样于 student 当前可能访问的前缀，并请 teacher 在这些前缀上给出稠密监督。MOPD 新增的问题是“一个前缀应由哪位 teacher 监督，以及不同能力如何放进同一参数”。它先使用**题目的领域标签**路由到对应 teacher，后续 [MOPD-Router](#paper=paper-opd-2609-30837)才进一步研究动态路由。

## 2. 方法与实现机制

### 三阶段训练流水线

输入是覆盖目标领域的 prompt 集。阶段一对共同 base checkpoint 做跨领域 SFT，产生共享起点。阶段二从这个起点分叉，分别在数学、指令遵循、软件工程上做领域 RL；这些训练可以并行，最终得到冻结的领域 teacher。阶段三再从**同一个 SFT 起点**初始化 student：student 自己生成完整轨迹，按 prompt 的领域把轨迹交给相应 teacher，teacher 对轨迹每个前缀计算下一 token 分布，student 在其实际访问的状态上更新。最终留下一个统一模型，不需要在推理时运行全部 teacher。

写成概念公式，若 $d(x)$ 是 prompt $x$ 的领域、$\pi_\theta$ 是 student、$q_{d(x)}$ 是对应冻结 teacher，则目标沿 student 轨迹 $y\sim\pi_\theta(\cdot\mid x)$ 累加逐 token 的 reverse KL：

$$
\mathcal L = \mathbb E_{x,y\sim\pi_\theta}\sum_t D_{\mathrm{KL}}\!\left(\pi_\theta(\cdot\mid x,y_{<t})\,\|\,q_{d(x)}(\cdot\mid x,y_{<t})\right).
$$

这个式子说明监督发生在 student 前缀，且 teacher 按域切换；实际梯度估计与 top-$k$ 实现要看原文 §3.2。论文分别讨论基于采样 token 的 policy-gradient 实现和 top-$k$ 分布蒸馏实现，并在实验里比较两者。它们共享训练数据流，却有不同的 teacher logit 传输、估计偏差与显存代价。

**为什么共享起点有用？** 领域 teacher 和 student 都从同一个 SFT checkpoint 来，初始分布相对接近。教师再经各自 RL 向领域能力移动；与任意外部 teacher 相比，student 访问的前缀更可能仍在 teacher 有意义的监督范围内。论文 §4.4.2 用 same-origin 对照分析这一点；“同源更稳”是该设置下的实验解释，不能推论任意 teacher 都应来自同一个 checkpoint。

## 3. 实验设置与算力

原文 §4.1 的主比较从 **Qwen3-30B-A3B-Base** 出发，所有基线和 MOPD 使用同一个跨域 SFT 起点。数学用 AIME25/AIME26，指令遵循用 IFBench/IFEval，软件工程用 SWE-bench Verified。基线分别是 Mix-RL、Cascade RL、Off-Policy Finetune、两种 Param-Merge；另用 MiMo-V2-Flash 验证更大模型上的完整流水线。SWE-bench 是带软件工程环境的任务，不等同于简单补全函数；训练时 teacher RL 的环境成本也不能只按模型参数估算。

| 项目 | 原文可核信息与解释 |
|---|---|
| 共同初始化 | Qwen3-30B-A3B-Base → 跨域 SFT；所有融合方案从同一 SFT checkpoint 出发。 |
| Teacher 构造 | 按领域分别做 RL；数学、指令遵循、软件工程 teacher 冻结后用于第三阶段。 |
| Student 数据 | 多领域 prompt；第三阶段生成 student 自己的 rollout，teacher 在这些前缀评分。 |
| 评测 | AIME25/AIME26、IFBench/IFEval、SWE-bench Verified；MiMo-V2-Flash 还涉及代码、工具任务。 |
| 指标 | 各 benchmark 准确率，以及“相对 SFT 与领域 teacher 能力差距的归一化分数”。 |
| 训练算力 | 本轮核读的主文未给出可复核的 GPU 型号、卡数、墙钟时间或 GPU-hours；不能从 30B/309B 参数规模推算。 |

归一化分数对每个领域把 SFT student 设为 0、该领域 RL teacher 设为 1，再做领域平均。这样能比较“各域能力差距填上多少”，但也依赖每个领域所选 benchmark 与 teacher 的 headroom；不能解释为一个与任务无关的统一能力值。

## 4. 结果与图表解读

原文 **Table 2** 中，Qwen3-30B-A3B 的归一化分数为 MOPD **0.9373**、Mix-RL **0.8818**、Off-Policy Finetune **0.8241**、Cascade RL **0.7752**、Task Arithmetic **0.8574**。MOPD 相比这里最强基线 Mix-RL 高约 **0.0555**；这是按原文定义的三领域相对 headroom 比较，不是 AIME 或 SWE-bench 的“提高 5.55 个百分点”。单项指标仍有取舍：例如 MOPD 的 AIME25 为 51.46，低于该域 RL teacher 的 54.79；AIME26 为 65.31，高于 teacher 的 63.65。平均结论不能代替逐任务查看。

原文 **Figure 1** 的横轴是各领域已消耗的训练样本数（千），纵轴是各领域准确率；它用于说明收敛速度，而非 GPU 时间。论文声称 MOPD 在 IF 与 SWE 更快接近 teacher 水平，Mix-RL 需要更多样本才能达到相近水平。这个图支持“每个训练样本的学习信号更有效”的解释，但不同路线的 teacher 前向成本、RL 环境成本和并行度仍需另计，不能直接换算为总算力节省。

**Table 3** 的 MiMo-V2-Flash 实验更能说明“能力集成”不是每项都严格无损。MOPD 相对各领域 teacher 在 AIME25/HMMT25/LCB 等项略高，但 IFBench 低 **2.2** 分、SWE-bench Verified 低 **0.8** 分。这里比较的是同一报告内的模型与指标；不能把不同基准的绝对分数直接平均成通用能力排名。原文 Table 4 的第二轮 teacher→student 演化还说明可以再次进行领域 RL 与融合，但收益并非所有 benchmark 单调上升。

## 5. 局限、结论与后续阅读

这篇论文最重要的贡献是把“独立做领域 RL”和“单模型承接多域能力”串成一个可执行的后训练流程：共享起点、多域 teacher、学生自己采样、按域稠密监督。当前证据支持它在论文规定的 Qwen3-30B-A3B 三领域比较中优于所列融合基线，并在 MiMo-V2-Flash 上有工业规模示例；它不证明任意 teacher 组合、任意 tokenizer 或任意预算下都有效。

后续验证应固定 teacher 总计算预算与训练 prompt，比较按域硬路由、动态 token 路由和信号归一化；同时逐领域报告遗忘、teacher 调用量和 GPU-hours。[MOPD-Router](#paper=paper-opd-2609-30837)与 [DN-MOPD](#paper=paper-opd-2609-35347)正好分别把“选谁”和“信号尺度”拆开。来源：[arXiv v1](https://arxiv.org/abs/2606.30406v1)，本文核读 §3–4、Table 2–4 与 Figure 1；没有执行复现。
