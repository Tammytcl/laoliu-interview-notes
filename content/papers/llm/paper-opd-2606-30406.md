## 1. 背景与已有工作

模型后训练常会把任务分成数学、指令遵循、代码或软件工程。对其中一个领域做强化学习（RL）能得到很强的专长模型，但用户需要的是同一个模型同时拥有这些能力。最直接的联合训练是把所有任务放进 Mix-RL；问题是不同任务的奖励、轨迹长度和更新节奏会相互牵制。Cascade RL 依次训练领域，后一个阶段可能遗忘前一个阶段。把各领域 teacher 生成的答案做离线 SFT，学生学习的是 teacher 已经走过的轨迹；部署时学生走到自己的错误前缀，训练数据不一定覆盖。参数合并则要求多个 RL checkpoint 的权重变化能够直接组合，效果依赖合并系数。

这篇论文的研究问题因此很具体：**能否让数学、指令遵循、软件工程的专长 teacher 独立训练，然后让单一 student 在自己的轨迹上吸收它们的能力？** 论文把这个流程称为 Multi-Teacher On-Policy Distillation（MOPD）。这里“多教师”指多个领域 RL 模型；[另一篇同缩写的 Multi-Rollout MOPD](#paper=paper-opd-2605-12652)则是同一题的成功/失败 student rollout 互相提供上下文，二者不能混为一种算法。

原文的出发点与 [GKD](#paper=paper-opd-2306-13649)相通：训练时取样于 student 当前可能访问的前缀，并请 teacher 在这些前缀上给出稠密监督。MOPD 新增的问题是“一个前缀应由哪位 teacher 监督，以及不同能力如何放进同一参数”。它先使用**题目的领域标签**路由到对应 teacher，后续 [MOPD-Router](#paper=paper-opd-2609-30837)才进一步研究动态路由。

这里需要区分三个经常被混用的对象。**Prompt** 是训练任务的输入；**rollout** 是 student 以当前参数逐 token 写出的答案或交互轨迹；**teacher prefill** 是在这条已写出的轨迹上计算每个位置的条件概率，并非让 teacher 再生成一条新答案。传统离线模仿只见到固定 teacher 轨迹，student 自己犯错后形成的前缀不在训练集内；这里每次更新都先让 student 走一遍，再在它走过的地方问 teacher。这就是标题中 on-policy 的实质，而不是“用了 RL 框架就自动 on-policy”。

## 2. 方法与实现机制

**三阶段训练流水线**

输入是覆盖目标领域的 prompt 集。阶段一对共同 base checkpoint 做跨领域 SFT，产生共享起点。阶段二从这个起点分叉，分别在数学、指令遵循、软件工程上做领域 RL；这些训练可以并行，最终得到冻结的领域 teacher。阶段三再从**同一个 SFT 起点**初始化 student：student 自己生成完整轨迹，按 prompt 的领域把轨迹交给相应 teacher，teacher 对轨迹每个前缀计算下一 token 分布，student 在其实际访问的状态上更新。最终留下一个统一模型，不需要在推理时运行全部 teacher。

![Figure 1 · 共享 SFT、独立领域 RL 与按域在线蒸馏](./assets/papers/paper-opd-2606-30406/figure-1-pdf.png)

**Figure 1 解读。** 左边的 SFT 模型同时是各领域 teacher 与最终 student 的共同起点；中间各领域 RL 分支互不串行；右边每次由 student 生成轨迹，teacher 在这条轨迹上 prefill，reverse KL 信号回到 student。图中多个 teacher 是训练资源，并不表示线上推理要运行多个模型。流程图解释了数据和监督从何而来，却不能单独证明比 Mix-RL 更省总 GPU 成本；还要比较 teacher RL、teacher 服务和 student 更新的完整预算。[原图：arXiv v1 PDF，第 4 页](https://arxiv.org/pdf/2606.30406v1#page=4)。

写成概念公式，若 $d(x)$ 是 prompt $x$ 的领域、$\pi_\theta$ 是 student、$q_{d(x)}$ 是对应冻结 teacher，则目标沿 student 轨迹 $y\sim\pi_\theta(\cdot\mid x)$ 累加逐 token 的 reverse KL：

$$
\mathcal L = \mathbb E_{x,y\sim\pi_\theta}\sum_t D_{\mathrm{KL}}\!\left(\pi_\theta(\cdot\mid x,y_{<t})\,\|\,q_{d(x)}(\cdot\mid x,y_{<t})\right).
$$

这里 $x$ 是 prompt，$y_{<t}$ 是 student 已生成的前缀，$d(x)$ 是领域标签，求和沿真实 rollout 而非 teacher 自己采样的序列。原文还除以有效回答长度 $|y|$，防止长答案仅因 token 多而获得更大 loss。这个目标使用的是 **reverse KL**：当 student 在某个位置给一种 token 较高概率、teacher 却给很低概率时会受到惩罚；它不等于对 teacher 生成答案做交叉熵。训练时 teacher 冻结，实际实现可选择下面两种估计，不能把公式误认成必须传送完整词表概率。

第一种 policy-gradient 路线只读 student 实际采样 token 的概率。它把 $\log q_{d(x)}(y_t)-\log\pi_\theta(y_t)$ 当逐 token advantage，并在原文实现中截断到 $[-A_{\max},A_{\max}]$；默认 $A_{\max}=5$。直觉上，如果 teacher 比 student 更支持刚采样的 token，就增强这个动作，反之削弱。第二种 top-$k$ 路线还读取 teacher 概率最高的 $k$ 个候选，默认 $k=64$，以更多分布信息降低采样估计的方差。原文式 (5) 在截断 KL 外另加 $q(v)-\pi_\theta(v)$ 修正项，使 top-$k$ 上 student 与 teacher 相等时仍是目标极小点；直接截断标准 KL 则未必如此。这个细节是算法正确性的一部分，而不只是节省传输的技巧。

**为什么共享起点有用？** 领域 teacher 和 student 都从同一个 SFT checkpoint 来，初始分布相对接近。教师再经各自 RL 向领域能力移动；与任意外部 teacher 相比，student 访问的前缀更可能仍在 teacher 有意义的监督范围内。论文 §4.4.2 用 same-origin 对照分析这一点；“同源更稳”是该设置下的实验解释，不能推论任意 teacher 都应来自同一个 checkpoint。

**核心源码与方法对照**

本文 arXiv 页面没有给出与这套实验一一对应的作者官方复现仓库；文中的 [open-r1](https://github.com/huggingface/open-r1) 是被引用的相关实现，不应当作 MOPD 代码。因此这里沿原文 §3.1–3.3 解释流水线与目标，没有虚构函数名或声称运行了训练。若之后发布官方代码，最值得核对的是：领域路由在 rollout 后还是 teacher 服务内执行、teacher/student top-$k$ 词表对齐方式、训练中的 token mask 与序列归一化，以及并行 teacher 的服务吞吐。

原文 §3.3 给出了虽未开源但可检查的执行顺序：每条 student rollout 一结束，就异步向对应领域的独立 teacher prefill 服务发请求；teacher 返回逐 token log-prob 或 top-$k$ 信息，训练器再计算优势或分布损失。这样 teacher 前向能与其他样本的生成重叠。作者称部署中额外墙钟开销几乎不可测，但并未在主文给出完整 GPU-hours 账本；**延迟被重叠不等于计算免费**。实现时尤其要保证 teacher 对同一文本前缀评分、EOS/无效位置 mask 一致，以及返回的分布对应采样时那一版 student 轨迹。

## 3. 实验设置与算力

原文 §4.1 的主比较从 **Qwen3-30B-A3B-Base** 出发，所有基线和 MOPD 使用同一个跨域 SFT 起点。数学用 AIME25/AIME26，指令遵循用 IFBench/IFEval，软件工程用 SWE-bench Verified。基线分别是 Mix-RL、Cascade RL、Off-Policy Finetune、两种 Param-Merge；另用 MiMo-V2-Flash 验证更大模型上的完整流水线。SWE-bench 是带软件工程环境的任务，不等同于简单补全函数；训练时 teacher RL 的环境成本也不能只按模型参数估算。

读指标前要知道：AIME 是竞赛数学，原文对每题采样 32 次并报告平均正确率 avg@32；IFBench/IFEval 检查回答是否满足指令约束，每题评估一次；SWE-bench Verified 以真实仓库问题及测试判断软件修复，每题也评估一次。五个 benchmark 不能简单加总成一个“通用能力”；作者将它们先归入数学、指令、软件三个领域再做归一化。全部评测采样温度为 1.0，未启用 top-$p$ 或 top-$k$ 截断（附录 B）。

| 项目 | 原文可核信息与解释 |

归一化分数对每个领域把 SFT student 设为 0、该领域 RL teacher 设为 1，再做领域平均。这样能比较“各域能力差距填上多少”，但也依赖每个领域所选 benchmark 与 teacher 的 headroom；不能解释为一个与任务无关的统一能力值。

附录 A/B 给出数据来源、batch、rollout、长度及评测解码，但没有完整的 GPU/TPU 型号、卡数、训练时间、所有随机种子或原始训练日志。没有这些项目，就无法复算阶段一 SFT、三个领域 RL、第三阶段蒸馏加起来的总训练成本。报告区分原文“teacher prefill 延迟可与采样重叠”的系统观察，以及尚不能验证的总算力节省。

## 4. 结果与图表解读

![Table 2 · Qwen3-30B-A3B 多领域能力融合主结果](./assets/papers/paper-opd-2606-30406/table-2-pdf.png)

**Table 2 解读。** Qwen3-30B-A3B 的归一化分数为 MOPD **0.9373**、Mix-RL **0.8818**、Off-Policy Finetune **0.8241**、Cascade RL **0.7752**、Task Arithmetic **0.8574**。MOPD 比这里最强的其他融合基线 Mix-RL 高 **0.0555**；这是三领域相对 headroom 指标差，不是 AIME 或 SWE-bench 的“提高 5.55 个百分点”。单项仍有取舍：MOPD 的 AIME25 为 51.46，低于该域 RL teacher 的 54.79；AIME26 为 65.31，高于 teacher 的 63.65。IFBench 77.89 低于 teacher 的 78.40，SWE 50.40 低于 teacher 的 51.20。表能支持“总体较好地保留专长”，不能支持“各项能力无损”。[原表：PDF 第 7 页](https://arxiv.org/pdf/2606.30406v1#page=7)。

![Figure 2 · 指令、数学与 SWE 三领域的训练动态](./assets/papers/paper-opd-2606-30406/figure-2-pdf.png)

**Figure 2 解读。** 横轴是各领域已消耗的训练样本数（千），纵轴是该领域准确率；三块子图依次是指令、数学、SWE，紫线是单域 specialist 的参照，不是第三阶段的额外 student。IF 图中 MOPD 较早上升，Mix-RL 更慢；SWE 中不同方法曲线波动较大，不能只取某一个训练点判定全程胜负。图支持在这个训练设置下“用较少领域样本接近 teacher”的解释，但横轴并非 GPU 时间，且各路线每个样本的 teacher 前向和环境成本不同，不能直接换算为总算力节省。[原图：PDF 第 7 页](https://arxiv.org/pdf/2606.30406v1#page=7)。

![Table 3 · MiMo-V2-Flash 上的多能力融合与残余退化](./assets/papers/paper-opd-2606-30406/table-3-pdf.png)

**Table 3 解读。** MiMo-V2-Flash 实验更能说明“能力集成”不是每项都严格无损。MOPD 相对各领域 teacher 在 AIME25/HMMT25/LCB 分别高 0.2/1.8/0.6 分，但 IFBench 低 **2.2** 分、SWE-bench Verified 低 **0.8** 分；工具相关的 τ²-Bench/Telecom 也列于同表。这里比较的是同一报告内的模型与指标，不能把不同基准的绝对分数直接平均成通用能力排名。原文 Table 4 的第二轮 teacher→student 演化还说明可以再次进行领域 RL 与融合，但收益并非所有 benchmark 单调上升。[原表：PDF 第 8 页](https://arxiv.org/pdf/2606.30406v1#page=8)。

## 5. 局限、结论与后续阅读

这篇论文最重要的贡献是把“独立做领域 RL”和“单模型承接多域能力”串成一个可执行的后训练流程：共享起点、多域 teacher、学生自己采样、按域稠密监督。当前证据支持它在论文规定的 Qwen3-30B-A3B 三领域比较中优于所列融合基线，并在 MiMo-V2-Flash 上有工业规模示例；它不证明任意 teacher 组合、任意 tokenizer 或任意预算下都有效。

后续验证应固定 teacher 总计算预算与训练 prompt，比较按域硬路由、动态 token 路由和信号归一化；同时逐领域报告遗忘、teacher 调用量和 GPU-hours。[MOPD-Router](#paper=paper-opd-2609-30837)与 [DN-MOPD](#paper=paper-opd-2609-35347)正好分别把“选谁”和“信号尺度”拆开。来源：[arXiv v1 正文与附录 A/B](https://arxiv.org/abs/2606.30406v1)，本文核读 Figure 1/2、Table 2/3 和训练细节；没有执行复现。已用固定版本 PDF 原图核对插图，裁剪页码、范围和 SHA256 见 `assets/papers/paper-opd-2606-30406/figures.json`。
