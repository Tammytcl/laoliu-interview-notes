## 1. 背景与已有工作

**阅读定位。**《Towards Understanding On-Policy Distillation through the Lens of Test-Time Scaling》放在 OPD 文献链条中，核心问题不是把一个最终答案从 teacher 复制给 student，而是 student 先在当前策略下生成前缀，teacher 再对这些真实会遇到的状态提供监督。这样可减少离线 teacher 轨迹与 student 部署轨迹的分布偏移，但代价是每轮都要生成、teacher 前向和更新，稳定性、概率空间以及评测预算会互相耦合。

本报告把贡献拆成“问题假设—训练信号—工程实现—证据边界”四层。与 SFT 相比，OPD 监督的是 student rollout；与 RL 相比，它通常不必为每题设计外部 reward，而以 teacher 分布或似然差为反馈；与离线 KD 相比，它能在 student 的错误前缀上纠偏。若 teacher 与 student tokenizer、终止符或能力分布不同，还会额外出现概率不可比、长度偏差或局部信号失真的问题。阅读原文时应先确认论文解决的是哪一层，而不是把所有提升笼统归因于“on-policy”。

这套定位也限定了结论：论文中的 benchmark 增益只能支持给定模型、数据和预算下的机制，不能自动外推到任意规模或任务。尤其需要区分 teacher 更强带来的上限、训练 token 更多带来的算力收益，以及新目标函数本身的贡献。后文保留原论文图表证据与负结果，避免只摘摘要中的最佳数字。

面试中常听到“OPD 提高 pass@1”，但实际推理系统可能会采 8、64 甚至上千个候选，再用 verifier 选。这时单次正确率提高，不保证高预算 pass@K 仍提高：蒸馏若把概率集中在原本就容易解的题上，困难题的偶然成功路径可能被抹掉。本文把问题从**单次质量**转到**测试时采样预算曲线**。

一个题的单次成功率为 $p_x$ 时，独立采 $K$ 次至少成功一次的理想式是 $1-(1-p_x)^K$；数据集 pass@K 是各题这一量的均值。两个模型平均 pass@1 的差，不决定每题 $p_x$ 变化如何分布，所以大 $K$ 下可能反转。这是读全文前必须先懂的数学背景。

## 2. 方法与实现机制

![Table 1：研究采用的三组 OPD 设置](./assets/papers/paper-opd-2608-11829/study-settings-pdf.png)

本文是经验分析而非新算法，使用原表展示研究设计：三组 teacher/student 配置构成后续 test-time scaling 比较的基础。表格由 LaTeX 排版，故裁取 PDF 中这一小块，不以结果曲线冒充方法流程。比较每条曲线时都应回到相应模型对，而不是将不同模型的最高值直接排名。 图表源：[arXiv 2608.11829v1 PDF，第 3 页](https://arxiv.org/pdf/2608.11829v1#page=3)，仅裁图表区域。

作为比较基线，student 轨迹记为 $y\sim\pi_\theta(\cdot\mid x)$，teacher 为 $\pi_T$。常见 token 级 on-policy 蒸馏的示意目标写成下式；它不代表本文所有变体都采用同一散度或同一梯度估计器：

$$\mathcal{L}(\theta)=\mathbb{E}_{x,\,y\sim\pi_\theta(\cdot\mid x)}\!\left[\sum_t D\!\left(\pi_\theta(\cdot\mid x,y_{<t}),\pi_T(\cdot\mid x,y_{<t})\right)\right].$$

这里最关键的是期望分布也依赖 student：参数更新后，下一批前缀会变，teacher 监督的位置随之移动。若实现先缓存 teacher 自己生成的固定答案，目标就退化为 off-policy；若 teacher 和 student 看到的模板、温度或 EOS 不一致，似然差还会混入协议偏差。散度是 reverse KL、forward KL、JS、回归损失还是经过门控的组合，会决定 mode-seeking、coverage 和梯度尺度，不能只用“KD loss”概括。

复现时建议把一次训练 step 拆成六个可审计阶段：固定 prompt 与模板；student 生成并记录 token/终止原因；teacher 在完全相同前缀上前向；构造论文定义的 token 掩码、权重或对齐；只对 student 反向；记录有效 token 数与梯度范数。对于跨 tokenizer 方法，还必须保存共同 byte/event 单元到两侧 token 的映射；对于自蒸馏，必须冻结 teacher 快照或明确同步频率；对于 verifier/多 teacher 方法，则要记录门控拒绝率与各 teacher 被选比例。

公式实现有三个常见陷阱。第一，用 batch mean 代替有效 token mean 会让长回答获得更大权重；第二，teacher logits 的温度缩放、top-k 截断和重新归一化次序会改变目标；第三，在本应 stop-gradient 的权重上反传，会引入论文没有的高方差项。最小测试应构造一个两 token 词表，手算每项概率、mask 与梯度方向，再做端到端小 batch 对照。本报告把论文原图与已有仓库线索分开：即使仓库存在，也应固定提交并逐项核对默认参数，不能用最新分支替代论文版本。

方法是否有效不能只看最终 accuracy。还要检查训练中 teacher-student KL、student 熵、回答长度、EOS 概率、有效更新 token 比例、梯度范数和 rollout 成功率。若主指标上涨却长度暴增、熵坍缩或 OOD 明显下降，应视为带代价的权衡。原文方法图、后续配置说明和结果图表共同构成可追溯链条。

论文先推导题目级正确率变化对不同 $K$ 的影响，再实测 OPD 前后各题的曲线。若少数已容易题提高很多、一些原本很难但可偶尔做对的题降到零，低 $K$ 可能受益而高 $K$ 受损。文章进一步讨论按预算选择 teacher：要优化实际部署的 $K$，不能只以 teacher 的 pass@1 排序。

Figure 中的每条线对应固定 student/teacher 与 benchmark，不是训练步数曲线；横轴采样预算增长时，还需记住独立采样公式是假设模型不因候选数量改变策略。作者官方 [opd-test-time-scaling 仓库](https://github.com/Geraldxm/opd-test-time-scaling)已确认；本轮未逐函数核读。复现应固定解码温度、verifier 和每题最大采样数。

## 3. 实验设置与算力

![Table 2：OPD 变体训练配置](./assets/papers/paper-opd-2608-11829/table-2-config-pdf.png)

原表分列 global/PPO mini-batch、prompt/response 长度、学习率和 checkpoint 或预算控制。斜杠两侧具有不同含义，不能把它们合并成一个 batch 或长度数字。所有实验共享的温度和 top-p 在表外正文交代；对照不同变体时还需要确认其 released configuration 的差异。 图表源：[arXiv 2608.11829v1 PDF，第 13 页](https://arxiv.org/pdf/2608.11829v1#page=13)，仅裁图表区域。

| 复现维度 | 必须记录的字段 | 为什么重要 |
|---|---|---|
| 模型协议 | checkpoint、tokenizer、chat template、EOS | 决定概率是否可比 |
| 采样预算 | prompts、每题 rollout、温度、top-p、最大长度 | 决定探索与成本 |
| 优化 | loss、学习率、batch、累积、step/epoch | 决定梯度尺度 |
| teacher 成本 | 前向 token、logits/top-k、缓存策略 | OPD 的主要额外开销 |
| 评测 | seed、样本数、Avg@k/Pass@k、judge | 防止口径漂移 |
| 算力 | GPU 型号、卡数、GPU-hours | 判断收益是否等预算 |

公平对照至少要固定 student 起点、训练 prompt、生成 token 总量和评测解码。只固定 step 不够：多 rollout、更长回答和更大 teacher 会显著增加计算。若论文没有完整 GPU 型号、卡数或 GPU-hours，本报告将其视作披露缺口；复现时需单独测量 student 生成、teacher 前向、反向传播和评测四部分 wall-clock。已有正文中的论文专属模型、数据和参数说明应与这张账本结合阅读。

统计上应报告多个随机种子或置信区间，并把 checkpoint 选择放在独立验证集。Pass@k 会随 k 和采样温度上涨，不能与 greedy accuracy 混写；LLM judge 需要固定版本与 prompt；verifier 过滤后的有效样本量也要报告。只有配置、预算和指标都对齐，结果差异才可归因于方法。

实验跨数学、代码、事实问答三领域，**8 组** student/teacher、**12 个 benchmark**。数学训练 DAPO-Math-17K、评测 AMC23/AIME24–26；代码训练 CodeR1-12K、评测 HumanEval+、MBPP+、LiveCodeBench v5/v6；事实题训练 NQ/HotpotQA、评测 HotpotQA、TriviaQA、PopQA、2WikiMultiHopQA。Table 3 的全局 prompt batch 数数学/事实 **64**、代码 **128**，最大 prompt/response 长度随域变化。

训练成本和测试时成本都重要：高 $K$ 的 pass@K 评测本身需要大量生成，不能用一次采样精度表替代。论文没有一个适用于全部实验的 GPU-hours 总数；采样上限和硬件吞吐需逐实验记录。

## 4. 结果与图表解读

![主要数学基准上的 pass@k](./assets/papers/paper-opd-2608-11829/passk-source.png)

原图按模型配置和 benchmark 分面展示 pass@k，而不是一张主结果表。观察小 k 与大 k 的相对排序，能检验 OPD 是否主要把概率集中到已有可解问题。大 k 下的交叉或饱和是本文结论的重要边界，但有限采样仍不能精确测出模型真正的全部能力上限。 图源：[arXiv 2608.11829v1 LaTeX 源码](https://arxiv.org/src/2608.11829v1)，原始文件 `figures/pass_at_k_primary_benchmarks_model_rows.png`。

![相同模型配置下的 avg@k](./assets/papers/paper-opd-2608-11829/avgk-source.png)

原图报告平均采样正确率，与上面的至少一次成功概率 pass@k 是不同指标。OPD 可以提高平均成功频率，却不一定扩大高 k 时的可解题集合；把两图合读才能区分采样效率改善和覆盖面扩展。这里保留作者完整面板和坐标，不挑选单个最有利的模型或任务。 图源：[arXiv 2608.11829v1 LaTeX 源码](https://arxiv.org/src/2608.11829v1)，原始文件 `figures/avg_at_k_primary_benchmarks_model_rows.png`。

结果证据应形成闭环：主表回答“最终是否更好”，曲线回答“训练是否更稳/更快”，消融回答“哪个部件起作用”，成本表回答“是否等预算”。任一环节缺失都降低因果强度。尤其在 OPD 中，更强 teacher、更长 rollout 或更多 teacher 前向本身就可能提高分数，因此必须同时报告 teacher 调用量和生成 token。只引用平均值还会掩盖 AIME 这类小样本基准的高方差。

实践决策不能只追最高 accuracy。若目标是单次在线回答，应重视 Pass@1/Avg@k 与延迟；若允许 test-time scaling，才关注较大 k 的 Pass@k；若模型需要持续更新，还要测 OOD、遗忘和连续多轮蒸馏。本文据原图与正文只给“这些实验设置下”的结论，不把局部结果外推成普遍规律。

**Table 2** 是最直观的反转证据。Qwen3-1.7B-Base←Qwen3-4B-Base-GRPO 的数学组，pass@1 **10.6→18.4**，但满预算 pass@K **73.3→65.4**，下降 **7.9 个百分点**。另一个 Qwen3-1.7B←Qwen3-4B-RL-Code 组，pass@1 **36.6→42.7**，满预算 **52.3→70.1**；即不同领域/教师的曲线形状并不统一。

Figure 的分题正确率分组解释为何总体曲线会交叉：低准确率题的微小退化在高 $K$ 下可能变得重要，已高准确率题再提升则边际变小。读表时注意满预算 $K$ 各组不同，不能把“70.1 比 65.4 高”理解为代码 student 比数学 student 强。

## 5. 局限、结论与后续阅读

共同局限可以归为四类：teacher 可能在 student 前缀上失准；on-policy 反复调用 teacher，训练成本高于离线 SFT；tokenizer/EOS/template 不一致会把协议差异伪装成知识差异；多数论文集中在数学或可验证任务，开放式对话、代码和长期遗忘证据仍少。Towards Understanding On-Policy Distillation through the Lens of Test-Time Scaling 应在这些边界内理解，不能因一个平均分提升就宣称普遍优于所有蒸馏或 RL 方法。

后续复现优先做等生成 token、等 teacher 前向和等 GPU-hours 三套对照，并报告长度、熵、KL、有效 token、梯度范数、OOD 与失败案例。阅读路线可依次对照普通 off-policy KD、标准 RKL OPD、本文专属改进以及同主题的稳定化/跨 tokenizer 工作。最终判断标准是“收益来自哪里、付出什么成本、在何种条件下失效”，而不是只复述摘要。

这个结果是部署策略提醒：如果系统只给一次回答，pass@1 可作为核心指标；如果靠多次采样搜索，必须画完整 pass@K 曲线并按题目分层分析。论文的独立采样推导不覆盖高度相关的多代理采样、verifier 错误或动态温度策略；这些系统还需单独测。
