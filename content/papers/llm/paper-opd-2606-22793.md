## 1. 背景与已有工作

**阅读定位。**《A Formula-Driven Survey and Research Agenda for On-Policy Distillation》放在 OPD 文献链条中，核心问题不是把一个最终答案从 teacher 复制给 student，而是 student 先在当前策略下生成前缀，teacher 再对这些真实会遇到的状态提供监督。这样可减少离线 teacher 轨迹与 student 部署轨迹的分布偏移，但代价是每轮都要生成、teacher 前向和更新，稳定性、概率空间以及评测预算会互相耦合。

本报告把贡献拆成“问题假设—训练信号—工程实现—证据边界”四层。与 SFT 相比，OPD 监督的是 student rollout；与 RL 相比，它通常不必为每题设计外部 reward，而以 teacher 分布或似然差为反馈；与离线 KD 相比，它能在 student 的错误前缀上纠偏。若 teacher 与 student tokenizer、终止符或能力分布不同，还会额外出现概率不可比、长度偏差或局部信号失真的问题。阅读原文时应先确认论文解决的是哪一层，而不是把所有提升笼统归因于“on-policy”。

这套定位也限定了结论：论文中的 benchmark 增益只能支持给定模型、数据和预算下的机制，不能自动外推到任意规模或任务。尤其需要区分 teacher 更强带来的上限、训练 token 更多带来的算力收益，以及新目标函数本身的贡献。后文保留原论文图表证据与负结果，避免只摘摘要中的最佳数字。

OPD 方法快速增多后，单看名称或 benchmark 容易把不同目标混在一起。这篇公式驱动的综述从变量出发：student 访问状态 $d_{\pi}$、teacher 信号 $q$、监督动作/词表事件、散度或优势、损失权重、训练系统。它想回答“一个方法到底改了哪一项”，而不只是列论文摘要。

与 [另一篇广谱综述](#paper=paper-opd-2604-00626)相比，本篇更重视**反馈可行动性**：teacher 在 student 当前状态给出的建议是否既可靠、又落在 student 能学到的局部支持上。这能把 teacher 过强、特殊 token 不匹配、off-policy 混入、长轨迹末端噪声等现象放进同一个诊断框架。

## 2. 方法与实现机制

![公式变量驱动的 OPD 更新路径](./assets/papers/paper-opd-2606-22793/method-source.png)

原图把直接散度最小化和 policy-gradient 风格的更新放在同一变量框架中，对照状态来源、教师反馈、信用分配和梯度路由。它是综述的分类工具，不是作者提出并训练的新算法。使用这张图整理文献时，应按实际估计器和梯度流归类，而不是仅按论文是否使用 KL 来命名。 图源：[arXiv 2606.22793v1 LaTeX 源码](https://arxiv.org/src/2606.22793v1)，原始文件 `figures/fig_update_pipeline.png`。

作为比较基线，student 轨迹记为 $y\sim\pi_\theta(\cdot\mid x)$，teacher 为 $\pi_T$。常见 token 级 on-policy 蒸馏的示意目标写成下式；它不代表本文所有变体都采用同一散度或同一梯度估计器：

$$\mathcal{L}(\theta)=\mathbb{E}_{x,\,y\sim\pi_\theta(\cdot\mid x)}\!\left[\sum_t D\!\left(\pi_\theta(\cdot\mid x,y_{<t}),\pi_T(\cdot\mid x,y_{<t})\right)\right].$$

这里最关键的是期望分布也依赖 student：参数更新后，下一批前缀会变，teacher 监督的位置随之移动。若实现先缓存 teacher 自己生成的固定答案，目标就退化为 off-policy；若 teacher 和 student 看到的模板、温度或 EOS 不一致，似然差还会混入协议偏差。散度是 reverse KL、forward KL、JS、回归损失还是经过门控的组合，会决定 mode-seeking、coverage 和梯度尺度，不能只用“KD loss”概括。

复现时建议把一次训练 step 拆成六个可审计阶段：固定 prompt 与模板；student 生成并记录 token/终止原因；teacher 在完全相同前缀上前向；构造论文定义的 token 掩码、权重或对齐；只对 student 反向；记录有效 token 数与梯度范数。对于跨 tokenizer 方法，还必须保存共同 byte/event 单元到两侧 token 的映射；对于自蒸馏，必须冻结 teacher 快照或明确同步频率；对于 verifier/多 teacher 方法，则要记录门控拒绝率与各 teacher 被选比例。

公式实现有三个常见陷阱。第一，用 batch mean 代替有效 token mean 会让长回答获得更大权重；第二，teacher logits 的温度缩放、top-k 截断和重新归一化次序会改变目标；第三，在本应 stop-gradient 的权重上反传，会引入论文没有的高方差项。最小测试应构造一个两 token 词表，手算每项概率、mask 与梯度方向，再做端到端小 batch 对照。作者未开源与该论文一一对应的官方代码仓库，因此这里只能依据固定版论文、公式和附录核读，不能声称函数级实现已验证。

方法是否有效不能只看最终 accuracy。还要检查训练中 teacher-student KL、student 熵、回答长度、EOS 概率、有效更新 token 比例、梯度范数和 rollout 成功率。若主指标上涨却长度暴增、熵坍缩或 OOD 明显下降，应视为带代价的权衡。原文方法图、后续配置说明和结果图表共同构成可追溯链条。

文章先把 OPD 视作对 student 轨迹的行为干预，再用公式区分序列级与 token 级、teacher 全分布与 sampled-token、时间信用分配与词表概率路由。教师在 student 某个前缀给高概率的候选，只有在 student 有一定局部概率质量、训练目标能作用到那里且 teacher 判断可靠时，才更可能转化为有效更新；单独的 teacher confidence 不够。

第 6 节把失败机制按公式变量映射：student-induced states 可能超出 teacher 可靠纠错区；tokenizer/EOS 使“同一 token 事件”失真；大 log-ratio 或长序列产生不稳定权重；多教师信号可能互相干扰。第 7 节给针对性稳定化思路，如控制异常值、调整监督位置、报告诊断量。它是文献综合与分析框架，不是提供一个可直接运行的新训练器。

## 3. 实验设置与算力

![Table 9：未来 OPD 工作的最低报告清单](./assets/papers/paper-opd-2606-22793/table-9-reporting-pdf.png)

原表是综述提出的 reporting checklist，不是某次实验的超参数账本。它要求同时交代状态、反馈、更新与资源条件，用来审计其他论文的可复现性。本报告引用它说明证据披露要求，不将这些建议误写成综述作者完成的训练实验，也不把未披露项自行补成默认值。 图表源：[arXiv 2606.22793v1 PDF，第 28 页](https://arxiv.org/pdf/2606.22793v1#page=28)，仅裁图表区域。

| 复现维度 | 必须记录的字段 | 为什么重要 |
|---|---|---|
| 模型协议 | checkpoint、tokenizer、chat template、EOS | 决定概率是否可比 |
| 采样预算 | prompts、每题 rollout、温度、top-p、最大长度 | 决定探索与成本 |
| 优化 | loss、学习率、batch、累积、step/epoch | 决定梯度尺度 |
| teacher 成本 | 前向 token、logits/top-k、缓存策略 | OPD 的主要额外开销 |
| 评测 | seed、样本数、Avg@k/Pass@k、judge | 防止口径漂移 |
| 算力 | GPU 型号、卡数、GPU-hours | 判断收益是否等预算 |

公平对照至少要固定 student 起点、训练 prompt、生成 token 总量和评测解码。只固定 step 不够：多 rollout、更长回答和更大 teacher 会显著增加计算。若论文没有完整 GPU 型号、卡数或 GPU-hours，本报告将其视作披露缺口；复现时需单独测量 student 生成、teacher 前向、反向传播和评测四部分 wall-clock。已有正文中的论文专属模型、数据和参数说明应与这张账本结合阅读。

统计上应报告多个随机种子或置信区间，并把 checkpoint 选择放在独立验证集。Pass@k 会随 k 和采样温度上涨，不能与 greedy accuracy 混写；LLM judge 需要固定版本与 prompt；verifier 过滤后的有效样本量也要报告。只有配置、预算和指标都对齐，结果差异才可归因于方法。

本论文为综述，没有单一 student/teacher checkpoint、训练数据、benchmark 或 GPU 配置。Table 1 明确区分核心 OPD 证据、工业系统报告、混合方法与相邻工作；这比把所有带“distillation”字样的结果合并成一张排行榜更可靠。表中的“证据等级”是作者分类，读者仍应回原论文核实实验协议。

把它用作报告模板时，可以固定记录：student 前缀由谁采样；teacher 可以提供什么信号；师生 tokenizer 是否一致；损失作用在 sampled token、top-$k$ 还是 full vocab；训练与 teacher 推理各耗多少。综述不报告 GPU-hours，不应为它填一个模型算力值。

## 4. 结果与图表解读

![Table 5：可审计的 OPD 更新路线](./assets/papers/paper-opd-2606-22793/table-5-routes-pdf.png)

原表比较目标如何被估计、求导和门控，是综述综合出的机制证据，而非 benchmark 排行榜。相同的 KL 方向仍可能对应不同的采样、归一化和 stop-gradient 位置；因此只复制一个损失名称不足以复现方法。表中的路线应与具体论文实现和适用条件一一核对。 图表源：[arXiv 2606.22793v1 PDF，第 12 页](https://arxiv.org/pdf/2606.22793v1#page=12)，仅裁图表区域。

![时间信用与词表梯度路由的两个轴](./assets/papers/paper-opd-2606-22793/credit-routing-source.png)

原图把时间轴上的 credit assignment 与词表维度的梯度路由区分开：前者决定后续回报如何影响当前动作，后者决定哪些候选 token 受到更新。这是综述的机制综合，不是一个实验曲线。两条轴可以组合，不能把 return-to-go、即时反馈和 top-k 支持混作同一层面的替代方案。 图源：[arXiv 2606.22793v1 LaTeX 源码](https://arxiv.org/src/2606.22793v1)，原始文件 `figures/fig_credit_routing.png`。

结果证据应形成闭环：主表回答“最终是否更好”，曲线回答“训练是否更稳/更快”，消融回答“哪个部件起作用”，成本表回答“是否等预算”。任一环节缺失都降低因果强度。尤其在 OPD 中，更强 teacher、更长 rollout 或更多 teacher 前向本身就可能提高分数，因此必须同时报告 teacher 调用量和生成 token。只引用平均值还会掩盖 AIME 这类小样本基准的高方差。

实践决策不能只追最高 accuracy。若目标是单次在线回答，应重视 Pass@1/Avg@k 与延迟；若允许 test-time scaling，才关注较大 k 的 Pass@k；若模型需要持续更新，还要测 OOD、遗忘和连续多轮蒸馏。本文据原图与正文只给“这些实验设置下”的结论，不把局部结果外推成普遍规律。

文中的故障表可作为核读 checklist，但不是每种故障都经过同预算因果消融。例如 teacher 不可靠与 student 支持不足可能同时出现；观察到训练失败，单凭一张梯度热图无法确定根因。对本专题的实际价值是让读者为每篇新论文先写**变量变化、对照对象与反事实**，再写精度提升。

文章对跨 tokenizer 结果的讨论应与 [SimCT](#paper=paper-opd-2605-07711)、[BPM](#paper=paper-opd-2607-22334)、[ESCD](#paper=paper-opd-2609-34738)原文对照；这些 2026 工作的版本和结果会继续更新，综述中的一次性归纳不能代替最新版表格。

## 5. 局限、结论与后续阅读

共同局限可以归为四类：teacher 可能在 student 前缀上失准；on-policy 反复调用 teacher，训练成本高于离线 SFT；tokenizer/EOS/template 不一致会把协议差异伪装成知识差异；多数论文集中在数学或可验证任务，开放式对话、代码和长期遗忘证据仍少。A Formula-Driven Survey and Research Agenda for On-Policy Distillation 应在这些边界内理解，不能因一个平均分提升就宣称普遍优于所有蒸馏或 RL 方法。

后续复现优先做等生成 token、等 teacher 前向和等 GPU-hours 三套对照，并报告长度、熵、KL、有效 token、梯度范数、OOD 与失败案例。阅读路线可依次对照普通 off-policy KD、标准 RKL OPD、本文专属改进以及同主题的稳定化/跨 tokenizer 工作。最终判断标准是“收益来自哪里、付出什么成本、在何种条件下失效”，而不是只复述摘要。

这个框架适合帮助确定阅读顺序，不等于一篇经过统一实验的结论论文。引用它的分类时，应保留“作者综述判断”和“被引论文实验事实”的层次。若后续扩展本专题，优先记录可行动性相关的可测量值——局部 top-$k$ 重叠、teacher 不确定度、EOS/特殊 token 错配、有效更新 token 比例——再讨论抽象的“teacher 更强”。
