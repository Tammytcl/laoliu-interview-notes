## 1. 背景与已有工作

逐 token 的 sampled-token OPD 把 teacher 与 student 对已采样 token 的 log-prob 差当作优势。它比保存完整词表 logits 省显存，却会在 student/teacher 差距大时产生极端权重：某些 student 偶然采到的 token 被 teacher 赋予很低概率，梯度可能将更新推向不稳定区域。Reopold 研究的是**如何放宽普通 reverse-KL 蒸馏对每个 token 的强制模仿**，让小推理模型既吸收 teacher，又能保留自己的有效轨迹。

这和简单减小学习率不同：减小学习率会整体降低更新，Reopold 则改变了 teacher/student token 差异转为优化信号的方式。与 [TrOPD](#paper=paper-opd-2606-01249) 的 trust-region 约束可以并列阅读，关注两者对极端优势的处理对象。

论文先指出一个容易被忽略的联系：on-policy RKL 的梯度可写成策略梯度，token 奖励是师生 log-likelihood ratio。若这个 ratio 没有 stop-gradient，有限样本下会带来期望为零但方差不为零的额外项；teacher 越强并不保证该噪声越小。实证中标准 RKL 甚至可能把 student 拉到初始化以下，说明“模仿更强 teacher”并非单调安全。

已有 GRPO 等 RL 方法依靠可验证奖励和多条采样，成本高；SFT/off-policy KD 便宜但受静态 teacher 轨迹限制。REOPOLD 试图保留 on-policy 每题少量采样的效率，同时借鉴 RL 中 reward clipping、动态采样和阶段训练来稳定蒸馏。论文覆盖数学、视觉推理与视觉工具使用，目标不仅是某一张数学表，而是验证同一稳定化原则是否跨任务成立。

## 2. 方法与实现机制

论文从 $R_t=\log p_T(y_t\mid h_t)-\log p_S(y_t\mid h_t)$ 出发，沿 student rollout 做 policy-gradient 式优化，并将该差值 stop-gradient，避免同一 student 参数既作为优势又作为被优化概率时引入不稳定的二阶耦合。Reopold 的 relaxed 机制基于师生相对概率对 token 更新进行选择/重加权，核心不是先让 teacher 生成一条新解答；student 前缀仍是监督位置。复现时应从原文 §4 的具体 loss 和附录实现对照，不能把“relaxed”仅理解为一个模糊的 clip。

原文没有给出相应作者官方 GitHub 入口；论文中的 LUFFY 数据链接是训练数据来源，不是 Reopold 代码。这里不声称函数级实现已经核读。

![REOPOLD 方法示意](./assets/papers/paper-opd-2603-11137/figure-2-pdf.png)

student 从 $\pi_\theta$ 采样 $y$，teacher 为同一前缀打分，token ratio 为

$$R_{i,t}(\theta)=\log\frac{\pi_T(o_{i,t}\mid q,o_{i,<t})}{\pi_\theta(o_{i,t}\mid q,o_{i,<t})}.$$

论文证明标准 RKL 与把 $R_{i,t}$ stop-gradient 后的策略梯度在期望上梯度相同：

$$\nabla_\theta\mathcal J_{\rm RKL}=\mathbb E\left[\sum_{i,t}\rho_{i,t}(\theta)R_{i,t}^{\rm sg}(\theta)\nabla_\theta\log\pi_\theta(o_{i,t}\mid q,o_{i,<t})\right].$$

差别在有限 batch 的梯度方差。Figure 3 显示两者 loss 趋势相近，但 stop-gradient 的梯度范数更低、验证分数更稳定。REOPOLD 在此强基线上加入三部分：对极端 teacher 信号做 clipping；按 token 信号选择性更新，让接近零或潜在有害位置跳过；训练前段更依赖 teacher、后段切换到更放松的目标，以免 student 长期被 teacher 的局部偏好锁死。图中绿色、黄色、红色分别对应正、跳过、负向优势，强调不是所有 token 都同等模仿。

超参数 $\lambda$ 控制 clipping，$β$ 是熵/选择百分位，$T_{\rm switch}$ 决定阶段切换。数学 1.5B/7B 分别在 100/50 步切换，视觉任务 20 步，agentic 任务 10 步；这些数值随总步数变化，不能直接搬到更长训练。方法实际价值在于把“何时相信 teacher”显式化，而不是一个神秘的 relaxed 标签。

复现时必须确保 teacher 和 student 打分的是相同 student prefix，ratio 中分母与被更新 policy 对应，并将奖励项 stop-gradient。作者未开源 REOPOLD 代码；原文列出的 Verl、LUFFY 与数据链接只能帮助搭建框架，不能被误写成官方实现。函数级细节应以 v1 附录伪代码、公式和配置表交叉核对。

图中虚线框的 skip token 很关键：放松不是简单把负 advantage 截成零，而是根据当前阶段与分位阈值决定哪些 teacher 差异值得学习。若所有正信号保留、所有负信号删除，student 会产生单向概率膨胀；若先在 batch 维度归一化再做分位筛选，阈值又会随题目难度漂移。复现必须写清筛选是在 token、序列还是 batch 层级完成，以及 padding、EOS 是否进入统计。阶段切换也应绑定实际 optimizer step，而不是数据 epoch，避免梯度累积改变含义。

此外，clipping 后的信号仍要与重要性比率共同解释：前者限制单 token 奖励幅度，后者控制新旧策略偏移。只复现其中一项会得到不同算法。一个可靠单元测试是构造 teacher 高/低概率 token，逐项检查正、负、skip 三类掩码与 stop-gradient 后的解析梯度。

## 3. 实验设置与算力

1.5B 设置使用 DeepSeek-R1-Distill-Qwen-1.5B student 和 SkyWork-OR1-Math-7B teacher；7B 设置使用相应 32B-Preview teacher。训练 prompt 来自约 **45K** 数学题；1.5B 主表比较把训练步数固定 **300**，Figure 1(a) 的样本效率曲线另延长 Reopold 到 600 步。评测 AIME24/25、AMC23、MATH-500、Minerva Math、OlympiadBench，对照 SFT、GRPO 和普通 reverse-KL OPD。

这些数学基准难度与指标口径不同，Table 1 的 Avg 只是论文定义的多项平均；若复现，应分别记录每个 benchmark 的生成温度和采样次数。原文未给出完整可复核的 GPU-hours，不能由 300 步直接比较两种方法的总开销。

![REOPOLD 跨任务超参数](./assets/papers/paper-opd-2603-11137/table-8-pdf.png)

原表显示所有任务都用 $\lambda=0.3$，但 $\beta$ 与切换步随任务变化：agentic 的 $\beta=0.4$、第 10 步切换，比数学更早更强地筛选。这说明方法虽共享框架，却不是一套超参数无调节地跨域迁移；复现应把调参验证集和搜索范围一并披露。

| 设置 | 数学 1.5B / 7B | 视觉 3B / 7B | Agentic 3B |
|---|---|---|---|
| 总步数 $K$ | 300 / 200 | 60 / 60 | 40 |
| 学习率 | $10^{-5}$ / $3\times10^{-6}$ | $5\times10^{-6}$ | $10^{-6}$ |
| clipping $\lambda$ | 0.3 / 0.3 | 0.3 / 0.3 | 0.3 |
| entropy percentile $\beta$ | 0.2 / 0.2 | 0.2 / 0.2 | 0.4 |
| switch step | 100 / 50 | 20 / 20 | 10 |

数学用 Verl，每题采样 8 条、最大响应 8192、温度 1.0，global batch 128、mini-batch 32，AdamW、恒定学习率。全部数学训练在单节点 8×NVIDIA H100 80GB 上完成；1.5B 与 7B 分别约 200 与 312 GPU-hours。视觉任务每题 12 条、最大 2048、batch 128、mini-batch 64、60 iteration，同一 8×H100 节点上 3B/7B 约 20/24 GPU-hours。Agentic 每题 8 条、最大 8192、最多 2 轮，batch 128、mini-batch 64、40 iteration，约 120 GPU-hours。

评测数学时最大输出 32768、温度 0.6、top-p 0.95；视觉也用温度 0.6/top-p 0.95，并以 Gemini-2.0-Flash-001 作 judge；agentic 使用 InfoVQA、TallyQA、VStar8 等数据。硬件披露较完整，但成本比较仍需注意 teacher 前向和 judge API；表中的 GPU-hours是作者设置，不代表其他实现的固定开销。

## 4. 结果与图表解读

**Table 1** 的 1.5B 组中，原 student Avg **44.4**，Reopold **57.1**；另一组相应 Reopold **51.5**，普通 RKL **46.5**。增益较大，但要检查每组 teacher 与训练起点是否一致，不能拿 1.5B 的强 teacher 分数去解释另一组。该表也提示逐项不一定全部领先：后一组的 Minerva Math，Reopold **30.2**，普通 RKL **30.9**，所以结论应落在平均趋势及关键任务而非“全项最优”。

Figure 1(a) 用训练步数展示样本效率；更长训练的 Reopold 曲线不能和只训练 300 步的主表混为一次等预算对照。读取图表要同时看是否出现早期大增益后平台、是否牺牲输出长度与多样性，以及 teacher/student 很接近时放宽信号还是否有益。

![数学推理主结果](./assets/papers/paper-opd-2603-11137/table-1-pdf.png)

原表解读：这张表将两种 teacher 分块，并保留初始 student、GRPO、SFT、RKL 与 REOPOLD，因而能把“更强 teacher”与“更好优化”分开。绿色 $\Delta\%$ 是相对 RKL 的变化，不是相对初始模型；第二块 Minerva 的红色负值尤其重要，它阻止把平均增益误读为所有任务同时改善。

表内还给出 teacher 上限 72.5/70.3，REOPOLD 的 57.1/51.5 仍有明显差距，因此方法是在给定学生容量和训练预算下提高传递效率，并未追平 teacher。第一块 GRPO 平均 47.8、明显低于 SFT/RKL，也不能据此断言 RL 普遍较差：这里的 rollout、奖励与步数只对应论文设定。逐列看 AIME、AMC 与 MATH-500 的一致增益，比只看 AVG 更能支持稳定化结论；Minerva 反例则限定了结论范围。

第一组使用 SkyWork-OR1-Math-7B teacher，1.5B student 的平均分从初始 44.4，经 SFT 51.5、RKL 54.4，到 REOPOLD 57.1；相对 RKL +4.96%。AIME24 37.1→41.6、AIME25 30.6→32.6、Minerva 34.6→38.6。第二组换 SkyWork-OR1-7B teacher，RKL 平均 46.5、REOPOLD 51.5，相对 +10.75%；但 Minerva 30.9→30.2 下降，证明选择性放松不是逐项保证。

![stop-gradient 的训练动力学](./assets/papers/paper-opd-2603-11137/figure-3-pdf.png)

Figure 3 是因果链里很重要的一环：红蓝 loss 近似重合，符合期望梯度等价；stop-gradient 的梯度范数大多约 2–3，标准 RKL 约 3–4 且多次尖峰到 10；AIME24 验证曲线也更高更稳。这不能单独证明完整 REOPOLD，但说明稳定化不是简单靠更低 loss。主表则证明在相同 teacher/student 组合下完整方法的收益。

规模实验还显示 7B student 的 vanilla RKL 在早期已较强的初始化上出现掉点，REOPOLD 曲线更稳定。视觉推理覆盖 Geometry3K、MathVerse、MathVision、MathVista、WeMath 和 HallusionBench；agentic 任务检验多轮工具使用。跨域结果增加了外部有效性，但不同任务使用不同 rollout 数、长度和 judge，因此不宜把所有平均数揉成一个统一“提升百分比”。最可信的陈述是：在作者给定预算与基线上，REOPOLD 多数任务改善了稳定性和最终性能。

## 5. 局限、结论与后续阅读

论文的强证据来自同模型对照下的数学任务；它不覆盖跨 tokenizer，也没有证明放宽约束对代码或长格式指令同样合适。实际应用里应监控极端 log-ratio 的比例、有效更新 token 数和 student 自身正确轨迹是否被错误压制。Reopold 的价值是提醒：teacher 比 student 强，并不代表 teacher 对 student 采到的每个 token 都提供同等可靠的梯度。

局限还包括：选择百分位与切换步数是任务相关超参数；过滤负信号可能保留 student 的错误习惯；Gemini judge 引入外部模型偏差；单节点 H100 结果虽披露成本，但没有相同 wall-clock 的 GRPO 全套对照；作者未发布官方实现，使边界条件复现更困难。跨 tokenizer 场景也不在本文范围，ratio 需要共同 token 空间。

建议复现实验至少记录每步 ratio 分位数、被跳过 token 比例、梯度范数、teacher/student 熵和正确轨迹保留率；分别去掉 stop-gradient、clipping、动态采样和阶段切换，判断收益来自哪一项。预算公平性上应固定 student 生成 token、teacher 打分 token 与总 GPU-hours，而不只固定 step 数。

后续阅读可依次对照标准 RKL/策略梯度等价、TrOPD 的 trust region、EOPD 的熵感知混合，以及跨 tokenizer 的 byte-level 蒸馏。结论是 REOPOLD 用 RL 视角解释并修复 on-policy distillation 的有限样本不稳定，在数学主表、梯度曲线和跨任务实验上形成相互支持的证据；它没有证明 teacher 信号可无条件放松，也不能脱离配置直接迁移。
