## 1. 背景与已有工作

sampled-token OPD 用 $\log p_T(y_t)-\log p_S(y_t)$ 指导 student 更新，但这个系数只反映师生分布差，未直接看整条回答是对是错。一个已经答对的 student token 若 teacher 概率更低，可能收到负向信号；一个错误轨迹中的 token 若 teacher 概率更高，可能被鼓励。OPDVR 用可验证结果纠正这种**概率差与任务正确性不一致**的问题。

它处在 OPD 与 RLVR 的交界：训练状态仍由 student 采样，teacher 仍给细粒度概率，但 verifier 的成功/失败决定哪些 teacher 差值可当作正向/负向监督。与简单把 OPD loss 加 GRPO loss 不同，验证信号进入了 token 级蒸馏权重本身。

## 2. 方法与实现机制

论文把 sampled-token OPD 梯度重写成 policy-gradient 形式，显示 log-ratio 扮演隐式奖励。然后按整条轨迹是否正确分两种情况，使用 ReLU gate 保留与任务 reward 方向一致的 teacher–student 概率差：正确轨迹不应被压低，错误轨迹不应因 teacher 对某个错误 token 更偏好而获得正奖励。这样可保留 teacher 的局部排序信息，同时用 outcome 约束信号符号。

这个 gate 与单纯“正确样本全加、错误样本全减”的 GRPO 不同：若 teacher/student 差异方向与 outcome 冲突，更新可被置零，避免错误指导；若方向一致，幅值仍来自分布差。官方 [OPDVR 仓库](https://github.com/LeapLabTHU/OPDVR)已确认；本轮未逐函数审读，复现需核对 ReLU 作用在何种 detached log-ratio、verifier 错误如何传播。

![Figure 2 · OPDVR 的 verifier-gated token 更新](./assets/papers/paper-opd-2608-24696/figure-method.png)

**图解。** 从左到右依次是 student 采样、teacher log-ratio、verifier 给整条轨迹判正负、ReLU gate 筛掉与结果方向冲突的局部信号，最后再做策略更新。绿色/红色分支分别对应正确/错误轨迹；它不是在 teacher loss 之外简单附加一个 reward。 [图源：arXiv 2608.24696v4](https://arxiv.org/html/2608.24696v4)。

## 3. 实验设置与算力

同架构主设置以 Qwen3-4B non-thinking 为 student，从同模型经 DeepMath GRPO 得到的 RL teacher 蒸馏；数学训练用 DeepMath 难度筛选的约 **57K** 题。论文还测跨架构 student/teacher 组合。评测 AIME24/25、AMC、MATH500、Minerva、OlympiadBench，对照 sampled-token OPD、Top-64 OPD、OPD+GRPO、ExOPD、SG-OPD。

不同方法使用 verifier 或完整 logits 的成本不同；比较质量时可先看同架构 Table 1，比较效率时要把成功判分的调用成本和 teacher top-$k$ 传输也算入。主文未给统一 GPU-hours。

## 4. 结果与图表解读

**Table 1** 同架构六项均值：初始 student **42.0**、RL teacher **50.4**、sampled-token OPD **47.8**、OPD+GRPO **47.7**、OPDVR **49.1**。AIME24 为普通 OPD **34.2**、OPDVR **36.9**；AIME25 **26.0→28.1**。OPDVR 的均值仍低于 teacher，不能写成全面超越；MATH500 上 OPDVR **84.7**，低于普通 OPD **85.5**，显示 gate 不是每个基准都获益。

原文的正确/错误轨迹符号示意是方法图核心。应沿一个具体 sampled token 检查四种情形：轨迹对/错 × teacher 比 student 更高/更低；看哪类被保留，哪类置零。结果表支持这种约束在主设置改善平均，但无法单独证明 verifier 对有歧义答案也可靠。

## 5. 局限、结论与后续阅读

OPDVR 的前提是可验证 reward，数学和代码比开放式写作更适合。若 verifier 有误，符号 gate 会把偏差直接带入 token 更新；若 student 很少答对，正向轨迹稀疏，方法可能需要 cold start。后续可在相同 teacher 前向预算下比较 gate、普通 OPD 和混合 GRPO，并报告 gate 实际过滤的 token 比例。
