## 1. 背景与已有工作

**阅读定位。**《Demystifying On-Policy Distillation: Roles, Pathologies, and Regulations》放在 OPD 文献链条中，核心问题不是把一个最终答案从 teacher 复制给 student，而是 student 先在当前策略下生成前缀，teacher 再对这些真实会遇到的状态提供监督。这样可减少离线 teacher 轨迹与 student 部署轨迹的分布偏移，但代价是每轮都要生成、teacher 前向和更新，稳定性、概率空间以及评测预算会互相耦合。

本报告把贡献拆成“问题假设—训练信号—工程实现—证据边界”四层。与 SFT 相比，OPD 监督的是 student rollout；与 RL 相比，它通常不必为每题设计外部 reward，而以 teacher 分布或似然差为反馈；与离线 KD 相比，它能在 student 的错误前缀上纠偏。若 teacher 与 student tokenizer、终止符或能力分布不同，还会额外出现概率不可比、长度偏差或局部信号失真的问题。阅读原文时应先确认论文解决的是哪一层，而不是把所有提升笼统归因于“on-policy”。

这套定位也限定了结论：论文中的 benchmark 增益只能支持给定模型、数据和预算下的机制，不能自动外推到任意规模或任务。尤其需要区分 teacher 更强带来的上限、训练 token 更多带来的算力收益，以及新目标函数本身的贡献。后文保留原论文图表证据与负结果，避免只摘摘要中的最佳数字。

OPD 常把 teacher–student 差异当作越大越有价值的学习信号，但大差异也可能来自不可信前缀、长度膨胀或高方差 token。此文把问题拆成“OPD 到底传递了什么能力”和“在哪些条件下出现病态”，再设计低额外成本的调节方法。与只换一种散度的论文相比，它更像一次行为诊断：同一 student 的性能、生成长度与梯度分布需一起读。

论文特别提醒，较强 teacher 的每个局部 token 建议并不一定改善 student 的最终解题；对基础 student，缺少 cold start 时直接逐 token 蒸馏还可能放大异常行为。这与 [Rethinking OPD](#paper=paper-opd-2604-13016) 的师生兼容性观点相连。

## 2. 方法与实现机制

![梯度信号调节：硬裁剪与对数压缩](./assets/papers/paper-opd-2607-13399/method-source.png)

原图比较对极端 token 信号进行 hard clipping 或 log-scale compression 的效果。硬裁剪把阈值外不同强度压成同一个值，会丢失排序；对数压缩则保留相对次序。这里展示的是两种信号变换机制，而非它们在所有任务上的胜负；最终效果仍由后面的匹配实验检验。 图源：[arXiv 2607.13399v1 LaTeX 源码](https://arxiv.org/src/2607.13399v1)，原始文件 `figs/signal_regulation_v4.pdf`。

作为比较基线，student 轨迹记为 $y\sim\pi_\theta(\cdot\mid x)$，teacher 为 $\pi_T$。常见 token 级 on-policy 蒸馏的示意目标写成下式；它不代表本文所有变体都采用同一散度或同一梯度估计器：

$$\mathcal{L}(\theta)=\mathbb{E}_{x,\,y\sim\pi_\theta(\cdot\mid x)}\!\left[\sum_t D\!\left(\pi_\theta(\cdot\mid x,y_{<t}),\pi_T(\cdot\mid x,y_{<t})\right)\right].$$

这里最关键的是期望分布也依赖 student：参数更新后，下一批前缀会变，teacher 监督的位置随之移动。若实现先缓存 teacher 自己生成的固定答案，目标就退化为 off-policy；若 teacher 和 student 看到的模板、温度或 EOS 不一致，似然差还会混入协议偏差。散度是 reverse KL、forward KL、JS、回归损失还是经过门控的组合，会决定 mode-seeking、coverage 和梯度尺度，不能只用“KD loss”概括。

复现时建议把一次训练 step 拆成六个可审计阶段：固定 prompt 与模板；student 生成并记录 token/终止原因；teacher 在完全相同前缀上前向；构造论文定义的 token 掩码、权重或对齐；只对 student 反向；记录有效 token 数与梯度范数。对于跨 tokenizer 方法，还必须保存共同 byte/event 单元到两侧 token 的映射；对于自蒸馏，必须冻结 teacher 快照或明确同步频率；对于 verifier/多 teacher 方法，则要记录门控拒绝率与各 teacher 被选比例。

公式实现有三个常见陷阱。第一，用 batch mean 代替有效 token mean 会让长回答获得更大权重；第二，teacher logits 的温度缩放、top-k 截断和重新归一化次序会改变目标；第三，在本应 stop-gradient 的权重上反传，会引入论文没有的高方差项。最小测试应构造一个两 token 词表，手算每项概率、mask 与梯度方向，再做端到端小 batch 对照。作者未开源与该论文一一对应的官方代码仓库，因此这里只能依据固定版论文、公式和附录核读，不能声称函数级实现已验证。

方法是否有效不能只看最终 accuracy。还要检查训练中 teacher-student KL、student 熵、回答长度、EOS 概率、有效更新 token 比例、梯度范数和 rollout 成功率。若主指标上涨却长度暴增、熵坍缩或 OOD 明显下降，应视为带代价的权衡。原文方法图、后续配置说明和结果图表共同构成可追溯链条。

作者先比较不同 teacher 对 Qwen3-1.7B-Base 的 OPD 结果，分析生成长度、token 级误差和训练中性能变化，再在同一循环内引入 Clip 与 Scale 两种规整手段。Clip 限制异常 token 的更新强度，Scale 调整信号总体尺度；它们不要求额外存 full-vocab replay，也不需要重新生成离线 SFT 数据。读 §5 的公式要看它裁剪的是 log-ratio、advantage 还是最终 loss，三者梯度效果不同。

理论和经验分析强调 teacher 信号的**有效性**而非只看 teacher 准确率。若某一轮生成长度大幅增加，表格分数上升也可能是推理预算换来的，必须用相同评测 cap 比较。原文未给出对应的官方代码仓库；这里不推断具体训练器函数。

补充检查还包括 teacher 置信度分桶与异常 token 比例。

## 3. 实验设置与算力



| 配置 / 指标 | 原文设置 | 为什么必须区分 |
|---|---|---|
| 学生起点 | Qwen3-1.7B-Base | 不是经过统一 SFT 的任意 1.7B 模型 |
| 教师 | 多尺度 Qwen3 post-trained 模型 | 包含 4B Instruct、4B/8B/32B 与 4B-GRPO 条件 |
| 训练数据 | Nemotron-Cascade Math | 不与 OPD 文献中常用的 DAPO 自动互换 |
| 模式约束 | 所有 rollout 强制 non-thinking 前缀 | 排除单纯切换 thinking 模式造成的收益 |
| 基线 | GRPO 与 OPD | 信号裁剪和对数压缩在匹配条件中比较 |
| Avg@32 | AMC23、AIME 2024–2026、HMMT25 Feb | 多次采样的平均正确率 |
| Pass@1 | MATH500、Minerva | 主表并非全部列都采用 Avg@32 |
| 能力覆盖分析 | 另外测试至 pass@1024 | 大 k 成功概率不等同于主表平均准确率 |

配置来源：[原文 §2.2–3，第 3 页](https://arxiv.org/pdf/2607.13399v1#page=3)。未在该设置段明确列出的优化参数不自行补成其他 OPD 论文的默认值。

公平对照至少要固定 student 起点、训练 prompt、生成 token 总量和评测解码。只固定 step 不够：多 rollout、更长回答和更大 teacher 会显著增加计算。若论文没有完整 GPU 型号、卡数或 GPU-hours，本报告将其视作披露缺口；复现时需单独测量 student 生成、teacher 前向、反向传播和评测四部分 wall-clock。已有正文中的论文专属模型、数据和参数说明应与这张账本结合阅读。

统计上应报告多个随机种子或置信区间，并把 checkpoint 选择放在独立验证集。Pass@k 会随 k 和采样温度上涨，不能与 greedy accuracy 混写；LLM judge 需要固定版本与 prompt；verifier 过滤后的有效样本量也要报告。只有配置、预算和指标都对齐，结果差异才可归因于方法。

主表使用 Qwen3-1.7B-Base student，多个 Qwen3 teacher，包括 Qwen3-4B-GRPO，评测 MATH500、Minerva、AMC23、AIME24/25/26、HMMT25 等，表头同时出现 pass@1 与 avg@32 类型指标。不同 teacher 分块的“OPD、+Clip、+Scale”只能在块内比较，不能横跨 teacher 视为单一消融。

训练预算与评测生成长度会影响数学结果；论文希望不增加明显算力的规整仍带来收益，但原文没有完整可复核的 GPU-hours。复现时应记录每个方法的真实生成 token、teacher 前向 token 和训练墙钟，而不是只看参数数。

## 4. 结果与图表解读

![Table 1：不同蒸馏方法的数学基准结果](./assets/papers/paper-opd-2607-13399/table-1-results-pdf.png)

原表把不同模型和方法分成多个区块，比较信号调节后的 downstream student 时必须在对应区块中选择同一起点。平均准确率提升不自动表示能力上限扩大；本文同时讨论教师选择和长度利用等病态，因而主表的结论需由 pass@k 曲线与训练诊断共同限定。 图表源：[arXiv 2607.13399v1 PDF，第 7 页](https://arxiv.org/pdf/2607.13399v1#page=7)，仅裁图表区域。

![Qwen3-1.7B-Base 的 pass@k 曲线](./assets/papers/paper-opd-2607-13399/passk-source.png)

原图比较不同训练路线随尝试次数 k 增长的表现。低 k 下 OPD 更容易抽到正确答案，不等于高 k 下能解决更多原本不可解的问题；如果曲线在大 k 处趋近，就更符合概率重分配而非能力边界扩张的解释。所有曲线仍受有限样本估计和采样温度影响。 图源：[arXiv 2607.13399v1 LaTeX 源码](https://arxiv.org/src/2607.13399v1)，原始文件 `figs/passk.png`。

结果证据应形成闭环：主表回答“最终是否更好”，曲线回答“训练是否更稳/更快”，消融回答“哪个部件起作用”，成本表回答“是否等预算”。任一环节缺失都降低因果强度。尤其在 OPD 中，更强 teacher、更长 rollout 或更多 teacher 前向本身就可能提高分数，因此必须同时报告 teacher 调用量和生成 token。只引用平均值还会掩盖 AIME 这类小样本基准的高方差。

实践决策不能只追最高 accuracy。若目标是单次在线回答，应重视 Pass@1/Avg@k 与延迟；若允许 test-time scaling，才关注较大 k 的 Pass@k；若模型需要持续更新，还要测 OOD、遗忘和连续多轮蒸馏。本文据原图与正文只给“这些实验设置下”的结论，不把局部结果外推成普遍规律。

**Table 1** 某个 teacher 分块里，OPD Avg **28.1**，加 Scale **30.4**；另一组 Qwen3-4B-GRPO teacher 下，OPD **26.7**，Clip **28.1**，Scale **26.8**。这说明不同 teacher 的最合适规整方式会变化，不能写成“Scale 总是最强”。表中基础模型与多教师预训练状态也不同，读者应先找分块标题，再抄具体数字。

诊断图把训练中长度、奖励和梯度一起展示：若一个方法只把回答拉长，却没提高独立正确率，就不能称为知识迁移。Clip/Scale 的价值在于给失败 OPD 一个低成本排障方向；它们不能修复 tokenizer 事件错配或 teacher 不会解题。

## 5. 局限、结论与后续阅读

共同局限可以归为四类：teacher 可能在 student 前缀上失准；on-policy 反复调用 teacher，训练成本高于离线 SFT；tokenizer/EOS/template 不一致会把协议差异伪装成知识差异；多数论文集中在数学或可验证任务，开放式对话、代码和长期遗忘证据仍少。Demystifying On-Policy Distillation: Roles, Pathologies, and Regulations 应在这些边界内理解，不能因一个平均分提升就宣称普遍优于所有蒸馏或 RL 方法。

后续复现优先做等生成 token、等 teacher 前向和等 GPU-hours 三套对照，并报告长度、熵、KL、有效 token、梯度范数、OOD 与失败案例。阅读路线可依次对照普通 off-policy KD、标准 RKL OPD、本文专属改进以及同主题的稳定化/跨 tokenizer 工作。最终判断标准是“收益来自哪里、付出什么成本、在何种条件下失效”，而不是只复述摘要。

此文适合在尝试 OPD 前建立监控项：answer accuracy、长度、截断比例、log-ratio 分位数、每次更新有效 token 与 teacher/student overlap。它的实验仍限于所测 teacher/student 与数学任务。后续可以与 [TrOPD](#paper=paper-opd-2606-01249)比较：一个强调异常位置的目标切换，一个强调在现有循环中规整更新信号。
