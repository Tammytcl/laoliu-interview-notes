## 1. 背景与已有工作

OPD 常把 teacher–student 差异当作越大越有价值的学习信号，但大差异也可能来自不可信前缀、长度膨胀或高方差 token。此文把问题拆成“OPD 到底传递了什么能力”和“在哪些条件下出现病态”，再设计低额外成本的调节方法。与只换一种散度的论文相比，它更像一次行为诊断：同一 student 的性能、生成长度与梯度分布需一起读。

论文特别提醒，较强 teacher 的每个局部 token 建议并不一定改善 student 的最终解题；对基础 student，缺少 cold start 时直接逐 token 蒸馏还可能放大异常行为。这与 [Rethinking OPD](#paper=paper-opd-2604-13016) 的师生兼容性观点相连。

## 2. 方法与实现机制

作者先比较不同 teacher 对 Qwen3-1.7B-Base 的 OPD 结果，分析生成长度、token 级误差和训练中性能变化，再在同一循环内引入 Clip 与 Scale 两种规整手段。Clip 限制异常 token 的更新强度，Scale 调整信号总体尺度；它们不要求额外存 full-vocab replay，也不需要重新生成离线 SFT 数据。读 §5 的公式要看它裁剪的是 log-ratio、advantage 还是最终 loss，三者梯度效果不同。

理论和经验分析强调 teacher 信号的**有效性**而非只看 teacher 准确率。若某一轮生成长度大幅增加，表格分数上升也可能是推理预算换来的，必须用相同评测 cap 比较。原文未给出对应的官方代码仓库；这里不推断具体训练器函数。

## 3. 实验设置与算力

主表使用 Qwen3-1.7B-Base student，多个 Qwen3 teacher，包括 Qwen3-4B-GRPO，评测 MATH500、Minerva、AMC23、AIME24/25/26、HMMT25 等，表头同时出现 pass@1 与 avg@32 类型指标。不同 teacher 分块的“OPD、+Clip、+Scale”只能在块内比较，不能横跨 teacher 视为单一消融。

训练预算与评测生成长度会影响数学结果；论文希望不增加明显算力的规整仍带来收益，但原文没有完整可复核的 GPU-hours。复现时应记录每个方法的真实生成 token、teacher 前向 token 和训练墙钟，而不是只看参数数。

## 4. 结果与图表解读

**Table 1** 某个 teacher 分块里，OPD Avg **28.1**，加 Scale **30.4**；另一组 Qwen3-4B-GRPO teacher 下，OPD **26.7**，Clip **28.1**，Scale **26.8**。这说明不同 teacher 的最合适规整方式会变化，不能写成“Scale 总是最强”。表中基础模型与多教师预训练状态也不同，读者应先找分块标题，再抄具体数字。

诊断图把训练中长度、奖励和梯度一起展示：若一个方法只把回答拉长，却没提高独立正确率，就不能称为知识迁移。Clip/Scale 的价值在于给失败 OPD 一个低成本排障方向；它们不能修复 tokenizer 事件错配或 teacher 不会解题。

## 5. 局限、结论与后续阅读

此文适合在尝试 OPD 前建立监控项：answer accuracy、长度、截断比例、log-ratio 分位数、每次更新有效 token 与 teacher/student overlap。它的实验仍限于所测 teacher/student 与数学任务。后续可以与 [TrOPD](#paper=paper-opd-2606-01249)比较：一个强调异常位置的目标切换，一个强调在现有循环中规整更新信号。
