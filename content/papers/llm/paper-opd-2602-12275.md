## 1. 背景与已有工作

工作中常遇到“临时读了一个长上下文，下一次还得重新给模型看”的问题。普通 context distillation 把带上下文 teacher 的输出离线收集，再 SFT 给无上下文 student；如果 student 生成时走到新的前缀，固定答案不一定教得了它。OPCD 把 on-policy 蒸馏用于**把提示词或任务经验写回模型参数**：训练时 teacher 能看见有用上下文 $c$，student 看不见；部署时希望 student 不再携带 $c$ 也能执行。

论文研究的经验可以来自测试时求解轨迹，而不必每次都靠人工标签。它与自我蒸馏的关系是同一个模型在“有上下文/无上下文”两种条件下形成师生差；与 [OPSD](#paper=paper-opd-2601-18734)的“有参考答案/无参考答案”相似，但被压缩的信息类型与测试任务不同。

问题的关键不是“teacher 是否更大”，而是 teacher 和 student 的**可见信息不对称**：teacher 读到经验、系统提示或规则，student 只读任务输入。传统 context distillation 先让 teacher 离线写答案，再拿固定答案训练 student；一旦 student 部署时走到训练答案之外的前缀，监督就失配。OPCD 改用 student 自己的 rollout 作为状态分布，teacher 在这些实际状态上给概率反馈，因此更接近 DAgger 式的分布纠偏。它也不同于 RAG：RAG 保留外部上下文并在每次推理时读取，OPCD 支付一次训练成本，把有限任务分布上的行为压进参数。

适用边界也应先说清：论文验证的是数学经验、文本游戏规则、医疗/安全系统提示的内化，不是无损压缩任意长文档。若上下文包含会频繁更新的事实，参数化记忆会有过期和删除困难；若包含互相冲突的规则，teacher 条件分布本身可能多峰。因而这篇工作的贡献应理解为一种可训练的“context-to-weights”机制及其 on-policy 证据，而非替代检索、缓存或长期记忆系统的通用方案。

## 2. 方法与实现机制

给定 prompt $x$ 与上下文 $c$，student 从 $\pi_\theta(\cdot\mid x)$ 采样回答；teacher 在同一 student 前缀上读取 $c,x$ 并给 next-token 概率。训练目标是沿 student 轨迹缩小 $\pi_\theta(\cdot\mid x)$ 与 $\pi_T(\cdot\mid c,x)$ 的 reverse KL。这样 teacher 的知识并非只在其自己写出的顺畅轨迹上被模仿，而是对 student 当前会遇到的状态提供局部修正。

![OPCD 方法总览](./assets/papers/paper-opd-2602-12275/figure-1-pdf.png)

对 student 轨迹 $y\sim\pi_\theta(\cdot\mid x)$，目标可写为

$$
\mathcal L_{\mathrm{OPCD}}(\theta)=\mathbb E_{x,c}\,\mathbb E_{y\sim\pi_\theta}\left[\sum_t D_{\mathrm{KL}}\!\left(\pi_\theta(\cdot\mid x,y_{<t})\,\|\,\pi_T(\cdot\mid c,x,y_{<t})\right)\right].
$$

这是 reverse KL：期望由 student 的状态分布产生，分布比较也以 student 为左项。实现上每步先由 student 采样完整或分段回答，再把相同前缀送入冻结 teacher；teacher 额外看到 $c$，student 看不到。论文只保留 student 概率最高的 256 个词表项近似 KL，减少完整 logits 的通信与显存，但这也意味着 teacher 在 student 低概率尾部的知识不会进入该步更新。梯度只更新 student，teacher 和经验文本保持冻结。

方法有三类上下文。其一是从多道数学/游戏轨迹抽取并串联的 experiential knowledge；其二是经过验证集打分后筛选出的高质量经验；其三是医疗或安全 system prompt。前两类先由 teacher 解 30 道验证题并总结经验，10 个随机种子形成 300 个候选上下文；数学最多 16384 token、游戏最多 8192 token。筛选版本再用 1000 道数学题或 128 个游戏实例评分，选择最高分上下文。这个流程把“经验产生质量”和“蒸馏算法质量”分开，读结果时也必须区分未筛选与筛选设置。

Figure 1 的实线箭头表达信息流，虚线梯度只回到 student。最容易复现错的地方是让 teacher 自己生成前缀，这会退化为 off-policy context distillation；另一个错误是把上下文也喂给 student，那测到的是 in-context learning 而不是内化。作者未开源对应代码仓库，因此本报告只能依据 v1 公式、附录训练描述和原图核读，不能声称已完成函数级复现。

从优化角度看，student 同时扮演“采集状态的行为策略”和“被更新策略”。每次参数变化后，下一批前缀分布也改变，所以 teacher 监督会自动追到 student 新出现的错误状态；这正是 on-policy 相对固定答案的核心收益。代价是训练中必须反复调用 teacher，且长经验会增大 teacher 的 KV cache。若用旧 rollout 多轮更新，就会逐渐偏离严格 on-policy，复现时应记录 rollout 复用次数。若 teacher 与 student 是同一底座，仍需冻结 teacher 快照，不能让两侧同时更新，否则目标分布会漂移。

这里“压缩 context”不是把原上下文逐字存进权重；成功的定义是有限任务分布上**不再附加该上下文时**，student 的行为接近带上下文 teacher。若上下文含很多互相矛盾的经验或一次性事实，单次更新难保证保真。原文方法图要从两条输入路径读：teacher 有 $c$，student 无 $c$，二者共享 student rollout 的待评估前缀。

论文原文没有给出对应的作者官方仓库；本报告以公式与实验核读，不能声称已读到函数实现。若复现，应核对 teacher 输入中经验的构建时点、student rollout 何时采样、是否把评测题的答案间接泄露到经验里。

## 3. 实验设置与算力

实验含 Qwen3-8B 数学和 Qwen3-1.7B Frozen Lake 两类情境，比较 base、仅把经验放在上下文、传统 context distillation 与 OPCD。数学端把测试时求解轨迹总结为可迁移经验；Frozen Lake 更像序列决策任务，能够检验“经验内化”是否超出纯语言问答。Table 1 还报告 IF-Eval 作为分布外指令遵循检查，不只看主任务。

原文结果有多次运行的不确定性（均值 ± 标准差），不能把 0.5–1 个点的小差距写成稳健显著差异。训练与生成时长由经验长度、student rollout 数及 teacher 前向决定；文中未给出完整跨任务可比的 GPU-hours，应据实际实现另记预算。

![医疗与安全系统提示的评测矩阵](./assets/papers/paper-opd-2602-12275/tables-3-4-pdf.png)

上图不是训练超参数表，而是三种模型、四种方法在医疗和安全两类系统提示上的实验矩阵，它明确了横向比较口径。附录给出的配置账本如下；硬件型号、卡数与总 GPU-hours 原文均未披露，复现报告必须单独补记，不能从 step 数倒推算力。

| 配置项 | experiential knowledge | system prompt |
|---|---:|---:|
| 更新步数 | 50 | 50 |
| batch size | 128 | 128 |
| 学习率搜索 | $\{10^{-6},5\times10^{-6}\}$ | 原文同一训练流程，未单列最优值 |
| KL 近似 | student top-256 token | student top-256 token |
| 最大生成长度 | 数学 16384；游戏每轮 1024、最多 5 轮 | 512 |
| checkpoint | 每 2 步保存，以测试准确率选取 | 每 2 步记录曲线 |
| 评测样本 | 数学 1000；游戏 128 | 500 个测试样本 |

评测同时包含 ID 主任务与 IF-Eval/OOD 任务，这是必要设计：仅看被蒸馏任务上涨，无法排除灾难性遗忘。公平复现还要固定上下文候选、student rollout 随机种子、解码温度和 teacher 调用次数；筛选经验本身用到了额外验证计算，不能把其结果与未筛选基线按相同预算直接比较。

模型选择也会影响统计口径：论文每两步保存 checkpoint，再按测试准确率选取会产生选择偏差，严格复现更适合用独立验证集选 checkpoint、最终测试集只评一次。报告均值与标准差时还应说明随机种子数，并同时给出生成 token 总量；否则 50 个 step 在不同最大长度下并不是相同训练预算。

## 4. 结果与图表解读

**Table 1** 的 Qwen3-8B 数学准确率：base **75.0**，仅 in-context **77.6 ± 1.1**，OPCD **79.7 ± 0.5**；对应 IF-Eval base **81.3**、OPCD **81.7 ± 0.4**。Frozen Lake 的 Qwen3-1.7B base **6.3**，传统 context distillation **22.9 ± 4.0**，OPCD **26.5 ± 6.4**；波动较大，需要结合重复运行读。后者的 IF-Eval 传统方法 **65.1 ± 0.5**、OPCD **67.1 ± 0.5**，提示经验内化并非只能换来主任务提高、其他能力下降。

这组表能支持“在这些设置下，student on-policy 前缀改善经验压缩”；不能据此断言模型会永久记住任意新知识。若把经验换成结构更复杂、与旧知识冲突的内容，测试后续遗忘和反例覆盖会更有价值。

![经验内化的主结果表](./assets/papers/paper-opd-2602-12275/tables-1-2-pdf.png)

Table 1 是未预筛选经验：数学 OPCD 79.7±0.5，高于 off-policy 78.5±0.5；Frozen Lake 26.5±6.4，高于 22.9±4.0，但方差明显较大。Table 2 使用筛选经验后，数学达到 80.9、Frozen Lake 38.3、Sokoban 53.9，均高于对应 context distillation 的 79.5、35.2、51.6。筛选使 Frozen Lake 的绝对提升远大于数学，说明瓶颈部分来自上下文质量，而不全是 loss。IF-Eval 大体不降，但数学筛选设置的 80.8 低于 base 81.3，不能写成所有通用能力都提升。

![ID 学习与 OOD 遗忘曲线](./assets/papers/paper-opd-2602-12275/figure-3-pdf.png)

Figure 3 给出更强的机制证据。蒸馏安全提示时，两种方法的 ID 安全准确率都从约 48 上升；OPCD 最终约 75，off-policy 约 72。右侧医疗 OOD 上，OPCD 围绕初始约 52 小幅波动，off-policy 一度跌至约 45、最终约 48。这支持“on-policy 状态反馈减轻遗忘”，但曲线只有一个任务对，阴影区也提醒方差不可忽略。表 3/4 进一步显示模型依赖性：Llama-3.2-3B 的安全任务 context distillation 83.3 与 OPCD 83.1 接近，而医疗从 71.0 到 76.3，优势并非每格都来自 ID 分数。

作者还比较 teacher-student 与 self-distillation：Sokoban 前者 53.9、后者 18.8；医疗 56.8 对 50.0。它说明强 teacher 仍重要，不能把方法概括为无需外部能力的自举。总体证据链是：同一上下文、同一 student 起点下，on-policy 比固定 teacher 轨迹更好；筛选经验继续增益；OOD 曲线显示较少遗忘。它尚未证明更长时间后的记忆稳定性或跨域上下文的普遍可迁移性。

## 5. 局限、结论与后续阅读

OPCD 的效果依赖 teacher context 质量与任务覆盖，且“测试时收集经验再更新权重”牵涉在线训练成本、数据泄漏和评测口径。下一步可在相同经验集合与相同更新 token 预算下比较：离线 teacher 答案 SFT、只放上下文推理、OPCD；再测新题和完全无关任务。它适合用来学习“上下文知识内化”这条路线，而不是替代检索或长期记忆系统的一般定理。

还有四个现实限制。第一，top-256 截断降低成本却可能漏掉 teacher 想抬升、student 当前极低概率的 token；第二，经验筛选使用额外验证集，若划分不严会形成隐性测试泄漏；第三，50 步后的短期 OOD 保持不等于多轮任务连续写入后的抗遗忘；第四，作者没有报告硬件与完整训练时长，成本优势无法精确量化。系统提示内化还涉及安全治理：把可编辑 prompt 固化到权重后，审计、撤销和按租户隔离都更困难。

建议后续实验报告“每获得 1 个准确率点所需 teacher token/GPU-hour”，并加入随机上下文、冲突上下文、过期事实和连续十次写入测试。阅读路线可先对照普通 context distillation，再读 OPSD 的答案条件化、EOPD 的熵感知目标，最后比较检索增强在可更新性上的优势。结论应保持克制：OPCD 在论文覆盖的任务中有效地把上下文行为蒸馏进 student，并展示比 off-policy 更好的 ID/OOD 权衡；它不是无损知识库，也没有消除在线训练的运维成本。
