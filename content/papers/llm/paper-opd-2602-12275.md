## 1. 背景与已有工作

工作中常遇到“临时读了一个长上下文，下一次还得重新给模型看”的问题。普通 context distillation 把带上下文 teacher 的输出离线收集，再 SFT 给无上下文 student；如果 student 生成时走到新的前缀，固定答案不一定教得了它。OPCD 把 on-policy 蒸馏用于**把提示词或任务经验写回模型参数**：训练时 teacher 能看见有用上下文 $c$，student 看不见；部署时希望 student 不再携带 $c$ 也能执行。

论文研究的经验可以来自测试时求解轨迹，而不必每次都靠人工标签。它与自我蒸馏的关系是同一个模型在“有上下文/无上下文”两种条件下形成师生差；与 [OPSD](#paper=paper-opd-2601-18734)的“有参考答案/无参考答案”相似，但被压缩的信息类型与测试任务不同。

## 2. 方法与实现机制

给定 prompt $x$ 与上下文 $c$，student 从 $\pi_\theta(\cdot\mid x)$ 采样回答；teacher 在同一 student 前缀上读取 $c,x$ 并给 next-token 概率。训练目标是沿 student 轨迹缩小 $\pi_\theta(\cdot\mid x)$ 与 $\pi_T(\cdot\mid c,x)$ 的 reverse KL。这样 teacher 的知识并非只在其自己写出的顺畅轨迹上被模仿，而是对 student 当前会遇到的状态提供局部修正。

这里“压缩 context”不是把原上下文逐字存进权重；成功的定义是有限任务分布上**不再附加该上下文时**，student 的行为接近带上下文 teacher。若上下文含很多互相矛盾的经验或一次性事实，单次更新难保证保真。原文方法图要从两条输入路径读：teacher 有 $c$，student 无 $c$，二者共享 student rollout 的待评估前缀。

论文原文没有给出对应的作者官方仓库；本报告以公式与实验核读，不能声称已读到函数实现。若复现，应核对 teacher 输入中经验的构建时点、student rollout 何时采样、是否把评测题的答案间接泄露到经验里。

## 3. 实验设置与算力

实验含 Qwen3-8B 数学和 Qwen3-1.7B Frozen Lake 两类情境，比较 base、仅把经验放在上下文、传统 context distillation 与 OPCD。数学端把测试时求解轨迹总结为可迁移经验；Frozen Lake 更像序列决策任务，能够检验“经验内化”是否超出纯语言问答。Table 1 还报告 IF-Eval 作为分布外指令遵循检查，不只看主任务。

原文结果有多次运行的不确定性（均值 ± 标准差），不能把 0.5–1 个点的小差距写成稳健显著差异。训练与生成时长由经验长度、student rollout 数及 teacher 前向决定；文中未给出完整跨任务可比的 GPU-hours，应据实际实现另记预算。

## 4. 结果与图表解读

**Table 1** 的 Qwen3-8B 数学准确率：base **75.0**，仅 in-context **77.6 ± 1.1**，OPCD **79.7 ± 0.5**；对应 IF-Eval base **81.3**、OPCD **81.7 ± 0.4**。Frozen Lake 的 Qwen3-1.7B base **6.3**，传统 context distillation **22.9 ± 4.0**，OPCD **26.5 ± 6.4**；波动较大，需要结合重复运行读。后者的 IF-Eval 传统方法 **65.1 ± 0.5**、OPCD **67.1 ± 0.5**，提示经验内化并非只能换来主任务提高、其他能力下降。

这组表能支持“在这些设置下，student on-policy 前缀改善经验压缩”；不能据此断言模型会永久记住任意新知识。若把经验换成结构更复杂、与旧知识冲突的内容，测试后续遗忘和反例覆盖会更有价值。

## 5. 局限、结论与后续阅读

OPCD 的效果依赖 teacher context 质量与任务覆盖，且“测试时收集经验再更新权重”牵涉在线训练成本、数据泄漏和评测口径。下一步可在相同经验集合与相同更新 token 预算下比较：离线 teacher 答案 SFT、只放上下文推理、OPCD；再测新题和完全无关任务。它适合用来学习“上下文知识内化”这条路线，而不是替代检索或长期记忆系统的一般定理。
