## 1. 背景与已有工作

普通 OPD 把 student 每个 sampled token 受到的 teacher 反馈近乎等权汇总。然而 teacher 在某些 token 的偏好可能与最终正确性一致，在另一些 token 上只是风格差异甚至误导。Dr. OPD（OPD Done Right）尝试让**可验证 outcome 帮助判断哪些 teacher 信号更值得跟随**，而不是把 OPD 与 GRPO 两个 loss 粗略相加。

它与 [OPDVR](#paper=paper-opd-2608-24696)都引入可验证 reward，但方法不同：OPDVR 约束 sampled-token 梯度符号，Dr. OPD 学习/构造连续权重，调节每个 teacher 概率信号的重要性。两者都适用于答案可判分的数学/代码场景。

## 2. 方法与实现机制

给定 student 前缀 $s_t$ 与候选 token $v$，普通 OPD 对各位置/候选的 teacher 匹配赋相同权重。Dr. OPD 引入正权重 $w(s_t,v)$，使蒸馏更关注与成功 outcome 相关的局部选择；论文从加权 OPD 的目标推导合适的权重，再用训练 rollout 的 outcome 信息估计 token credit。权重由 $\lambda$ 控制偏离 1 的强度，$\lambda=0$ 回到普通 OPD；实现上对权重限定下界/上界，避免少数 token 独占梯度。

关键区别是 outcome 决定**怎样用 teacher 信号**，而不是只给整条回答再加一个独立奖励。读方法算法时要追踪 reward 信号从 verifier 到 token credit 再到权重的路径，并检查不正确但有局部有价值推理的 token 是否全被丢掉。官方 [Dr-OPD 仓库](https://github.com/zywang0701/Dr-OPD)已确认；本轮未逐函数核读，不能把论文推导等同于实际代码完全复现。

## 3. 实验设置与算力

实验覆盖四种 teacher/student 配置：Qwen3-4B teacher→Qwen3-1.7B/1.7B-Base，以及同尺寸 Qwen3-4B→4B-Base 的 RL teacher 情况。数学评测 AIME24/25、AMC、Minerva、Olympiad，代码 HumanEval+、MBPP+、LCB；对照 OPD、ExOPD、OPD+GRPO、GRPD。附录 Table 4 共同设置学习率 **1×10⁻⁵**、batch **128**、每 prompt **8** 条 rollout、每 step **1024** 条 rollout；Table 5 主方法用 $\lambda=0.4$、权重范围 **0.001–3**。

教师评分、student 多 rollout、verifier 与加权估计都会产生成本。原文没有统一 GPU-hours，若比较“比 GRPO 更高效”，需对齐 rollout 数和 teacher 前向量，不只看 optimizer step。

## 4. 结果与图表解读

跨尺寸主表 Qwen3-1.7B student 的数学五项均分，初始 **22.6**、普通 OPD **25.3**、Dr. OPD **35.0**，而 Qwen3-4B teacher **34.1**；这组实验里 student 略超 teacher。代码三项均分普通 OPD **43.4**、Dr. OPD **48.4**。同尺寸 Qwen3-4B-Instruct 起点的 RL teacher 数学均分 **55.2**，普通 OPD **55.6**、Dr. OPD **57.8**；后者比普通 OPD 高 **2.3** 个百分点。不是所有问题都需要更强 teacher，权重设计可把已有 teacher 信号利用得更好。

论文的超参数消融称所试正 $\lambda$ 均优于 $\lambda=0$，但取最优 $\lambda=0.4$ 仍属于基于这些任务的选择，不能视为通用常数。低能力 1.7B-Base 提供的正确 rollout 更少，数学收益也更小，说明 outcome-credit 依赖 student 有足够成功/失败对照。

## 5. 局限、结论与后续阅读

该方法依赖可靠 verifier，开放式回答的 reward 噪声可能让 token 权重学偏；teacher 本身若对正确答案给错局部概率，重加权也有限。未来复现应报告权重分布、按正确/错误轨迹分层的 teacher 信号利用率、不同初始 student 能力下的收益，并与 [OPDVR](#paper=paper-opd-2608-24696) 做等预算消融。
