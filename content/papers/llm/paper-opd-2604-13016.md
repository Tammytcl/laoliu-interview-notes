## 1. 背景与已有工作

许多 OPD 论文强调“更强的 teacher、更多 teacher logit 应带来更好 student”，这篇机制研究指出两个反例条件：teacher 与 student 的**推理模式**太不一致，或 teacher 对 student 没有超出已有能力的有效新知识。student 在自己前缀上求 teacher 分布只解决了状态覆盖，并没有保证 teacher 建议的 token 处在 student 可以吸收的局部区域。

这篇论文因此关注成功/失败 OPD 更新具体发生在哪些 token 上。它不是提出一个单独 benchmark 更高的新损失函数，而是给出诊断规则与训练配方，帮助判断何时值得蒸馏、何时先缩小师生差距。

## 2. 方法与实现机制

作者用 Qwen3-1.7B-Base student，在相同设置下比较 Qwen3-4B non-thinking 与经 GRPO 训练的 Qwen3-4B-Base teacher，并追踪 token-level 概率质量、师生 top-token 重叠及训练动态。关键观察是：成功运行的更新主要来自**双方都给较高概率的 token**上的逐步对齐；teacher 很确信却 student 几乎不可能采到的 token，并不容易通过当前 sampled-token OPD 被学到。

由此读实用配方时要分清两类干预：一类是改善 student/teacher 的 thinking-pattern 兼容性，例如先给 student 合适的 cold start；另一类是让 teacher 的监督更贴近 student 的局部支持，避免大量更新耗在无法触达的候选上。论文 §5 给出相应策略与对照，但这些策略不能解释成 teacher 越接近 student 就越好：若 teacher 完全没有新知识，兼容性也无法创造增益。

论文的对照围绕 Qwen3 系列数学推理。Table 1 给出训练 Qwen3-4B-Base-GRPO teacher 的配方，Table 2 是 OPD 默认超参数，Table 3 是 cold-start SFT 配方；这些表告诉读者“teacher 预训练/后训练”和“student 先热身”分别消耗预算。将一个 RL teacher 的成本忽略后再说 OPD 便宜，会把研究对象换掉。

原文机制图比较成功与失败的蒸馏运行，重点指标是 top-token 对齐、teacher-student overlap、训练后推理能力，而非只看最终 Accuracy。文中未给出一张统一覆盖所有策略的 GPU-hours 表；复现应记录 teacher 生成/评估 token 和 student 更新 token。

## 4. 结果与图表解读

论文 §3 的关键结论是“更强的 teacher 不保证更好的 student”：teacher 的推理模式差异可能使 student 看到不适合当前能力的局部目标。§4 的 token 轨迹表明成功蒸馏常伴随共享高概率 token 的对齐，而失败运行里 teacher 建议可能远离 student 支持集。这是对机制的观测，不等于“高概率重叠”已被证明是唯一因果变量；student 初始水平与 teacher 训练过程仍会同时影响。

阅读图表时可做三个检查：同一个 student 对两个 teacher 的起始准确率差多少；两位 teacher 在共同 top-$k$ 中有多少可学习概率质量；经过 cold start 后，成功率与该质量是否同时改变。若只摘“teacher 强弱”这一列，容易把兼容性结论读反。

## 5. 局限、结论与后续阅读

适用于评估现有 teacher 池是否值得做 OPD。结论来自所测 Qwen3 思维模式与数学任务，不能自动扩展到不同 tokenizer、图像模型或一个 student 同时接多个领域 teacher。它与 [MOPD-Router](#paper=paper-opd-2609-30837) 的 accessible novelty 相互呼应：后者把“学生可触达的 teacher 差异”显式变成路由指标。
