## 1. 背景与已有工作

**阅读定位。**《Rethinking On-Policy Self-Distillation for Thinking Models》放在 OPD 文献链条中，核心问题不是把一个最终答案从 teacher 复制给 student，而是 student 先在当前策略下生成前缀，teacher 再对这些真实会遇到的状态提供监督。这样可减少离线 teacher 轨迹与 student 部署轨迹的分布偏移，但代价是每轮都要生成、teacher 前向和更新，稳定性、概率空间以及评测预算会互相耦合。

本报告把贡献拆成“问题假设—训练信号—工程实现—证据边界”四层。与 SFT 相比，OPD 监督的是 student rollout；与 RL 相比，它通常不必为每题设计外部 reward，而以 teacher 分布或似然差为反馈；与离线 KD 相比，它能在 student 的错误前缀上纠偏。若 teacher 与 student tokenizer、终止符或能力分布不同，还会额外出现概率不可比、长度偏差或局部信号失真的问题。阅读原文时应先确认论文解决的是哪一层，而不是把所有提升笼统归因于“on-policy”。

这套定位也限定了结论：论文中的 benchmark 增益只能支持给定模型、数据和预算下的机制，不能自动外推到任意规模或任务。尤其需要区分 teacher 更强带来的上限、训练 token 更多带来的算力收益，以及新目标函数本身的贡献。后文保留原论文图表证据与负结果，避免只摘摘要中的最佳数字。

在有参考答案时，同一模型可同时充当 student（看题）和 teacher（看题加答案），沿 student rollout 做自蒸馏。[OPSD](#paper=paper-opd-2601-18734)在某些 Instruct 模型上取得增益，但 thinking 模型已经学会较长的独立搜索；teacher 提前看到答案可能更快收束、较少分叉，反而把 student 的搜索过程压没。这篇论文专门检验“自蒸馏是否保留 thinking 能力”。

研究焦点是**特权上下文**，不是 on-policy 数据本身。若没有区分 teacher 是否看见答案，就容易把 thinking model 的退化归咎于所有 OPD。

## 2. 方法与实现机制

![特权上下文如何翻转自我修正 token 的信用](./assets/papers/paper-opd-2607-05184/method-source.png)

原图对照具体 rollout 片段中有无特权上下文时的 token 信号，关注本来通向正确答案的自我修正语句。它是作者对退化机制的诊断案例，不是完整训练框架；教师看到答案后对探索步骤的偏好可能改变，从而向学生传递错误方向的局部信用。不能仅据一个片段断言全部教师反馈都无效。 图源：[arXiv 2607.05184v1 LaTeX 源码](https://arxiv.org/src/2607.05184v1)，原始文件 `figures/fig_privilege_flips_self_correction.pdf`。

作为比较基线，student 轨迹记为 $y\sim\pi_\theta(\cdot\mid x)$，teacher 为 $\pi_T$。常见 token 级 on-policy 蒸馏的示意目标写成下式；它不代表本文所有变体都采用同一散度或同一梯度估计器：

$$\mathcal{L}(\theta)=\mathbb{E}_{x,\,y\sim\pi_\theta(\cdot\mid x)}\!\left[\sum_t D\!\left(\pi_\theta(\cdot\mid x,y_{<t}),\pi_T(\cdot\mid x,y_{<t})\right)\right].$$

这里最关键的是期望分布也依赖 student：参数更新后，下一批前缀会变，teacher 监督的位置随之移动。若实现先缓存 teacher 自己生成的固定答案，目标就退化为 off-policy；若 teacher 和 student 看到的模板、温度或 EOS 不一致，似然差还会混入协议偏差。散度是 reverse KL、forward KL、JS、回归损失还是经过门控的组合，会决定 mode-seeking、coverage 和梯度尺度，不能只用“KD loss”概括。

复现时建议把一次训练 step 拆成六个可审计阶段：固定 prompt 与模板；student 生成并记录 token/终止原因；teacher 在完全相同前缀上前向；构造论文定义的 token 掩码、权重或对齐；只对 student 反向；记录有效 token 数与梯度范数。对于跨 tokenizer 方法，还必须保存共同 byte/event 单元到两侧 token 的映射；对于自蒸馏，必须冻结 teacher 快照或明确同步频率；对于 verifier/多 teacher 方法，则要记录门控拒绝率与各 teacher 被选比例。

公式实现有三个常见陷阱。第一，用 batch mean 代替有效 token mean 会让长回答获得更大权重；第二，teacher logits 的温度缩放、top-k 截断和重新归一化次序会改变目标；第三，在本应 stop-gradient 的权重上反传，会引入论文没有的高方差项。最小测试应构造一个两 token 词表，手算每项概率、mask 与梯度方向，再做端到端小 batch 对照。本报告把论文原图与已有仓库线索分开：即使仓库存在，也应固定提交并逐项核对默认参数，不能用最新分支替代论文版本。

方法是否有效不能只看最终 accuracy。还要检查训练中 teacher-student KL、student 熵、回答长度、EOS 概率、有效更新 token 比例、梯度范数和 rollout 成功率。若主指标上涨却长度暴增、熵坍缩或 OOD 明显下降，应视为带代价的权衡。原文方法图、后续配置说明和结果图表共同构成可追溯链条。

作者在几组 thinking/instruct 模型上复现 privileged-context OPSD，并记录生成长度、分叉与 benchmark 成绩。随后用同样的 student on-policy 轨迹做不带答案的普通 OPD，或改 teacher 的示例上下文，判断退化来自采样机制还是 teacher 所见信息。因果区分很重要：student 从自己的前缀学习本身可行，但一个“知道答案”的 teacher 可能在关键分叉处偏好直接结束。

论文用 “forking” 描述 reasoning trajectory 在不确定步骤处继续探索不同路线的行为；读机制图要看同一问题的不同上下文如何改变 teacher next-token 概率，尤其 EOS/结束标记附近。作者官方 [Self-Distillation 仓库](https://github.com/idanshen/Self-Distillation)已确认；本轮未逐函数审读，复现需检查 Instruct 与 Thinking 模式的 chat template 是否匹配。

## 3. 实验设置与算力

![Table 9：默认 OPSD 训练超参数](./assets/papers/paper-opd-2607-05184/table-9-config-pdf.png)

原表给出默认训练参数，但不同模型的偏离项另见 Table 10，评测生成协议另见 Table 11。尤其长推理模型的长度上限、rollout 数与温度会影响压缩收益和探索损失；复现本文的预算交叉现象，必须保留训练预算和评测预算的区分，而不能只复制默认学习率。 图表源：[arXiv 2607.05184v1 PDF，第 19 页](https://arxiv.org/pdf/2607.05184v1#page=19)，仅裁图表区域。

| 复现维度 | 必须记录的字段 | 为什么重要 |
|---|---|---|
| 模型协议 | checkpoint、tokenizer、chat template、EOS | 决定概率是否可比 |
| 采样预算 | prompts、每题 rollout、温度、top-p、最大长度 | 决定探索与成本 |
| 优化 | loss、学习率、batch、累积、step/epoch | 决定梯度尺度 |
| teacher 成本 | 前向 token、logits/top-k、缓存策略 | OPD 的主要额外开销 |
| 评测 | seed、样本数、Avg@k/Pass@k、judge | 防止口径漂移 |
| 算力 | GPU 型号、卡数、GPU-hours | 判断收益是否等预算 |

公平对照至少要固定 student 起点、训练 prompt、生成 token 总量和评测解码。只固定 step 不够：多 rollout、更长回答和更大 teacher 会显著增加计算。若论文没有完整 GPU 型号、卡数或 GPU-hours，本报告将其视作披露缺口；复现时需单独测量 student 生成、teacher 前向、反向传播和评测四部分 wall-clock。已有正文中的论文专属模型、数据和参数说明应与这张账本结合阅读。

统计上应报告多个随机种子或置信区间，并把 checkpoint 选择放在独立验证集。Pass@k 会随 k 和采样温度上涨，不能与 greedy accuracy 混写；LLM judge 需要固定版本与 prompt；verifier 过滤后的有效样本量也要报告。只有配置、预算和指标都对齐，结果差异才可归因于方法。

实验包括 Qwen3-1.7B/4B Thinking 与 Qwen3-4B-Instruct-2507、OLMo-7B Instruct/Thinking；数学评测 AIME24/25、HMMT25，并另有 Countdown 与 self-revision 情境。Table 1 与 Table 4 对 Qwen3 thinking 的 Avg 值是 **0–1 比例**，不是百分制。对比时要确保同一模式的 base 与蒸馏后模型放在一起，不能把 Instruct baseline 与 Thinking post-training 混比。

训练时 teacher 的额外上下文会增加前向 token，且长链推理的 response cap 与 EOS 设置会影响效果。主文没有统一可比的 GPU-hours；若复现，应同时报告 student/teacher token、生成长度、截断比例与多样采样预算。

## 4. 结果与图表解读

![Table 1：跨模型族的 thinking-model OPSD 结果](./assets/papers/paper-opd-2607-05184/table-1-results-pdf.png)

原表以带 OpenThoughts 解答的特权上下文训练多个 thinking 模型，再检查不同评测预算下的能力。它显示退化并非只出现在单个模型，但各配置的程度不同。短预算下因回答变短而提高可用性，不代表长预算推理上限同步提高；主表应与预算曲线而非单一平均数字合读。 图表源：[arXiv 2607.05184v1 PDF，第 3 页](https://arxiv.org/pdf/2607.05184v1#page=3)，仅裁图表区域。

![逐模型 pass-rate 与生成预算曲线](./assets/papers/paper-opd-2607-05184/budget-curves-source.png)

原图把横轴改为生成预算，分别比较基础模型与 OPSD 变体，直接检验收益会不会随可用推理长度改变。曲线交叉说明短预算和长预算可能给出相反结论；不能只截取某一个预算宣布方法更好。不同模型子图的分数范围也不同，应在同一子图内做配对比较。 图源：[arXiv 2607.05184v1 LaTeX 源码](https://arxiv.org/src/2607.05184v1)，原始文件 `figures/avg_pass_budget_curves_thinking5_fs_ao.pdf`。

结果证据应形成闭环：主表回答“最终是否更好”，曲线回答“训练是否更稳/更快”，消融回答“哪个部件起作用”，成本表回答“是否等预算”。任一环节缺失都降低因果强度。尤其在 OPD 中，更强 teacher、更长 rollout 或更多 teacher 前向本身就可能提高分数，因此必须同时报告 teacher 调用量和生成 token。只引用平均值还会掩盖 AIME 这类小样本基准的高方差。

实践决策不能只追最高 accuracy。若目标是单次在线回答，应重视 Pass@1/Avg@k 与延迟；若允许 test-time scaling，才关注较大 k 的 Pass@k；若模型需要持续更新，还要测 OOD、遗忘和连续多轮蒸馏。本文据原图与正文只给“这些实验设置下”的结论，不把局部结果外推成普遍规律。

**Table 1** 的 Qwen3-1.7B Thinking，三项平均从 base **0.372** 降到 privileged OPSD **0.308**；4B 从 **0.591** 到 **0.534**。但 **Table 4** 说明问题更细：1.7B 的普通 OPD 为 **0.392**，高于 base，而 privileged OPSD 仍是 **0.308**；换成 gold demo 的 OPD **0.350**。这个对照支持“答案条件改变 teacher 信号”比“on-policy 本身有害”更准确。

Countdown 设置中 Instruct 模型受益更明显：Qwen3-4B-Instruct 平均 **0.527→0.559**，OLMo-7B-Instruct **0.474→0.494**；对应 Thinking 模型一个略降、一个微升，不能把“thinking 必然下降”说成定律。Figure 的推理分叉/长度分析提供机制线索，但仍要与独立测试分数互证。

## 5. 局限、结论与后续阅读

共同局限可以归为四类：teacher 可能在 student 前缀上失准；on-policy 反复调用 teacher，训练成本高于离线 SFT；tokenizer/EOS/template 不一致会把协议差异伪装成知识差异；多数论文集中在数学或可验证任务，开放式对话、代码和长期遗忘证据仍少。Rethinking On-Policy Self-Distillation for Thinking Models 应在这些边界内理解，不能因一个平均分提升就宣称普遍优于所有蒸馏或 RL 方法。

后续复现优先做等生成 token、等 teacher 前向和等 GPU-hours 三套对照，并报告长度、熵、KL、有效 token、梯度范数、OOD 与失败案例。阅读路线可依次对照普通 off-policy KD、标准 RKL OPD、本文专属改进以及同主题的稳定化/跨 tokenizer 工作。最终判断标准是“收益来自哪里、付出什么成本、在何种条件下失效”，而不是只复述摘要。

该论文纠正了“同模型知道更多就能教得更好”的直觉。它对 long-chain thinking 模型的反例很强，但不同任务、teacher prompt 与训练步数会改变方向。准备复现或迁移时，先做无特权 OPD 对照，再试加入答案/示例；同时报告 pass@1、pass@k、推理长度和正确分支覆盖，不只追一个平均分。
