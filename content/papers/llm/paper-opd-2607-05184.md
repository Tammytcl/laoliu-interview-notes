## 1. 背景与已有工作

在有参考答案时，同一模型可同时充当 student（看题）和 teacher（看题加答案），沿 student rollout 做自蒸馏。[OPSD](#paper=paper-opd-2601-18734)在某些 Instruct 模型上取得增益，但 thinking 模型已经学会较长的独立搜索；teacher 提前看到答案可能更快收束、较少分叉，反而把 student 的搜索过程压没。这篇论文专门检验“自蒸馏是否保留 thinking 能力”。

研究焦点是**特权上下文**，不是 on-policy 数据本身。若没有区分 teacher 是否看见答案，就容易把 thinking model 的退化归咎于所有 OPD。

## 2. 方法与实现机制

作者在几组 thinking/instruct 模型上复现 privileged-context OPSD，并记录生成长度、分叉与 benchmark 成绩。随后用同样的 student on-policy 轨迹做不带答案的普通 OPD，或改 teacher 的示例上下文，判断退化来自采样机制还是 teacher 所见信息。因果区分很重要：student 从自己的前缀学习本身可行，但一个“知道答案”的 teacher 可能在关键分叉处偏好直接结束。

论文用 “forking” 描述 reasoning trajectory 在不确定步骤处继续探索不同路线的行为；读机制图要看同一问题的不同上下文如何改变 teacher next-token 概率，尤其 EOS/结束标记附近。作者官方 [Self-Distillation 仓库](https://github.com/idanshen/Self-Distillation)已确认；本轮未逐函数审读，复现需检查 Instruct 与 Thinking 模式的 chat template 是否匹配。

## 3. 实验设置与算力

实验包括 Qwen3-1.7B/4B Thinking 与 Qwen3-4B-Instruct-2507、OLMo-7B Instruct/Thinking；数学评测 AIME24/25、HMMT25，并另有 Countdown 与 self-revision 情境。Table 1 与 Table 4 对 Qwen3 thinking 的 Avg 值是 **0–1 比例**，不是百分制。对比时要确保同一模式的 base 与蒸馏后模型放在一起，不能把 Instruct baseline 与 Thinking post-training 混比。

训练时 teacher 的额外上下文会增加前向 token，且长链推理的 response cap 与 EOS 设置会影响效果。主文没有统一可比的 GPU-hours；若复现，应同时报告 student/teacher token、生成长度、截断比例与多样采样预算。

## 4. 结果与图表解读

**Table 1** 的 Qwen3-1.7B Thinking，三项平均从 base **0.372** 降到 privileged OPSD **0.308**；4B 从 **0.591** 到 **0.534**。但 **Table 4** 说明问题更细：1.7B 的普通 OPD 为 **0.392**，高于 base，而 privileged OPSD 仍是 **0.308**；换成 gold demo 的 OPD **0.350**。这个对照支持“答案条件改变 teacher 信号”比“on-policy 本身有害”更准确。

Countdown 设置中 Instruct 模型受益更明显：Qwen3-4B-Instruct 平均 **0.527→0.559**，OLMo-7B-Instruct **0.474→0.494**；对应 Thinking 模型一个略降、一个微升，不能把“thinking 必然下降”说成定律。Figure 的推理分叉/长度分析提供机制线索，但仍要与独立测试分数互证。

## 5. 局限、结论与后续阅读

该论文纠正了“同模型知道更多就能教得更好”的直觉。它对 long-chain thinking 模型的反例很强，但不同任务、teacher prompt 与训练步数会改变方向。准备复现或迁移时，先做无特权 OPD 对照，再试加入答案/示例；同时报告 pass@1、pass@k、推理长度和正确分支覆盖，不只追一个平均分。
