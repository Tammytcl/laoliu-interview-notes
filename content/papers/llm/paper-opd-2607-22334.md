## 1. 背景与已有工作

On-policy distillation（OPD）让 student 先生成轨迹，再让 teacher 在同一前缀上给出逐 token 的稠密监督。teacher 和 student 共用 tokenizer 时，位置与词表坐标天然对齐；换成不同 tokenizer 后，这两个前提同时消失：同一个字符串会被切成不同数量的 token，相同位置编号不再代表同一个文本前缀，teacher 的 token id 也不属于 student 的动作空间。问题因此不是“找几个同名 token”这么简单，而是要把 teacher **完整下一 token 分布的概率质量**转换成 student 真正能执行的下一步分布。

已有跨 tokenizer 方法各自牺牲了一部分信息。只保留词表表面交集会静默丢掉不重合 token 的概率；把两边概率排序后逐名次配对能保留数值，却会把字节含义不同的 token 连在一起；先做文本对齐、再只给 student 已采动作打分，则未必得到覆盖整个 student 词表的目标。BPM（Byte-Prefix Marginalization）提出三个明确约束：目标要对 student 全词表有定义（vocabulary completeness）、映射依据实际 byte 内容（byte-level alignment）、所有 teacher 概率包括无法立即确定 token 的部分都要守恒（mass preservation）。

它与 [Breaking the Tokenizer Barrier](#paper=paper-opd-2606-09456) 的同步 chunk、[SimCT](#paper=paper-opd-2605-07711) 的共同监督单元属于同一问题线，但监督对象不同：BPM 从 teacher 的全词表概率分布出发，问“若 teacher 下一 token 是某个字节串，student 的 greedy tokenizer 会先吐出哪个 token”。后续 [ESCD](#paper=paper-opd-2609-34738)则进一步追问部分 teacher token 已被消费时，多个合法补全是否应该作为集合目标。读本文最重要的判断标准不是示意图能否对齐字符串，而是映射后总质量、停止概率与跨边界路径是否仍然可训练。

## 2. 方法与实现机制

### 从同步边界到 byte-prefix marginal

把一条回答视为同一串 bytes，teacher 切分为 $w^T_1,\ldots,w^T_M$，student 切分为 $w^S_1,\ldots,w^S_N$。两边 token 边界落在相同 byte offset 的位置叫 sync point；只有这里的 teacher 分布 $q_j$ 与 student 分布 $p_i$共享同一文本前缀。对 teacher 候选 token $w$，BPM 在预先构建的 student byte trie 中寻找 bytes 最长且为 $\operatorname{bytes}(w)$ 前缀的 student token：

$$
\phi(w)=\underset{u\in V_S,\;\operatorname{bytes}(u)\preceq\operatorname{bytes}(w)}{\arg\max}\ |\operatorname{bytes}(u)|.
$$

所有映到同一个 $u$ 的 teacher 概率相加；不足以确定任何完整 student token 的质量进入显式 residual 单元 $\varnothing$：

$$
t_i(u)=\sum_{w:\phi(w)=u}q_j(w),\qquad
t_i(\varnothing)=\sum_{w:\phi(w)=\bot}q_j(w).
$$

每个 teacher token 恰好进入一个 student token 或 residual，因此 $\sum_u t_i(u)+t_i(\varnothing)=1$。这比 overlap-only 多保留未重叠质量，也比 rank pairing 多保留 token 身份。$\phi$ 只依赖两套词表，可为 tokenizer pair 预编译；训练时主要是 scatter-add，而不是逐 token 做字符串搜索。

![Figure 2 · BPM 在 byte trie 上守恒地重分配 teacher 概率](./assets/papers/paper-opd-2607-22334/figure-2-pdf.png)

**Figure 2 解读。** 左侧 `unbelievable` 的真实分词展示同一 bytes 被 teacher 与 student 切在不同位置；黑线是共享 sync point。右侧把 `believe/.28`、`belle/.17`、`bells/.09` 等 teacher 候选沿 student trie 映射，`.17 + .09` 聚到 `bell`，无法确定完整 token 的质量进入 $\varnothing$。底部另列 stopping bridge 与 spanning student token，说明正文的单步求和不是全部实现。图中数字只演示概率路由，不是任务成绩。[原图：固定 PDF Figure 2](https://arxiv.org/pdf/2607.22334v1#page=4)。

### teacher token 内部位置与跨 teacher 边界

若 student 在一个 teacher token 内已经生成前缀 $r_{\text{pre}}$，目标应在“teacher token 以该前缀开头”的条件下重新归一化，而不是重新使用边界处的无条件分布。论文用 prefix mass $\pi(r_{\text{pre}})$作分母，把兼容 teacher token 按下一个 student continuation 聚合。相反，若一个 student token 覆盖多个 teacher token，单个 $q_j$不可能直接包含完整 bytes；BPM 沿 teacher 已实现分词路径使用链式概率：

$$
t_i(u)=\left(\prod_{k=j}^{j+m-1}q_k(w^T_k)\right)\pi_{j+m}(r).
$$

它是该 realized path 的概率，因此是完整 byte marginal 的下界；实现把这部分加入 $u$ 并从闭式目标中扣除同量，以维持总质量。论文报告边界内条件化覆盖绝大多数位置，spanning correction 与无法构造目标而跳过的位置合计低于 1%。这项假设依赖 greedy longest-prefix tokenizer；若 tokenizer 有上下文相关正规化或不是 byte-level BPE，不能不加验证地直接套用。

### divergence、空白行与停止符

目标建好后，BPM 用 generalized JSD 连接 forward KL、对称 JSD 与 skew reverse KL：

$$
D_\beta(t\|p)=\beta\,\mathrm{KL}(t\|m_\beta)+(1-\beta)\,\mathrm{KL}(p\|m_\beta),\quad
m_\beta=\beta t+(1-\beta)p.
$$

默认 $\beta=1/2$；主结果最终选在三组 pair 上都更好的 FKL。内容为空格或 tab 的 realized student token 会屏蔽 target row，因为这类位置的概率差更多反映 tokenizer 对缩进深度的切分偏好，论文观察到不屏蔽会让代码缩进塌缩。EOS 没有内容 bytes，不能走普通 trie；作者汇总 teacher/student chat template 与 generation config 的 stop sets，将 teacher 停止质量映到本次回答实际使用的 student stop token。若停止行为已塌缩，还用二元 stopping bridge 和 FKL 提供恢复梯度。

实现证据需要谨慎表述：论文说明训练基于 [slime](https://github.com/THUDM/slime)，teacher sleep–wake 调度参考 [KDFlow](https://github.com/songmzhang/KDFlow)，并发布[项目页](https://bpm-opd.github.io/)、模型与数据；作者**未开源可确认的 BPM 独立训练代码仓库**，因此不能把框架仓库中的通用函数冒称为本文算法实现。复现时至少要单测四类输入：一对一前缀、teacher token 被拆分、student token 跨 teacher 边界、空白/EOS；每类都应验证目标归一化与 realized token 是否落在正确单元。

## 3. 实验设置与算力

三组实验固定 Qwen3.5-2B（thinking mode）为 student，只更换 teacher：Qwen3-32B、GLM-Z1-9B-0414、MiniMax-M2.7。论文用分词 span Jaccard 表示 tokenizer 距离，依次为 0.92、0.87、0.81。teacher 能力和 tokenizer 距离同时变化，所以有效比较单位是**同一 teacher–student pair 内的不同蒸馏方法**，不能把三块最终分数简单解释为 tokenizer 越远收益越大。训练 prompt 共 20K：DAPO-Math 10K（整数答案）与 TACO 10K（可执行测试）各半。

| 项目 | 固定配置 / 口径 |
| --- | --- |
| Student | Qwen3.5-2B，248K vocabulary，thinking mode |
| Teachers | Qwen3-32B；GLM-Z1-9B-0414；MiniMax-M2.7 |
| On-policy 训练 | 2 epochs；batch 256；恒定 LR $5\times10^{-7}$ |
| Rollout | temperature 1.0；top-p 0.95；top-k 20；最长 27,648 tokens |
| BPM 默认 | $\beta=1/2$ JSD；启用 whitespace-row mask；主表另以 FKL 报告最佳 divergence |
| SeqKD | teacher 固定回答；3 epochs；LR $10^{-5}$，不与在线分布目标等价 |
| 评测解码 | temperature 0.6；每题 8 个回答；avg@8 与 pass@8 |
| 数学 | AIME 2026、HMMT 2026、MATH-500；等价表达 verifier |
| 代码 | HumanEval+、LiveCodeBench、TACO test；官方测试沙箱 |
| 硬件 | 每个训练 run 一台 $8\times$ H200 SXM 141GB 节点；少数 arm 为缩短墙钟时间增加同型数据并行节点 |
| 未披露 | 每个 arm 的精确 GPU-hours、能耗与端到端复现成本 |

![Table F.1 · 训练、rollout、评测与硬件配置](./assets/papers/paper-opd-2607-22334/table-f-1-pdf.png)

**Table F.1 解读。** 这张附录表把正文散落的关键变量放在一起，并明确硬件是“一台 8×H200 节点/每 run”，不是含糊的“H200 nodes”。表内默认 divergence 是 JSD，而主结果 Table 1 报三种 divergence 中表现更好的 FKL，二者不矛盾：前者是默认 recipe，后者是主表选择口径。SeqKD 使用不同的离线目标和学习率，不能仅按 epochs 认定等算力。[原表：固定 PDF Table F.1](https://arxiv.org/pdf/2607.22334v1#page=19)。

模型选择按六个 benchmark 平均分选 checkpoint；每题 8 次采样，avg@8 是单次平均成功率，pass@8 是至少一次成功的比例，后者会受采样数影响。论文还使用 paired bootstrap，但没有把所有随机种子训练均值作为主表口径。报告因此能支持“在该 schedule 与三组 teacher pair 下更好”，不能升级为跨所有模型规模与 tokenizer 的普遍结论。

## 4. 结果与图表解读

![Table 1 · 三组 teacher–student pair 的六任务主结果](./assets/papers/paper-opd-2607-22334/table-1-pdf.png)

**Table 1 解读。** BPM 在 Qwen3、GLM、MiniMax 三组的六任务 Avg. 上分别得到 avg@8/pass@8：**39.0/60.9、41.5/59.4、38.7/57.1**。相对每组 strongest baseline 的平均提升分别是 **+3.7/+8.5、+6.6/+5.5、+5.9/+9.1 个百分点**。但逐列并非全胜：例如 Qwen3 pair 的 MATH-500 avg@8 比最强 baseline 低 1.3，HumanEval+ avg@8 低 0.3，LiveCodeBench avg@8 低 3.1；正确结论是总体平均和大量列改善，而不是每个任务都刷新最佳。灰色 teacher 行是上界参照，不是与 student 同尺寸、同推理成本的 baseline。[原表：固定 PDF Table 1](https://arxiv.org/pdf/2607.22334v1#page=7)。

![Table 2 · FKL、JSD、RKL divergence 消融](./assets/papers/paper-opd-2607-22334/table-2-pdf.png)

**Table 2 解读。** 在目标映射相同的条件下，FKL 三组 All avg@8/pass@8 都最高：Qwen3 为 **39.0/60.9**，GLM 为 **41.5/59.4**，MiniMax 为 **38.7/57.1**。JSD/RKL 仍有局部列更好，例如 MiniMax 的 JSD math avg@8 为 43.7，高于 FKL 的 41.9；因此这张表支持“主表用 FKL 的整体选择”，不支持“FKL 在每项指标必胜”。target construction 与 divergence 是两层设计，复现时应分别消融。[原表：固定 PDF Table 2](https://arxiv.org/pdf/2607.22334v1#page=8)。

![Figure 3 · 空白行屏蔽、缩进塌缩与 teacher gap closure](./assets/papers/paper-opd-2607-22334/figure-3-pdf.png)

**Figure 3 解读。** (a–c) 在 GLM-Z1-9B 的 BPM-JSD run 中比较 mask/no-mask：不屏蔽空白行时，后期 code reward 下滑，平均 indentation margin 从约 6.1 降到 4.1，block indentation errors 升至 **84%**；屏蔽后错误维持 **0%**。这不是“JSD 必然失败”，而是 tokenizer-specific whitespace rows 把概率监督变成了缩进偏好。作者还报告 pass rate 可从 49% 跌到 9%。(d) 的 gap closure 只比较各 pair 最佳 BPM arm 与其 strongest baseline，不能把柱高当成 teacher 绝对能力。[原图：固定 PDF Figure 3](https://arxiv.org/pdf/2607.22334v1#page=9)。

三张证据合起来给出完整因果链：Figure 2 说明如何守恒映射；Table 2 排除“只是换了 divergence”的解释；Figure 3 证明看似细小的空白/EOS 处理会直接改变训练稳定性。Table 1 则回答最终任务效果。若只展示 Table 1，会看不到跨 tokenizer 目标是否正确；若只展示方法图，也无法确认它比 overlap/rank baseline 有实际收益。

## 5. 局限、结论与后续阅读

BPM 的核心贡献是把 teacher 的全词表分布投影到 student 可执行动作，并把 residual、跨 teacher 边界、停止符与 whitespace failure mode 明确写进算法。证据覆盖三个 tokenizer 距离不同的 teacher、数学与代码两类任务，也披露了单 run 的 8×H200 节点配置。它没有证明 greedy byte-prefix 是所有 tokenizer 的通用语义对齐；spanning chain 只沿 realized teacher segmentation 给出下界；完整训练代码与每个 arm 的 GPU-hours尚未公开。teacher 能力与 tokenizer 差异也没有正交控制。

实践上，BPM 更像一套概率守恒接口，而不是“找相同 token”的启发式。实现验收应优先检查：映射后的总质量恒为 1、条件前缀分母不退化、spanning correction 不重复计数、stop set 来自实际 chat template、空白行 mask 的覆盖率可观测。随后再在固定 teacher pair 下比较 FKL/JSD/RKL，而不是同时更换目标、schedule 与 teacher。

后续可对照 [ESCD](#paper=paper-opd-2609-34738) 的 completion-set 监督，分析 teacher token 内部位置存在多个合法 student continuation 时，点分配与集合目标的差别；也可与 [SimCT](#paper=paper-opd-2605-07711) 比较“共同监督单元”与“全分布概率路由”的显存、通信和稳定性。来源固定为 [arXiv v1](https://arxiv.org/abs/2607.22334v1)、[项目页](https://bpm-opd.github.io/)及原 PDF 图表；本报告静态核读论文、模型/数据入口和引用框架，没有运行训练复现。
