## 1. 背景与已有工作

跨 tokenizer 蒸馏不止需要找到“相同文本的对齐位置”，还要回答：**teacher 下一 token 分布中的概率质量，应该落到 student 哪些可输出 token 上？** 只监督 teacher/student 词表交集会丢掉不重合 token 的质量；按概率排名配对会把本来表示不同文字的 token 连在一起；把一个 teacher token 强拆成若干 student token 又会面临部分前缀状态。BPM 选择所有 tokenizer 都共享的 bytes 作为共同参照，研究可守恒的概率路由。

这项工作与 [Breaking the Tokenizer Barrier](#paper=paper-opd-2606-09456)的最小同步 chunk、[SimCT](#paper=paper-opd-2605-07711)的共同监督单元同在跨 tokenizer 线。它的特征是从 teacher 完整 next-token 分布出发，按 byte-prefix 把质量聚合到 student 词表，而不是只对 student 已采 token 打一个分数。后续 [ESCD](#paper=paper-opd-2609-34738)认为，在部分 teacher token 已被 student 生成之后，多个合法补全可能只应作为集合监督。

## 2. 方法与实现机制

**Byte trie、最长前缀与剩余质量**

把每个 student token 展开为字节串，并把 student 词表组织为 byte trie。对于 teacher 某候选 token 的字节串，沿 trie 走到能够确定的、最长的 student token 前缀，把该 teacher token 的概率质量加到这个 student token。对所有 teacher token 候选重复，就得到定义在 student 词表上的目标分布。若字节还不够确定任何完整 student token，质量进入显式 residual 类；不能把它静默丢掉或分到字节不匹配的词项。

概念上，若映射 $\phi(w)=u$ 表示 teacher token $w$ 的字节前缀选择了 student token $u$，则 student 目标质量为 $t(u)=\sum_{w:\phi(w)=u}q(w)$。这个简式需要和 residual 类、spanning-token correction 一起读；只有在论文说明的 refinement 情形，单步最长前缀形式才直接成立。论文还处理 student token 横跨多个 teacher token 时的校正、teacher/student 边界不同的同步点，以及终止符与空白符的特殊处理。

![Figure 2 · BPM 以 byte trie 聚合 teacher 概率质量](./assets/papers/paper-opd-2607-22334/figure-method.png)

**Figure 2 解读。** 左侧 `unbelievable` 的 teacher 与 student 切分边界不同，显示“词表重叠”和“按排名配对”分别会丢质量或丢语义。右侧上方在 student byte trie 中找前缀；中部把多个 teacher token 的质量汇到同一个 student token 或 residual；底部单列 stopping bridge 与 spanning token。图里示例的 0.28、0.17 等数字只是局部概率路由演示，不是 benchmark 效果。阅读时沿字节箭头核对目标 token 的文本内容，再核对总质量是否保留。[图源](https://arxiv.org/html/2607.22334v1)。

**核心源码与方法对照**

arXiv 主文引用 [slime](https://github.com/THUDM/slime) 与 [KDFlow](https://github.com/songmzhang/KDFlow) 等框架，但本轮没有核实到 BPM 作者发布并明确对应此论文的独立实现仓库。因此这里按 §3 的定义解释 trie、前缀聚合、残差/终止与 spanning correction，不把被引用框架的函数冒称为 BPM 代码。下一步源码核对的关键测试应是：一个 teacher token 拆成数个 student token、反向横跨 teacher 边界、含空白及 EOS 的四类输入，验证输出概率总量和可微目标。

## 3. 实验设置与算力

三组实验固定 **Qwen3.5-2B** student（thinking mode），分别配 Qwen3-32B、GLM-Z1-9B-0414、MiniMax-M2.7 teacher，按 tokenizer 差异逐渐增大设置；不同 teacher 能力也不同，所以只在**同一 teacher–student pair 内**对比方法。训练用 **20K prompt**，数学 DAPO-Math 与代码 TACO 各半，student rollout 温度 **1.0**、最高 **27,648 token**。On-policy 各组训练 **2 epochs**、batch **256**、恒定学习率 **$5\times10^{-7}$**，原文指明使用 **H200 SXM nodes**，但“nodes”没有自动给出本轮可复核的 GPU 卡数或 GPU-hours。

| 项目 | 原文 §4.1 的口径 |
|---|---|
| Student / teacher | Qwen3.5-2B；Qwen3-32B、GLM-Z1-9B、MiniMax-M2.7。 |
| 训练 prompt | DAPO-Math 10K（整数答案）+ TACO 10K（可执行测试）；不能混同评测集。 |
| OPD 设置 | Student 自采轨迹，teacher 以自身 chat template 对同一内容评分；on-policy 各组配相同 schedule/更新预算。 |
| Baselines | ULD、GOLD、SimCT 等跨 tokenizer 对照；SeqKD 为离线序列参考。 |

## 4. 结果与图表解读

**Table 1** 给出三个 teacher pair、六项 benchmark 的 avg@8/pass@8。以 Qwen3-32B → Qwen3.5-2B 为例，student base 六项平均 avg@8 为 **24.7**；BPM 的改进需与同 teacher pair 内的 SimCT、GOLD 和 SeqKD 比。不能把 Qwen3、GLM 与 MiniMax 三组的最终绝对分数直接当作算法排名，因为 teacher 能力本身改变。论文的 **Table 2** 进一步比较 BPM 下 forward KL、JSD、reverse KL，说明 byte routing 建立共同目标后，仍需要为下游任务选择 divergence；三个目标的总体结果并非始终同序。

这篇论文还有一个很实用的失败分析：空白符/终止符处理不当会造成生成塌缩或过早停止，论文以 whitespace-row mask 与 stopping bridge 消融。这说明 cross-tokenizer OPD 的工程细节并非次要实现；它们直接决定哪些动作被监督、哪些动作被误罚。图 2 展示机制，表 1/2 展示任务效果，二者要一起看。

## 5. 局限、结论与后续阅读

BPM 的价值在于把 teacher 概率分布映到 student 可执行的词表，并显式保留残余质量；它不能凭一张映射图保证所有中间 token 状态的监督都唯一。尤其是 teacher 一个 token 的部分字节已被 student 输出时，后续多个 student token 都可能合法完成剩余字节，逐项分配仍是建模选择。[ESCD](#paper=paper-opd-2609-34738)正是在这个位置提出 completion set 目标。
