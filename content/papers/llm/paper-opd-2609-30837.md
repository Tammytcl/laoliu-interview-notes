## 1. 背景与已有工作

多教师 on-policy distillation（MOPD）希望把数学、代码和指令遵循等专长模型合并到一个部署 student。基础做法先给 prompt 一个领域标签，再让匹配 teacher 对整条 student rollout 打分：数学题从第一个 token 到最后一个 token 都只听数学 teacher。这套规则简单，却把两个假设绑定在一起：prompt 标签必须存在且可靠；一个领域标签必须足以决定回答每个局部位置最有价值的监督。现实中的回答往往跨域——数学推理可能调用 Python 验算，最后还要满足 JSON 格式——整段 hard routing 会忽略其他专家在局部阶段的补充信号。

无标签数据使问题更明显。可以先用额外 LLM 分类再执行 Standard MOPD，但这引入分类成本与标签误差；也可以平均所有 teacher，却默认每位专家在每个 token 都同样有用。已有 router 还可能需要单独训练分类器。MOPD-Router 把问题改写成：**student 已访问当前前缀 $h_t$ 时，哪位 teacher 的下一 token 修正更值得进入这一步更新？** 路由器不生成文本、不在推理时运行，也不训练额外网络，而是从 student、teacher 及共享 RL 前 base 的即时分布计算权重。

本文和 [MOPD](#paper=paper-opd-2606-30406) 的区别是改“谁在此位置提供监督”；和 [DN-MOPD](#paper=paper-opd-2609-35347) 的区别是后者保留按领域选 teacher，只归一化不同领域优势的数值尺度。路由与归一化分别处理“信号来源”和“信号音量”，不能互相替代。论文的关键证据也不只是总分：要同时验证逐 token 路由优于 rollout-level 固定权重、跨域 teacher 确实被选中、收益不是单纯来自多做 teacher forward，以及额外训练成本是否可接受。

## 2. 方法与实现机制

### 在 student rollout 上聚合 teacher 优势

student 旧策略 $\pi_{\theta_{old}}$先生成回答。对已采 token $y_t$，teacher $i$ 在同一前缀 $h_t=(x,y_{<t})$上给出 sampled-token OPD 优势：

$$
A_t^{(i)}=\log \pi_{\phi_i}(y_t\mid h_t)-\log \pi_{\theta_{old}}(y_t\mid h_t),\qquad
A_t=\sum_{i=1}^{M}w_{i,t}A_t^{(i)}.
$$

router 只负责非负权重 $w_{i,t}$；actor 仍通过 importance ratio 与 clipped objective 更新。权重随 token 位置变化，teacher 评估的是 student 自己走过的上下文，不是把多位 teacher 各自生成的答案拼接。训练完成后只部署 student。

![Figure 1 · prompt hard routing 与逐 token metric routing](./assets/papers/paper-opd-2609-30837/figure-1-source.png)

图源：[arXiv 2609.30837v2 LaTeX 源码](https://arxiv.org/src/2609.30837v2)，`overview/mopd_router_overview_refined.pdf`。

**Figure 1 解读。** A 区把“整段只选一个 teacher”和“每个 token 的三位 teacher 权重变化”并排；B 区给出训练流：student rollout → 所有 teacher 在相同前缀上算 OPD → metric 生成 token-level weights → 聚合优势 → 更新 student。底部三块不是三个串联模块，而是可替换的路由指标 Entropy、Novelty、ExpertAlign。ExpertAlign 额外需要共享 pre-RL base，用于区分“专家后训练获得的方向”和一般 teacher–student 差异。[原图：固定 PDF Figure 1](https://arxiv.org/pdf/2609.30837v2#page=1)。

### 三类路由信号

**Entropy** 用 teacher 下一 token 分布的负熵做分数，再跨 teacher softmax；低熵 teacher 获得更高权重。它只看 teacher，不看当前 student，因此容易把某位 teacher 天生更尖锐的输出风格错当成专长。论文观察到数学 teacher 的熵长期更低，导致路由偏向它；batch-wise 去偏只带来很小改善。

**Novelty** 同时要求“teacher 和 student 有差异”与“差异落在 student 可触及的局部支持”。令 $S_t^S,S_t^i$为两边 top-$k$ token，交集 $\Omega_{i,t}=S_t^S\cap S_t^i$，则：

$$
a_{i,t}=\sqrt{p_t^S(\Omega_{i,t})p_t^i(\Omega_{i,t})},\qquad
N_{i,t}=1-\exp\!\left[-\frac{\mathrm{JS}(p_t^S|_\Omega,p_t^i|_\Omega)}{\tau_N}\right],\qquad
s^{Nov}_{i,t}=a_{i,t}N_{i,t}.
$$

$a$惩罚双方共同 top-$k$ 上质量很小的情况，$N$衡量交集内的归一化分布差异；空交集分数为 0。强教弱设置中去掉 accessibility，Overall 从 36.70 降到 34.12；同尺寸设置则 NoveltyOnly 反高 0.55，说明“可学习性”阈值与模型差距相关，不是普适常数。

**ExpertAlign** 问 teacher 的当前修正是否沿着它后训练获得的专长方向。所有 teacher 共享一个 pre-RL base，在 student top-$k$ 支持上定义：

$$
\mathbf e_{i,t}=[\log p_t^i(v)-\log p_t^{base}(v)]_{v\in S_t^S},\qquad
\mathbf d_{i,t}=[\log p_t^i(v)-\log p_t^S(v)]_{v\in S_t^S}.
$$

$\mathbf e$是 teacher 相对 base 的 post-training shift，$\mathbf d$是 teacher 此刻想把 student 推向的方向。只有内积大于 $\delta=10^{-6}$的 teacher 被保留，主方法再按正余弦相似度归一化：

$$
c_{i,t}=\max\!\left(\frac{\langle\mathbf e_{i,t},\mathbf d_{i,t}\rangle}{\|\mathbf e_{i,t}\|_2\|\mathbf d_{i,t}\|_2},0\right),\qquad
w_{i,t}=\frac{\mathbb 1[i\in\mathcal E_t]c_{i,t}}{\sum_{j\in\mathcal E_t}c_{j,t}}.
$$

若没有正对齐 teacher，该位置跳过 OPD。该设计把“teacher 与 student 不同”收窄为“不同方向像是 teacher 通过领域 RL 获得的能力”，但它依赖 teacher 共享且可访问的 base；来源不同的 API teacher 未必能计算同样的 $\mathbf e$。

## 3. 实验设置与算力

论文有两个训练数据 regime。无标签混合数据含 30K Nemotron-v3 general chat 与 30K NuminaMath-TIR 数学/代码执行 prompt；Standard/Open-MOPD 需要 DeepSeek-V4-Flash 额外生成领域标签，而 router 直接忽略标签。有标签集含 DeepMath 25K、Eurus-RL-Code 25K、HiR-16K 16K。teacher pool 是三个同源 Qwen3-4B-Non-Thinking 领域 RL 模型，共享 Qwen3-4B pre-RL base；student 分别是 Qwen3-1.7B（strong-to-weak）和 Qwen3-4B（same-size）。

| 项目 | 固定配置 / 口径 |
| --- | --- |
| 训练 | 3 epochs；train/mini-batch 都为 1,024；恒定 LR $10^{-5}$；gradient clip 1.0 |
| OPD objective | clip $\epsilon=0.2$；KL penalty disabled；rollout $n=1$ |
| 长度 | prompt 上限 2,048；response 上限 16,384 |
| 采样 | rollout temperature/top-p = 1.0/1.0；thinking mode disabled |
| Router | Entropy/Novelty temperature 0.1；Novelty top-$k=16$、JS saturation 0.1；ExpertAlign top-$k=16$、margin $10^{-6}$ |
| 数学评测 | AIME24/25、HMMT25 Feb/Nov；Avg@8 |
| 代码评测 | HumanEval+、MBPP+、LiveCodeBench v6；Pass@1 |
| IF 评测 | IFEval、IFBench；每例 5 次采样后的 prompt-level accuracy |
| Overall | 九个 benchmark 指标宏平均，不是统一 pass@1 |
| 成本环境 | same-size labeled 成本分析统一使用 8×NVIDIA H20 |
| 稳健性 | paired bootstrap；same-size labeled 另做 3 个训练 seed |

![Table 6 · MOPD 与 IF teacher 训练超参数](./assets/papers/paper-opd-2609-30837/table-6-pdf.png)

**Table 6 解读。** 上半给出所有 router 与 Standard MOPD 共享的训练 recipe，所以精度差异可主要归因于路由信号；下半是论文自行训练 IF teacher 的 ROLL 配置，不应误当成 student MOPD 参数。response limit 为 16,384，batch 1,024，和早期简略报告中“未披露训练细节”的印象不同。[原表：固定 PDF Table 6](https://arxiv.org/pdf/2609.30837v2#page=13)。

成本表在相同 step budget 与 8×H20 环境下报告 Standard MOPD **692.9 GPU-hours**、ExpertAlign **716.9 GPU-hours**，实测增加 3.5%；按 token 归一化的 end-to-end cost 是 **1.18×**。Entropy/Novelty 因回答更短只有 524.2/539.6 GPU-hours，但 token-normalized 仍为 1.13×/1.09×。这些计时排除初始化、下载、验证与 checkpoint I/O，只能用于论文所述环境的相对比较，不能直接换算云端总账单。

## 4. 结果与图表解读

![Table 1 · 无标签混合训练集上的主结果](./assets/papers/paper-opd-2609-30837/table-1-pdf.png)

**Table 1 解读。** 对 1.7B student，Mean、Standard MOPD、Novelty、ExpertAlign 的 Overall 分别为 **34.49、36.33、36.70、38.58**；对 4B student 分别为 **47.88、48.76、50.30、53.76**。4B ExpertAlign 相对 Standard MOPD 的九列差值全部为正，Overall **+5.00**；相对 Mean 则是 +5.88。1.7B ExpertAlign 也最高，但不是每列最佳，例如 MBPP+ 由 Entropy 得 59.52、LCB-v6 由 Novelty 得 20.00。Standard MOPD 在“无标签”表中依赖外部 LLM 生成标签，不是无额外信息的纯基线。[原表：固定 PDF Table 1](https://arxiv.org/pdf/2609.30837v2#page=6)。

![Table 3 · ExpertAlign 正对齐筛选与余弦加权消融](./assets/papers/paper-opd-2609-30837/table-3-pdf.png)

**Table 3 解读。** ExpertAlign-Uniform 只保留正对齐 gate、对保留 teacher 均匀平均；Cosine 再用对齐强度加权。无标签 1.7B/4B 的 Overall 从 **35.71/50.42** 升到 **38.58/53.76**；有标签则从 **38.57/52.91** 升到 **40.19/54.58**。因此收益不只是“删掉负对齐 teacher”，余弦幅度也提供稳定增益。表中有标签结果还说明，即使真实领域标签存在，逐 token ExpertAlign 仍不必使用它。[原表：固定 PDF Table 3](https://arxiv.org/pdf/2609.30837v2#page=8)。

![Figure 2 · 跨域 teacher 路由质量与回答阶段变化](./assets/papers/paper-opd-2609-30837/figure-2-source.png)

图源：[arXiv 2609.30837v2 LaTeX 源码](https://arxiv.org/src/2609.30837v2)，`figures/final_cross_domain_routing.pdf`。

**Figure 2 解读。** 左侧按 prompt domain 归一化：math prompt 只有 37.4% 路由给 math teacher，其余 62.6% 来自 code/IF；code 与 IF 行的 off-domain 合计也都超过 50%。这不是说领域 teacher 无用，而是 token 级融合在每条回答内大量调用补充专家。右侧单个 1.7B rollout 中，math 权重在数值推理阶段上升，code 在 Python verification 附近增加，IF 在 JSON formatting 阶段形成峰值；阶段边界是作者为解释手工标注，不能当作自动 segmentation 准确率。[原图：固定 PDF Figure 2](https://arxiv.org/pdf/2609.30837v2#page=9)。

论文进一步把 full-pool ExpertAlign 与两个控制变量比较：限制只能用领域内 teacher 时，1.7B/4B Overall 比 full pool 低 **2.40/2.75**；把 token 分数在整条 response 上平均、形成固定 teacher mixture 时，又比 token-level 低 **3.62/1.97**。所以“更多 teacher”和“更细粒度路由”都有独立贡献。paired bootstrap 与三 seed 结果支持总体方向，但 teacher 都来自同一 Qwen3 base，这一控制同时也是外推限制。

## 5. 局限、结论与后续阅读

MOPD-Router 的贡献是把多教师选择从 prompt 级标签移动到 student 已访问的每个 token，并给出从 teacher-only 置信度到 student-conditioned 差异、再到 specialization-aligned 修正的清晰阶梯。它在无标签与有标签、1.7B 与 4B 两个设置中都让 ExpertAlign 得到最高 Overall，也用 full-pool/response-level 消融证明跨域与 token 粒度不是装饰性组件。训练后仍只部署 student。

边界同样明确：三位 teacher 同源、同 tokenizer、同尺寸，并共享可访问的 pre-RL base；跨 tokenizer、多架构或黑盒 teacher 不能直接计算相同 ExpertAlign。top-$k=16$忽略长尾分布，正余弦会把所有 teacher 都不对齐的位置跳过；teacher 数量增加仍带来前向、通信与显存压力。Overall 混合 Avg@8、Pass@1 与 prompt accuracy，方便汇总但不代表一个统一概率指标。成本数字也只覆盖同尺寸有标签环境。

复现时应先锁定 teacher pool、prompt mixture、rollout 长度和 MOPD objective，只替换 $w_{i,t}$；同时记录每位 teacher 的权重直方图、空 gate 比例、response length、token-normalized cost 与领域梯度贡献，避免路由退化为恒选单一 teacher。随后可把本文“选谁”与 [DN-MOPD](#paper=paper-opd-2609-35347) 的“校准多大”组合成二维实验，检验路由和尺度归一化是否互补。
