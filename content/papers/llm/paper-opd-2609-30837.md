## 1. 背景与已有工作

多教师 OPD 想把分别擅长数学、代码与指令遵循的 RL 模型融合为一个学生。基础的 [MOPD](#paper=paper-opd-2606-30406)要求每条训练 prompt 带领域标签：数学题交给数学 teacher，整条回答都由它评分。这在领域清楚、标签可靠时容易执行，却忽略一个事实：一道数学题的某些 token 可能是代码、格式或一般语言表达，领域标签不一定代表每个生成位置最好的 teacher。若 prompt 没有标签，还需先分类；简单平均多个 teacher 则会把有用与无用信号同等对待。

MOPD-Router 问的是**student 已经写到某个前缀时，谁的下一 token 判断最值得学？** 它保留 student 自己采样的 on-policy 轨迹，在每个 token 上比较全部 teacher 的分布，再将 teacher 信号加权。与需要训练额外 router 模型的方法不同，这里的三个路由指标直接由当时可见的 logits 计算。也要区分它和 [DN-MOPD](#paper=paper-opd-2609-35347)：前者改“选谁”，后者保留按领域选 teacher，只调节各领域信号尺度。

## 2. 方法与源码对照

student 对 prompt $x$ 生成 $y$；在位置 $t$，每位 teacher 都读取同一个 student 前缀 $h_t=(x,y_{<t})$。采样 token 的单 teacher 优势可理解为 $A_t^{(i)}=\log p_i(y_t\mid h_t)-\log p_S(y_t\mid h_t)$；router 形成 $A_t=\sum_i w_{i,t}A_t^{(i)}$，再放入带 importance ratio 与 clipping 的 policy-gradient 更新。权重 $w_{i,t}$ 随前缀变化；它并没有把几个 teacher 的最终答案拼起来，也不在部署时运行 teacher。

论文比较三种独立的信号。**Entropy** 偏向下一 token 更确定的 teacher，但低熵可能只是该 teacher 的整体风格，无法说明它能纠正当前 student。**Novelty** 在 student 与 teacher 的 top-$k$ 候选交集中比较概率分布的差异，并乘以交集概率质量：既要有新信息，也要在 student 有机会学到的局部支持上。**ExpertAlign** 进一步使用 teacher 与共同 RL 前 base 的变化方向，识别由领域训练产生且与学生更新相符的专长；因此它不等于“哪个 teacher 置信度最高”。论文用 Figure 1 将固定路由、均值与按 token 路由并列；图中的每个小格是同一生成前缀上的不同 teacher 权重。

![Figure 1 · 固定领域路由与逐 token 专家路由的差别](./assets/papers/paper-opd-2609-30837/figure-method.png)

作者仓库在固定版本中把分布计算拆成可核对的函数。[`topk_log_probs_from_logits`](https://github.com/TURLEing/MOPD-Router/blob/557833652c5bce289142260d9c877b7ca756521c/verl/verl/utils/teacher_routing.py#L14)对完整词表 logits 分块求精确 top-$k$ 与 log-prob，避免一次性持有所有位置的额外中间张量；[`accessible_novelty_from_topk`](https://github.com/TURLEing/MOPD-Router/blob/557833652c5bce289142260d9c877b7ca756521c/verl/verl/utils/teacher_routing.py#L43)求共同 token、双方交集质量与归一化差异。`verl` 的 actor/worker 再把多个 teacher 的分数写入 sampled-token 优势。这里的“可访问”专指**局部 top-$k$ 支持交集**，不是 teacher API 的可访问性；只看这个函数也无法代表整个分布路由训练已经跑通。

## 3. 实验设置与算力

论文测试两种数据情境。无领域标签混合集由 **30K Nemotron-v3 聊天 prompt + 30K NuminaMath-TIR 数学 prompt** 组成；有标签集由 **25K DeepMath + 25K Eurus-RL-Code + 16K HiR-16K** 组成。教师池为三个同源 Qwen3-4B-Non-Thinking 领域 RL 模型；学生分别是 Qwen3-1.7B（强教弱）和 Qwen3-4B（同尺寸）。比较 Standard MOPD、Open-MOPD、均值、Entropy、Novelty、ExpertAlign；无标签情境中的固定路由基线先由额外模型推断标签，因此需注意标签生成本身的成本。

评测覆盖数学 AIME24/25、HMMT25 Feb/Nov，代码 HumanEval+、MBPP+、LiveCodeBench v6，指令遵循 IFEval 与 IFBench。数学报告 Avg@8，代码 Pass@1，指令任务对每例采样五次并报 prompt-level 准确率；**Overall 是论文定义的九项均值，不是统一的 pass@1**。各路由方法在同一个 teacher 池、rollout 配置和优化预算下比较，这使路由消融更有解释力。静态核读的主文没有完整可复核的 GPU 型号、卡数与 GPU-hours；新增所有 teacher 前向与 top-$k$ 分数有训练成本，不能从精度表推出性价比。

## 4. 结果与图表解读

在无标签集的 **Table 1**，1.7B student 的 Overall：均值 **34.49**、Standard MOPD **36.33**、Novelty **36.70**、ExpertAlign **38.58**；4B student 的 Standard MOPD **48.76**，ExpertAlign **53.76**。这显示逐 token 信号在所测组合里比固定标签或平均更有效。Entropy 的 1.7B 分数仅 **34.65**，与均值接近；原文分析发现数学 teacher 的熵天然更低，直接按熵选会偏向它。不能把“更确定”当成“更有用”。

有标签集的 **Table 2** 更直接检验“标签已知还需不需要 router”：1.7B 的 Standard MOPD 为 **37.52**，ExpertAlign **40.19**；4B 分别为 **50.63** 与 **54.58**。**Table 4** 移除 token-level routing 后，1.7B Overall 从 **40.19** 降到 **36.57**；禁止跨域 teacher 后降到 **37.79**。因此收益不仅来自换了更多 teacher，还来自对同一轨迹中的局部位置进行不同加权。原文另做 paired bootstrap 和三种随机种子重复，支持方向一致；具体收益仍受教师池与训练集组成限制。

## 5. 局限与阅读结论

这篇论文把多教师融合的“路由粒度”从整条 prompt 推到单个 token，并给出三个逐级更关心 student 状态的指标。若只需低成本部署，训练结束后依然只留 student；但训练阶段需要为每个 teacher 在 student 轨迹上求分布，teacher 数量增多会提高前向、通信及路由计算成本。三个 teacher 同源、同 tokenizer，当前证据不能直接证明跨 tokenizer 多教师池也能用同一 top-$k$ 对齐方式。

复现时要先固定基础 MOPD 的 teacher 池、rollout 和 token 预算，再替换权重函数；同时记录每个 teacher 的路由权重分布和调用开销，以排除某一 teacher 被恒选的伪路由。来源：[arXiv 原文](https://arxiv.org/abs/2609.30837)、[作者代码固定 commit](https://github.com/TURLEing/MOPD-Router/tree/557833652c5bce289142260d9c877b7ca756521c)；已核 §3–4、Figure 1、Table 1–4 及上述源码，未执行训练复现。
