## 1. 背景与已有工作

**研究问题。** On-policy distillation（OPD）让 student 先按自己的当前策略生成回答，再让 teacher 在同一条 student 前缀上给 next-token 分布。与只在 teacher 答案或静态数据上训练相比，这能让 student 学到部署时自己真正会访问的状态。但逐 token 蒸馏暗含一个条件：teacher 与 student 的概率分布必须定义在同一组可比较事件上。Qwen、Phi、Gemma 使用不同 tokenizer 时，这个条件不成立；同一个文本 `happy` 可以被 teacher 切成 `hap|py`，被 student 切成 `ha|pp|y`。token id 相同不代表文本相同，文本相同也不保证 token 边界相同。

最保守的 SimpleOPD 只比较两套词表中字面重合的 token。它不会错误匹配 token，却会丢掉两类信号：一是当前位置双方都能表达、但高概率 teacher token 不在共享词表中的 **vocabulary mismatch**；二是同一文本被切成不同长度序列的 **sequence mismatch**。论文实测 Gemma-2-2B 与 Phi-4-mini 的非一一对齐比例分别为 19.5% 与 11.3%，而 teacher top-100 预测落在共享词表外的比例分别为 14.2% 与 4.6%。因此“只取交集”不是无损对齐，而是主动舍弃 teacher 的一部分偏好。

已有跨 tokenizer 蒸馏接口各自改变比较空间：DSKD 学一个跨模型投影，需要额外参数；ALM 比较 tokenizer 诱导的 chunk likelihood；GOLD 把文本对齐位置的概率合并。它们说明异构词表并非不可蒸馏，但未回答一个更具体的问题：**在不改变 student on-policy 训练范式、也不训练额外映射器的前提下，最细可以比较到什么文本单位？** SimCT 的回答是 minimal aligned unit——两套 tokenizer 都能完整表示、且不能继续拆成更小共同边界的文本片段。

这篇论文的贡献应限定为“监督接口”而不是新的 rollout 算法：student 仍生成轨迹，teacher 仍在相同前缀上给概率，优化仍使用 reverse KL；变化发生在 teacher/student logits 进入散度之前。它与 [Breaking Tokenizer Barrier](#paper=paper-opd-2606-09456) 的异步 credit assignment、[BPM](#paper=paper-opd-2607-22334) 的 byte-prefix 概率质量都处理跨 tokenizer，但构造概率事件的方法不同，不能把三者统称为同一类文本聚合。

## 2. 方法与实现机制

### 从两个词表到共同监督空间

设 teacher、student 词表为 $V_T,V_S$，student 已生成前缀 $x_{<t}$。广义 OPD 不要求原词表相同，只要求存在映射 $\Pi_T,\Pi_S$，把两边分布投到同一监督空间 $U$。SimpleOPD 取 $U=V_T\cap V_S$；SimCT 在此基础上加入当前文本中的最小对齐单元集合 $A$：

$$
U_{\mathrm{SimCT}}=(V_T\cap V_S)\cup A,
\qquad
\mathcal L_{\mathrm{SimCT}}(x_{<t})
=D\!\left(q_S^{\mathrm{SimCT}}(\cdot\mid x_{<t}),q_T^{\mathrm{SimCT}}(\cdot\mid x_{<t})\right).
$$

![Figure 2 · SimCT 的异构词表、最小对齐单元与共同监督空间](./assets/papers/paper-opd-2605-07711/figure-2-pdf.png)

**原图解读。** [Figure 2，固定 PDF 第 4 页](https://arxiv.org/pdf/2605.07711v2#page=4)左侧先把问题画清：同一 student 前缀下，两边 next-token 分布分别位于 $\Delta(V_T)$ 和 $\Delta(V_S)$，不能直接逐维做 KL。中间的 $\Pi_T,\Pi_S$ 不是训练出的语义投影，而是把可比较文本事件重写到 $\Delta(U)$。右侧以 `hap|py` 对 `ha|pp|y` 为例，双方首次重新落到共同字符边界时得到最小单元 `happy`；共享 token 与这类 span 一起组成 $U_{\mathrm{SimCT}}$。图只定义比较接口，并不表示 `happy` 在完整生成分布中具有严格守恒的概率质量。

对于共享的一对一 token $u$，分数就是原 next-token log-prob。对于需要 $k$ 个 token 才实现的共同文本单元 $u$，模型 $M\in\{T,S\}$ 按自回归链计算每一步 log-prob，再取平均：

$$
s_M(u\mid x_{<t})=
\frac{1}{k}\sum_{j=1}^{k}\log p_M(v_j\mid x_{<t},v_{<j}),
\qquad
q_M(u\mid x_{<t})=
\frac{\exp s_M(u\mid x_{<t})}{\sum_{u'\in U_{\mathrm{SimCT}}}\exp s_M(u'\mid x_{<t})}.
$$

这里的 $1/k$ 很重要：直接相乘会天然压低被切成更多 token 的同一文本，平均 log-likelihood 则相当于长度归一化的几何平均。但 $q_M$ 是有限候选集上的**操作性偏好分布**，不是对所有可能续写做严格、质量守恒的边缘化。读到式 (8) 时若把它理解为“原词表概率完整搬运”，会高估方法的概率语义。

### 一个边界扫描例子

实现先把同一 rollout 分别用 teacher/student tokenizer 编码，然后从左到右累计两边 decode 后的文本。若两边累计字符串长度不同，就继续推进较短一侧；当累计文本重新相等时记录一个共同边界。`hap|py` 与 `ha|pp|y` 从空串出发，中途没有共同边界，直到两边都累积为 `happy`，所以整个单词是一个 minimal aligned unit。如果某处双方恰好都产生同一 token，则得到 1:1 单元。这样的贪心扫描给出 jointly tokenizable 的最细分割；进一步合并会变成更粗 span，进一步拆分则至少一侧没有 token 边界。

论文的 Proposition 1 用 KL 的分组分解说明：把 minimal units 合并为粗单元 $C$ 后，$KL(q_S^{min}\|q_T^{min})\ge KL(q_S^C\|q_T^C)$；差值正是粗单元内部被抹掉的 teacher/student 条件分布差异。这个不等式说明合并必然少看一些区分信号，但不自动证明更大的 KL 一定带来更好下游性能，因此论文还用 Figure 4 做经验验证。

### 固定 commit 的源码伴读

作者代码固定在 [`cf0f33a`](https://github.com/sunjie279/SimCT-/tree/cf0f33a0e6c967d4b74ea32b2dba12be01b73b9e)。[`_align_sequences_with_spans`](https://github.com/sunjie279/SimCT-/blob/cf0f33a0e6c967d4b74ea32b2dba12be01b73b9e/kdflow/algorithms/span_ctkd.py#L75-L173) 对 loss-mask 后的 next-token label 逐 token decode，用累计文本长度寻找共同边界，返回 `(teacher_start, teacher_end, student_start, student_end)`；这与论文 minimal aligned units 的输入输出直接对应。[`_build_virtual_vocab_logits`](https://github.com/sunjie279/SimCT-/blob/cf0f33a0e6c967d4b74ea32b2dba12be01b73b9e/kdflow/algorithms/span_ctkd.py#L178-L310) 把共享词表 logits 与每个 span 的维度拼成 `[num_segments, num_overlap + num_spans]`，span logit 取组成 token 的 self-logit 均值。

[`training_step`](https://github.com/sunjie279/SimCT-/blob/cf0f33a0e6c967d4b74ea32b2dba12be01b73b9e/kdflow/algorithms/span_ctkd.py#L355-L508) 沿真实调用链做 student forward、从 teacher hidden states 恢复 teacher logits、按样本对齐、构造两边同形状 virtual logits，最后调用 RKL。[`compute_reverse_kl_div`](https://github.com/sunjie279/SimCT-/blob/cf0f33a0e6c967d4b74ea32b2dba12be01b73b9e/kdflow/loss/reverse_kl_div.py#L6-L27) 计算 $\sum q_S(\log q_S-\log q_T)$。代码还可按 teacher 候选质量 $Z_T(h)$ 屏蔽重归一化倍数 $G(h)=1/Z_T(h)$ 过大的位置，避免小概率尾部被放大；这是理解数值稳定性时不能漏掉的分支。

在线训练器的顺序是 student rollout → teacher forward → student distill → 把更新后权重同步回 rollout engine，可在 [`OnPolicyKDTrainer.fit`](https://github.com/sunjie279/SimCT-/blob/cf0f33a0e6c967d4b74ea32b2dba12be01b73b9e/kdflow/trainer/on_policy_kd_trainer.py#L145-L236) 核对。以上是静态代码阅读，没有在本机运行 8 卡训练；仓库当前示例脚本写 1 epoch、$5\times10^{-7}$，而论文 Table 4 写 2 epochs、$10^{-6}$。因此报告以固定 PDF 的论文实验为结果口径，并把脚本差异视为复现前必须确认的版本问题。

## 3. 实验设置与算力

实验用三组大模型教小模型：Qwen2.5-7B-Instruct→Gemma-2-2B-it、Qwen2.5-7B-Instruct→Phi-4-mini-instruct、Phi-4-mini-instruct→Gemma-2-2B-it。所有方法从同一 SFT warm-start checkpoint 出发，OPD prompt、rollout、优化器和总训练预算保持一致，只改变跨 tokenizer 监督接口。这样 Table 1 的差异主要对应 SimCT / SimpleOPD / ALM / GOLD / DSKD，而不是谁拿到了更好的初始学生。

**数据流水线。** 数学 prompt 来自 GSM8K、Orca-Math、OpenMathInstruct-1 与排除 MATH-500 的 MATH；代码来自 OpenCodeInstruct、KodCode、TACO、CodeContests。teacher 对每题以 temperature 0.6、top-$p$ 0.95 采 8 个回答，用可验证正确性或质量过滤保留一个，得到 10,000 条 warm-start 样本：5,800 条数学、4,200 条代码。评测为 zero-shot：GSM8K、MATH-500、MBPP、LiveCodeBench-v6；每个 benchmark 做 5 个随机种子，报告 mean±std 的 pass@1。

| 环节 | SFT warm start | On-policy distillation |
| --- | --- | --- |
| 优化器 / 精度 | AdamW / bfloat16 | AdamW / bfloat16 |
| 峰值学习率 | $2\times10^{-6}$ | $1\times10^{-6}$ |
| warmup / 调度 | 0.05 / cosine decay | 0.05 / cosine decay |
| epoch / 有效 batch | 2 / 64 | 2 / 64 |
| per-device batch / 累积 | 2 / 4 | 1 / 8 |
| 最大序列长度 | 4096 | 4096 |
| rollout | — | temperature 0.6，top-$p$ 0.95，最大 4096 |
| 损失 | next-token SFT | SimCT 与 SimpleOPD 用 reverse KL |
| 计算资源 | 单机 8×NVIDIA H20 96GB | 单机 8×NVIDIA H20 96GB |

![Table 4 · SFT 与 OPD 的完整训练超参数](./assets/papers/paper-opd-2605-07711/table-4-pdf.png)

**原表解读。** [Table 4，固定 PDF 第 20 页](https://arxiv.org/pdf/2605.07711v2#page=20)把两阶段配置并排给出，能防止把 SFT 的 $2\times10^{-6}$ 与 OPD 的 $1\times10^{-6}$ 混写，也明确两阶段都训练 2 epochs。仓库当前脚本的参数与表格不同，所以复现报告数值时应先取得论文对应 release/config，而不能只运行今天的 main。论文硬件还包括双路 AMD EPYC 9K84、384 逻辑核和 2.2TB 内存；这些 CPU/内存资源对多引擎 rollout 与 teacher forward 的吞吐同样相关。

Appendix E 测得单次 OPD：SimpleOPD 平均 2.53h、SimCT 2.69h、ALM 2.84h、GOLD 2.93h、DSKD 2.92h，均在同一台 8×H20 机器上。主实验复现估算包括 25 次冷启动相关运行、75 次训练与 105 次评测，总计约 **14.79 个 8×H20 server-days**；这不含超参探索、消融、失败任务和研发调试。因而“SimCT 只比 SimpleOPD 多约 0.16h/次”与“完整论文成本很低”不是同一结论。

## 4. 结果与图表解读

![Table 1 · 三组 teacher/student、四个 benchmark 的完整主结果](./assets/papers/paper-opd-2605-07711/table-1-pdf.png)

**原表解读。** [Table 1，固定 PDF 第 7 页](https://arxiv.org/pdf/2605.07711v2#page=7)每组都从同一 SFT checkpoint 比较五种蒸馏接口。Qwen→Gemma 的四项平均由 SFT **30.95**、SimpleOPD **31.12** 提到 SimCT **32.80**；其中 MATH-500 为 18.02→22.18，LCB-v6 为 6.77→7.29。Qwen→Phi 的平均为 51.30→55.06，Phi→Gemma 为 31.11→32.58。SimCT 在三组平均和表内每个 benchmark 都最高，但绝对提升并不均匀：例如 Qwen→Gemma 的 GSM8K 提升小于 MATH-500，不能把平均增益解释为每个任务等幅改善。

标准差来自 5 次评测运行，而不是 5 次完整独立训练的置信区间；表中粗体也不是显著性检验。Base 行是未经该组 warm-start 的基础模型，SFT 行是共同起点，蒸馏方法应优先与同组 SFT / SimpleOPD 对比。跨模型组直接比较绝对 pass@1 会混入 student 能力、tokenizer 和 teacher 强弱，不能只凭 55.06 大于 32.80 就说某个接口在 Phi 上“更有效”。

![Figure 3 · tokenizer mismatch 的两类监督损失与恢复收益](./assets/papers/paper-opd-2605-07711/figure-3-pdf.png)

**原图解读。** [Figure 3，固定 PDF 第 8 页](https://arxiv.org/pdf/2605.07711v2#page=8)A/B 分别量化 sequence mismatch 和 shared-vocabulary coverage：Gemma 的 unaligned 为 19.5%，teacher top-100 落在共享词表外为 14.2%；Phi 对应 11.3% 与 4.6%。C 从 SimpleOPD 开始单独加回共享词表外监督（+OoSV）或非一一对齐 span（+Unaligned）：Gemma 相对增益从 0.9% 增到 1.2% / 4.8%，完整 SimCT 为 6.4%；Phi 从 2.2% 增到 3.1% / 6.3%，完整 SimCT 为 8.3%。两类信号单独恢复都有效，且 sequence mismatch 在这里贡献更大；但这是两种 student 的实验，不能外推为所有 tokenizer 永远由 span mismatch 主导。

![Figure 4 · 恢复比例与粗化损失的消融](./assets/papers/paper-opd-2605-07711/figure-4-pdf.png)

**原图解读。** [Figure 4，固定 PDF 第 9 页](https://arxiv.org/pdf/2605.07711v2#page=9)左图把 mismatch-unit 监督的使用比例从 0% 提到 100%，Gemma 的相对增益约从 1.2% 单调升至 6.4%，Phi 从 3.1% 升至 8.3%，为“恢复越多有效监督，收益越高”提供剂量关系。右图横轴是粗化后被移除的 KL 信号，纵轴是相对提升；两种 student 都呈负趋势：合并越多 minimal units、抹掉的内部差异越大，收益越低。它与 Proposition 1 的方向一致，但散点数量有限，虚线是趋势描述，不足以证明 removed-KL 是跨模型通用的因果指标。

主表与两张消融图共同支持的最窄结论是：在论文给定的三组白盒 teacher/student、数学与代码数据、相同 warm-start 和预算下，minimal aligned units 比 exact shared-token overlap 保留更多有用监督，并优于所列三种跨 tokenizer 基线。它们不证明黑盒 teacher、非 BPE tokenizer、多语种 Unicode 规范化或多模态 token 序列同样有效。

## 5. 局限、结论与后续阅读

SimCT 的价值在于把“不同 tokenizer 的 logits 怎么比较”从工程补丁变成一个可解释的监督空间问题：先找双方最细共同文本边界，再在共享 token 与 minimal aligned units 上比较偏好。Figure 3 说明旧接口确实丢信号，Figure 4 说明恢复比例与粒度都影响收益，Table 1 则给出统一预算下的下游结果；三种证据互相衔接，比只报平均分更可信。

边界同样明确。第一，方法需要白盒 next-token logits；只有文本或标量 reward 的 teacher 不能直接使用。第二，span 分数采用平均 log-likelihood 并在有限候选集重归一化，不是严格质量守恒的序列概率映射；候选覆盖很低时可能放大 teacher 尾部，源码为此提供 $G(h)$ mask。第三，论文集中于标准文本 tokenizer、两个任务域和三组模型，尚未覆盖 Unicode 规范化差异、byte fallback、特殊 token、工具调用结构、多语种或多模态序列。第四，完整主实验估算约 14.8 个 8×H20 server-days，不能只用单次训练约 2.69h 描述成本。

复现时应先做三个小测试：用真实 tokenizer 检查换行、空格、特殊 token 与 `happy` 类 span 的共同边界；确认 virtual logits 的形状、候选质量 $Z_T$ 和被 mask 比例；最后核对论文 Table 4 与仓库脚本的 epoch/LR 差异，再启动多卡训练。建议继续对照 [GKD](#paper=paper-opd-2306-13649) 理解共享 tokenizer 下的 on-policy 目标，对照 [Cross-Tokenizer OPD](#paper=paper-opd-2606-09456) 与 [BPM](#paper=paper-opd-2607-22334) 比较异步边界和概率质量构造。
