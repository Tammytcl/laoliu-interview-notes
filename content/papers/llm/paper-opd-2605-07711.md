## 1. 背景与已有工作

普通 OPD 在 student 自己生成的前缀上，请 teacher 给出下一个 token 的概率分布，再让 student 模仿。若双方共享 tokenizer，两个分布定义在同一词表上，逐 token KL 有意义；换成 Qwen 教 Gemma、Phi 教 Gemma，词表和切词边界都会不同。比如同一个 “happy”，teacher 可能切成 `hap|py`，student 切成 `ha|pp|y`。直接把某个 token id 对齐，可能比较了不同文本；只保留两个词表**字面相同的 token**，又丢掉了大量可利用的 teacher 信号。

SimCT 问的是：**能否把双方不同的 token 还原到共同的文本预测单位，在不训练额外对齐模型的前提下做在线蒸馏？** 它延续 [GKD](#paper=paper-opd-2306-13649) 的 student on-policy 前缀，但把“共享词表”替换成“共享的文本单位”。[Breaking Tokenizer Barrier](#paper=paper-opd-2606-09456)着重处理异步边界与语义 credit，[BPM](#paper=paper-opd-2607-22334)用 byte prefix mass；三者的概率构造不同，不宜只因都叫跨 tokenizer OPD 就合并成同一算法。

## 2. 方法与实现机制

给定 student 前缀文本 $x_{<t}$，teacher 在自身词表 $V_T$ 上预测，student 在 $V_S$ 上预测。SimCT 定义共同监督空间 $U$：一部分是本来一对一相同的 token，另一部分是**最小对齐文本单位**。所谓“最小”是同时沿两套 tokenizer 的边界扫描，找到下一次两边都结束于同一文本位置的最短片段；这使前面 “happy” 的两种切法能被视作同一个单位。对每个单位，模型按自己 tokenizer 的连续 token 计算续写 log-prob，再在候选单位集合内归一化。目标是在 student 访问的文本前缀上比较两套映射后的分布 $\Pi_T(p_T)$ 与 $\Pi_S(p_S)$，而不是硬配不同词表的 id。

这个构造有两层代价。第一，长的共同单位需要多步条件概率；不能把序列中每个 token 概率随意相加当作一个 next-token 概率。第二，构造候选集会截断原词表质量，归一化后的分布是**共同候选集上的相对偏好**，并非原模型整个词表的无损映射。原文 Algorithm 1 给出在线训练流程：student 采样文本，双方重分词，寻找对齐单位，计算单位得分，归一化后做蒸馏；Figure 2(A/B)解释“公共空间”和 “happy” 例子。

作者代码仓库为 [SimCT-](https://github.com/sunjie279/SimCT-)。原文将它作为复现实验入口；本轮已核对官方链接与算法描述，但**尚未逐函数静态审读**，所以不把某个代码函数名冒充为核心实现。实际复现时应先检查边界扫描如何处理特殊 token、空白前缀与多个候选文本具有同一标准化字符串，再对照 Algorithm 1 的概率归一化和 loss mask。

## 3. 实验设置与算力

实验有三组异构 teacher→student：Qwen2.5-7B-Instruct→Phi-4-mini-Instruct、Qwen→Gemma-2-2B-IT、Phi→Gemma。为了避免“哪个算法拿到了更好的初始学生”，作者先用同一批 teacher 生成回答做 SFT warm start：数学 prompt 来自 GSM8K、Orca-Math、OpenMathInstruct-1、MATH（排除 MATH-500）；代码来自 OpenCodeInstruct、KodCode、TACO、CodeContests。每题 teacher 采 **8** 次，依据可验证正确性或质量过滤留一条，最终得到 **10K** 例，其中数学 **5,800**、代码 **4,200**。各 OPD 方法从同一 warm-start checkpoint 出发，固定 prompt、采样和优化预算。

基线包括只用同名 token 的 SimpleOPD、learned projection 的 DSKD、chunk likelihood 的 ALM、文本对齐概率聚合的 GOLD。评测数学 GSM8K/MATH-500、代码 MBPP/LiveCodeBench v6，报告零样本 **pass@1 的五次运行平均**。这组实验比较的是共同起点后不同监督空间的收益；teacher 预生成 10K SFT 样本的成本属于完整流水线，不能只算 OPD 更新。主文未给出统一的 GPU 型号、卡数、GPU-hours，复现需从附录与仓库配置补充。

## 4. 结果与图表解读

**Table 1** 的 Qwen→Gemma 组，warm-start SFT 四项平均 **30.95**，SimpleOPD **31.12**，ALM **31.42**，GOLD **31.99**，DSKD **32.01**，SimCT **32.80**。单项中 MATH-500 从 SFT **18.02** 到 SimCT **22.18**，LCB-v6 从 **6.77** 到 **7.29**：总体提升主要不能被说成所有任务同幅度改进。Qwen→Phi 组 SFT 平均 **51.30**，SimCT **55.06**；需对照原文该组的每列结果，避免只看平均掩盖更弱的任务。

**Figure 2** 用相同文本但切分不同的例子说明为什么 exact-token overlap 会浪费监督，而非展示性能曲线。原文后续消融比较共同单位的覆盖与不同基线；读这些图表时应追问：新增单位带来多少有效 token 监督、每次 student rollout 需要多少 teacher 前向，以及候选单位归一化是否给常见短字符串偏置。性能增加与系统代价必须一起衡量。

## 5. 局限与阅读结论

SimCT 适合教学上理解“跨 tokenizer 蒸馏先要定义双方究竟在比较什么”。它给出了不用训练额外投影的一个共同文本单位构造，并在三个大教小组合中胜过所列基线。但这些实验不能保证任意 Unicode 规范化、特殊 token、超长异步切分或多模态 tokenizer 都有同样的单位覆盖。若准备复现，先用短字符串与真实模型 tokenizer 做边界单元测试，再跑完整训练；记录共同单位覆盖率、teacher 额外前向次数与峰值显存。
