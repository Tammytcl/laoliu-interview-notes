## 1. 背景与已有工作

**要解决的具体问题。** 给定输入 $x$，自回归 student 生成 $y_1,y_2,\ldots$ 时，每一步的决策都依赖自己先前写出的 token。假设训练集总是以正确摘要“公司公布季度利润”为前缀，student 推理时却写成“公司公布季度亏损”；训练阶段没有见过后面这个前缀，随后它该怎样纠错？传统蒸馏常在固定的人写答案或 teacher 答案上训练，teacher 的 soft label 虽比单个金标准 token 更丰富，监督所覆盖的前缀却仍由固定语料决定。这里的问题是 **训练前缀的分布与 student 真正生成的前缀分布不一致**，而不是模型是否知道下一个 token 的正确答案。

这个问题在模仿学习中早就出现，通常称为 covariate shift 或 exposure bias：行为克隆在专家轨迹上看似准确，自己执行时一次小错会使后续状态逐渐偏离训练数据。论文借鉴交互式模仿学习的思路：让当前 student 亲自走到某个前缀，再让 teacher 在该前缀上给出下一步的完整概率分布。这样 teacher 评价的是 student 实际可能遇到的状态，甚至包括已有错误的状态，而非只评价教科书式轨迹。要注意，teacher 给的不是自然语言批改意见，也不是序列级偏好分数，而是每一步的 token 分布。

已有方法的区别可从“轨迹来自谁、监督是什么”两轴理解。监督微调用人写答案和 hard token 标签；SeqKD 先让 teacher 写答案，student 再模仿这些固定文本；supervised KD 在固定答案前缀上匹配 teacher logits。ImitKD 已引入混合 student 轨迹，f-distill 讨论不同散度，但 GKD 把轨迹比例与散度作为可独立选择的变量，并系统地研究完全 on-policy 的情况。因此它的贡献不是首创一切在线学习，而是为自回归语言模型蒸馏给出可实验比较的统一框架。[原文第 2–5 页](https://arxiv.org/pdf/2306.13649v3#page=2)明确给出了这些基线及差别。

还有一个单独的问题：小 student 未必有足够容量覆盖 teacher 的多种合理续写。通常采用的 forward KL 会强烈惩罚遗漏 teacher 支持的模式；reverse KL 更倾向挑选较集中的高概率模式。这里“覆盖”和“挑选”的取舍与前缀来自谁不是同一件事。若任务看重单个最优答案，集中概率可能有利；若摘要需要保留多样表达，过度集中也可能造成损失。读这篇论文时应该分别追问：收益来自见到了自己的错误，还是来自换了散度？图 4 与附录消融正是回答这两个问题的关键证据。

## 2. 方法与实现机制

先固定符号。$p_T$ 是 teacher，$p_S^\theta$ 是参数为 $\theta$ 的 student；$x$ 是输入 prompt，$y=(y_1,\ldots,y_{L_y})$ 是一条输出序列。给定任意前缀 $y_{<n}$，两个模型都输出同一词表上的下一个 token 分布。论文先在每个 token 位置计算散度，再除以序列长度，避免长序列只因位置多就主导损失：

$$
D(p_T\parallel p_S^\theta)(y\mid x)
=\frac{1}{L_y}\sum_{n=1}^{L_y}
D\!\left(p_T(\cdot\mid x,y_{<n})\parallel p_S^\theta(\cdot\mid x,y_{<n})\right).
$$

GKD 的数据源是一个混合分布：以 $1-\lambda$ 的权重取固定的 $(x,y)$，以 $\lambda$ 的权重取输入 $x$ 并由当前 student 生成 $y$。在两种序列上，真正训练的目标都是同一个位置对齐的 teacher–student 散度：

$$
\mathcal L_{\mathrm{GKD}}(\theta)=(1-\lambda)\,\mathbb E_{(x,y)\sim(X,Y)}D(p_T\parallel p_S^\theta)(y\mid x)
+\lambda\,\mathbb E_{x\sim X}\mathbb E_{y\sim p_S(\cdot\mid x)}D(p_T\parallel p_S^\theta)(y\mid x).
$$

$\lambda=0$ 退化为固定轨迹蒸馏，$\lambda=1$ 则完全在当前 student 的生成轨迹上学习。实现时把生成的 token 当作本轮数据，**不穿过离散采样反传**；这与用 REINFORCE 直接对生成概率求梯度不同。每次 student 参数更新后，新采出的前缀分布也会变，故这里的 on-policy 不是一次性缓存 student 答案。teacher 必须在完整的 student 前缀上计算 logits，不能拿 teacher 自己的前缀或仅拿最终文本分数替代，否则位置对齐和训练目标都会改变。

![Algorithm 1 · GKD 的 student 轨迹采样与蒸馏更新](./assets/papers/paper-opd-2306-13649/algorithm-1-pdf.png)

**原图解读。** [原文 Algorithm 1，第 4 页](https://arxiv.org/pdf/2306.13649v3#page=4)是这篇论文最直接的方法流程图：先抛一个均匀随机数 $u$；$u\leq\lambda$ 时从输入集抽 prompt 并让 student 生成 batch，否则抽固定输入输出对；最后计算 batch 上的散度并更新 $\theta$。图中并没有一个额外的“纠错模型”，反馈来自 teacher 对同一前缀的分布。若做实现检查，最要紧的是确认每轮采样用的是当时的 student，以及 teacher 与 student 看到完全相同的 $x,y_{<n}$。原文的批量级随机选择是一种实现，数学目标则允许按样本估计期望。

论文让 $D$ 取 forward KL、reverse KL 或 generalized JSD。对于两个 token 分布 $P,Q$，forward KL 是 $D_{KL}(P\parallel Q)$，会在 teacher 认为可能的 token 上要求 student 保留概率；reverse KL 是 $D_{KL}(Q\parallel P)$，更可能聚焦某个 teacher 高概率区域。JSD($\beta$) 则把二者通过混合分布 $M=\beta P+(1-\beta)Q$ 连接：$\beta D_{KL}(P\parallel M)+(1-\beta)D_{KL}(Q\parallel M)$。论文测试 $\beta=0.1,0.5,0.9$，它们不是学习率或采样温度。选散度前还要问评测是 greedy 还是带温度采样；同一模型在这两种解码下可能呈现不同的质量与多样性排序。

GKD 还可接入奖励优化。在 student 自采样轨迹上，一边最大化标量奖励 $r(y)$，一边用系数 $\alpha$ 保留 teacher 分布约束。这里的 $\lambda$ 控制 **训练序列来源**，$\alpha$ 控制 **奖励与蒸馏两项目标的权重**；混淆二者会读错 Figure 5 的横纵意义。论文第 5 页给出这一目标，并在摘要的事实一致性实验中使用基于文本蕴含的 AI 反馈奖励，但这部分是组合验证，不是 GKD 必须依赖的组成件。

**源码核读边界。** 本文及附录没有给出可核实为作者 GKD 实验实现的官方 GitHub 仓库；T5 checkpoint 和被引框架地址不能当成算法源码。因而这里逐行解释原文 Algorithm 1 与损失公式，没有虚构 `train_step`、采样函数或配置文件名。将来若补到经作者确认的仓库，应再检查四个点：on-policy batch 比例、生成时 student 温度、teacher logits 的前缀对齐、散度的归一化及采样 stop-gradient；届时补具体文件与行号。

## 3. 实验设置与算力

**模型与起点。** 主要 teacher 是约 3B 参数的 T5-XL，student 有 T5-small 77M、T5-base 250M、T5-large 800M 三档，分别约小 38、12、3.8 倍。论文不是从随机初始化的小模型直接做 on-policy：两边先从 LM-adapted T5v1.1 或 FLAN-T5 出发，再按任务监督微调。这一步很关键，因为在 student 还不会生成有意义序列时，teacher 即使给出 soft labels，也不能保证训练轨迹覆盖合理任务行为。所有蒸馏基线从同一个任务 SFT student 起点比较。训练优化器采用 Adafactor；原文 Appendix A.2 披露了各模型 SFT 步数。[原文第 5 页与附录 A.2](https://arxiv.org/pdf/2306.13649v3#page=14)。

**任务和测量。** XSum 是新闻单文档摘要，使用 validation 上的 ROUGE-2；WMT14 英译德使用 validation BLEU，并在评测时做 beam search；GSM8K 使用约 5.3K 道题及外部生成的 CoT 训练文本，测试集以 4-shot CoT 提示、计算器辅助检查最终答案，报告正确率；FLAN2021 包含 62 个任务、536 万例指令数据，蒸馏后用未进入训练的 MMLU 57 个任务与 BBH 23 个任务检验迁移，以 few-shot exact-match accuracy 均值报告。不同任务的指标不能横向相减，尤其 ROUGE-2 和 GSM8K accuracy 的数值刻度完全不同。

| 设置 | XSum 摘要 | WMT14 en→de | GSM8K 推理 | FLAN 指令蒸馏 |
| --- | --- | --- | --- | --- |
| teacher / student | SFT T5-XL / small、base、large | SFT T5-XL / small、base、large | SFT FLAN T5-XL / small、base、large | FLAN T5-XL / FLAN T5-base |
| 蒸馏步数 | 40,000 | 100,000 | 40,000 | 50,000 |
| batch size | 32 | 32 | 32 | 128 |
| 学习率 | 通常 3e-4；small 的选优值为 1e-3 | 3e-4 | 3e-4 | 1e-4 |
| 最大输入 / 输出长度 | 1024 / 64 | 80 / 80 | 512 / 320 | 输入 2048；其他长度见原表 |
| 核心评测 | validation ROUGE-2 | validation BLEU | test accuracy，4-shot CoT + calculator | held-out MMLU / BBH exact match |

这张账本提取自附录 A.1–A.4；它是帮助复核的文字整理，下面保留原论文的实验参数表截图。注意 XSum 的 T5-small 最优学习率单独选 1e-3，而 reverse KL 更敏感，原文默认 3e-4；如果只拿统一学习率复现并宣称某个散度失效，比较可能并不公平。GSM8K 的 teacher softmax 温度设为 0.1、评测用 greedy；WMT 的 BLEU 结果平均三次随机种子。训练数据和解码策略也要与表中条件一起记录，不能只抄最终指标。

![Table A.1 · XSum 蒸馏的原论文超参数表](./assets/papers/paper-opd-2306-13649/table-a-1-pdf.png)

**原表解读。** [Table A.1，原文第 15 页](https://arxiv.org/pdf/2306.13649v3#page=15)明确列出 40k steps、batch 32、输入最多 1024 token、输出最多 64 token、2k warmup 与 30k–40k 的线性 cooldown。表里的 3e-4 是默认 LR，不能覆盖正文讨论过的 small 模型例外。原表也注明 validation 与 greedy/temperature sampling 两种评测方式，这正解释了为什么 Figure 4 的温度扫描值得单独读；只看一列 ROUGE-2 会漏掉解码条件。

**算力与成本。** 论文没有提供所有任务统一的 GPU 型号、卡数或总 GPU-hours，因此不能据此报出“复现需 N 张 A100”。它给出的可用锚点是：各方法共享的 SFT 起点，在最小 TPUv3 配置 **8 cores** 上需要“数小时”；GSM8K 中因 student 采样带来的额外计算开销，相对于从固定输出集采样，约为 1.8×、2.0×、2.2×，分别对应 38×、12×、3.8× 的 teacher/student 参数比。这里是论文报告的训练开销比，并非所有任务的端到端 GPU 成本；加入 teacher 推理、序列长度和数据生成方式后，实际预算会变。若计划自己复现，优先实测 tokens/s 与 teacher 前向成本，再估算总 TPU/GPU 小时。[原文附录 A.2](https://arxiv.org/pdf/2306.13649v3#page=14)。

## 4. 结果与图表解读

![Figure 1 · 三种任务、三档 student 的主结果](./assets/papers/paper-opd-2306-13649/figure-1-pdf.png)

**原图解读。** [Figure 1，原文第 1 页](https://arxiv.org/pdf/2306.13649v3#page=1)的三个 panel 分别是 XSum 的 ROUGE-2、WMT 的 BLEU 和 GSM8K 的计算器辅助准确率；横轴是 77M、250M、800M 三档 student，水平线是约 3B 的 teacher。颜色对照为初始 SFT、supervised KD、SeqKD、on-policy GKD。最稳定的观察是 GKD 在这些配置下超过固定轨迹基线，而不是每一档 student 都追平 teacher。论文说的 **2.1×/1.7×/1.9×** 分别是摘要、翻译、推理中“相对初始 student 的性能提升”相对于基线 KD 提升的平均倍数；它们不是 ROUGE-2、BLEU 或 accuracy 的绝对分数，更不能解读成质量提高 210%。图注还限定了 WMT 用 JSD(0.1)、另外两项用 forward KL，说明主图本身不是“同一散度通吃任务”的证据。

要拆解收益来源，还得看原文 Figure 3、6–9 与附录 A.12–A.15。Figure 3 在 XSum 上把训练数据缩到 0.5%、5%、25%，on-policy 版本只用 5% 输入、无人工摘要时仍超过使用全部摘要的若干固定轨迹对照，提示 student 自身访问到的前缀有价值。WMT Figure 6 对 $\lambda=0,0.5,1$ 和五种散度作网格消融，纯 on-policy 或混合通常胜于只用固定序列；GSM8K Figure 8 表明 on-policy 比例超过约 25% 后通常继续改善。它们共同削弱“只因为换了 loss 所以变好”的解释，但不同任务里最好的 loss 不一样，不能由此推导所有任务都应该设 $\lambda=1$、reverse KL。

![Figure 4 · 摘要质量与生成多样性的取舍](./assets/papers/paper-opd-2306-13649/figure-4-pdf.png)

**原图解读。** [Figure 4，原文第 6 页](https://arxiv.org/pdf/2306.13649v3#page=6)横轴是 Self-BLEU：越高代表不同生成结果越相似、**多样性越低**；纵轴是 XSum ROUGE-2，越高代表对参考摘要的词面匹配越好。颜色和线型改变采样温度，点形改变散度。在高温采样时，向 JSD(0.9) 或 reverse KL 移动可以提高质量，但点也常向右移动，表示牺牲多样性；温度降低时，各散度在质量上的间隔缩小。这个图提醒我们：若产品希望一题多解或不同摘要表达，不能只报告 ROUGE-2；若只需一条稳定输出，则质量与多样性的权重可能不同。Self-BLEU 是样本间相似度，不等同于事实性或人工偏好评价。

![Figure 10 · 未见过的 MMLU 与 BBH 指令任务结果](./assets/papers/paper-opd-2306-13649/figure-10-pdf.png)

**原图解读。** [Figure 10，原文第 9 页](https://arxiv.org/pdf/2306.13649v3#page=9)显示 FLAN 指令数据蒸馏后，在未用于蒸馏的 MMLU 与 BBH 上相对原始 student 的 **百分点变化**。粉色的 on-policy reverse KL 在两侧都最高，MMLU 约 +2 个百分点，BBH 约 +1 个百分点；蓝色 on-policy forward KL 在 MMLU 甚至低于起点。这里“on-policy 有效”必须带上“选择合适散度”的条件。图注和正文对 student 名称存在不一致：图标题及第 4.4 节说 FLAN T5-base，但图注末句称 T5-large。本文以第 4.4 节的实验设置为主，保留这一原文矛盾，不用图注末句的基线数值拼接出假精确的蒸馏后绝对分数。

论文还把 on-policy GKD 接到 RLAIF：Figure 5 随 $\alpha$ 改变，摘要质量与基于蕴含模型的事实一致性呈可调权衡。这个结果支持“同一 student rollout 可同时用于奖励训练与分布约束”，但蕴含分数只是代理指标，并不能自动证明人工事实核查也改善。整体上，最强的证据链是主图的跨任务收益、数据来源与散度的消融、以及不同解码温度下的质量—多样性分析，而不是挑一幅表现最好的柱状图下结论。

## 5. 局限、结论与后续阅读

GKD 给 OPD 研究留下的可复用框架是两道独立选择：**student 访问哪些前缀**，以及 **在这些前缀上以什么散度逼近 teacher**。它把模型部署时真正会遇到的自生成错误带回训练，同时承认小模型对 teacher 分布的容量限制。对新论文做比较时，至少要问清楚 on-policy 比例、teacher 是否提供完整 logits、散度作用在 token 还是序列、训练起点是否 SFT、以及评测解码温度；否则“也是 on-policy 蒸馏”不足以说明机制相同。

限制同样具体。当前实验以同词表 T5/FLAN-T5 为主，teacher 能在 student 前缀上返回 token 分布；仅返回文本的黑盒 API 无法直接执行论文所需的全词表散度。方法假设 student 起点能生成尚可的序列，而训练中不断生成文本会增加计算开销。实验覆盖摘要、翻译、短数学题及指令迁移，尚不足以断言长链推理、不同 tokenizer、多教师融合或大规模 decoder-only LLM 一定有相同排序。代码未确认开源，本文对实现仅做算法级核读，尚未训练复现。

接下来可把 [MiniLLM](#paper=paper-opd-2306-08543) 的序列级 reverse KL、[SimCT](#paper=paper-opd-2605-07711) 的跨词表对齐与本文并排读：前者改变优化对象和目标，后者改变 teacher/student token 空间，正好检验 GKD 的两个前提如何被后续工作改写。主要证据来自 [固定 arXiv v3 原文](https://arxiv.org/abs/2306.13649v3)，报告中的示例性前缀用于解释机制，并非论文的真实训练样本。
