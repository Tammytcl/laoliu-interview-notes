## 从问题出发

把所有历史都塞进窗口会增加 token 成本，也不保证关键事实被利用。问题是选择下一轮决策真正需要的信息。

## 三种信息存放位置

| 信息 | 合适位置示例 | 关键要求 |
|---|---|---|
| 当前任务、约束、最近动作结果 | 活跃上下文 | 下一步可直接使用 |
| 文件、完整日志、原文证据 | 外部工具/存储 | 可按 ID 重新读取 |
| 已核实的偏好或项目状态 | 持久记忆 | 来源、时效、可纠错 |

这是一种实践拆解，不是所有产品都有同样内存结构。上下文是当次模型输入，外部状态不能因为没塞进 prompt 就被视为不存在。

## 压缩策略与取舍

删除重复工具输出最便宜，但可能删掉错误线索；摘要能保留结论，但会丢细节或引入错误；检索保留原文，需要召回正确内容。组合使用时保留证据 ID、关键参数、尚未完成事项和失败记录。

压缩后问一句：下一轮能否知道目前环境状态、有效约束以及为何此前尝试失败？摘要“都处理过了”通常不可验证。

## 与 prefix cache 和训练的连接

将稳定系统信息放在前缀、变动观察放后面可能利于 [前缀缓存](https://docs.vllm.ai/en/latest/features/automatic_prefix_caching/)，但信息布局首先要满足任务。重写早期历史会改变后续前缀；不能默认缓存仍命中。

训练时必须保存每轮实际 prompt，而非拿最终摘要倒推当时条件。删掉旧 thinking 后仍可按当轮输入训练，见 [多轮梯度](#q=agent-gradient)。

## 小实验与自检

建立一个跨 10 轮查证任务，在第 7 轮需要第 2 轮的细节。比较完整历史、摘要、摘要+按 ID 重读。记录成功率、输入 token 与重新读取次数；不要只凭摘要长度判断好坏。

自检：记住“任务完成”与记住可核验产物有什么区别？摘要写错了怎样让系统恢复？

## 面试表达

上下文管理是为当前决策选信息，外部状态保存可重读的事实；压缩要保留约束、证据和未完成事项，并用长程任务评测。
