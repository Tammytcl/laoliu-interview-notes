## 60–90 秒回答

我会先用一句话描述可验证的问题，例如跨 tokenizer 时监督事件不一致，或多轮 OPD 中完整轨迹交接造成等待。接着明确我负责的设计和实现，与已有方法的区别。第三部分用同起点、同数据、同评测与相近预算的主结果、消融和故障分析支撑结论，同时报告统计和成本。最后说明哪些已公开、哪些是历史实验、哪些仍是待检验假设。项目介绍不需要把论文每一节复述一遍，但必须让面试官追到公式、代码、数据流和日志时都能对应上；团队结果也不能全部说成个人贡献。

## 原理拆解

### 三分钟要完成的是可追问的论证

开头先说任务、旧方法的具体失败与约束，例如“教师事件被学生分成多步，root 对齐仍未约束后续完成”，接着说自己提出/实现的改动及作用位置。方法只挑一个核心公式或一张真实数据流图；第三段给与这个机制对应的证据，最后明确失败边界。模型名字、算法名和参与任务列表不能代替“为什么这个改动应该影响这个指标”的逻辑链。

针对你的三条线，可以分别准备：跨 tokenizer 的事件与集合梯度；Math/Code/IF 合版的任务—教师—学生更新流程及分域结果；Agentic OPD 的轮级就绪条件与在线 critic 权重。每条分开写团队成果、自己负责的代码/实验、公开材料与仍待验证的设计，面试官追问到实现时才不会出现叙述断层。

### Infra 与算法要做交叉对照

对异步与 critic 加权，可用一个 2×2 实验：同步/异步 × 等权/critic 权重。先在相同调度下比较监督分配，再在相同权重下比较时间线；组合结果检验两者是否有交互。单纯异步后多更新了很多步，不能证明权重学习更有效；单纯最终分数更高，也不能证明减少了等待。

同时给三种口径：相同有效训练 token 看数据利用；相同总 GPU-hour/墙钟看资源效率；相同推理预算看最终能力。异步会改变版本滞后与长短任务比例，需记录这些中介量。消融中的随机权重应尽量匹配原权重均值/方差，避免把整体梯度尺度改变误当作语义评分有效。

### 小评测集怎样报告不确定性

用同一组题比较模型，保存逐题差异而非只报两次均值。可以按题 paired bootstrap：每次有放回抽题，计算同一抽样索引下两个模型的均分差，观察差值分布。若题来自少数相关题族，应考虑按题族重采样；若有多个训练 seed，还要单独呈现训练波动。对 40 题，改变一个二元成败会改变通过率 2.5 个百分点，但 rubric 分数均值不等于通过率；多次调用同一 judge 也不等于新增独立题目。这里是统计设计建议，不是对已有结果的显著性声明。

### 面试追到失败时，怎样继续讲

选一个有原始记录的失败：描述现象，列出竞争解释，说明哪个最小实验排除了哪个原因，再给修复与回归。如果没有证据，直接限定为当前假设。公开仓库中 CPU 数值测试、模拟 API、真实 GPU 训练与大规模论文实验各自能证明的范围不同；讲清范围体现的是可审查的研究判断，不能用“已经开源”统一替代。

## 白板与例子

三分钟结构可以按 30 秒问题、60 秒方法与个人工作、60 秒证据、30 秒边界组织。它是练习时长参考，不是固定台词。

| 主张 | 最小证据卡 | 不能代替它的东西 |
| --- | --- | --- |
| 事件监督更合理 | toy 事件/梯度测试、root/child 消融与覆盖分析 | 仅最终分数更高 |
| 吞吐更高 | 各阶段时间线、总墙钟、全部预留 GPU-hour | 只看 learner tokens/s |
| 学习更有效 | 同预算学习曲线、独立任务和分域效果 | 更新 step 更多 |
| 打分依据更好 | 校准、价值与终局关系、等权/固定权重消融 | 自己的训练 loss 更低 |
| 已开放可复现 | 代码、配置、数据、版本和执行范围 | 只有论文 PDF 或空仓库 |

对 40 题评测，单题相对总样本就是 2.5%，但 rubric 均分不是二元正确率。可按问题进行 paired bootstrap 等不确定性分析；有多个训练 seed 时还应分别体现训练波动。重复评分不等于新增独立任务。

## 追问怎么接

**为什么不是 baseline 没调好？** 讲独立调参、公平起点、数据与解码控制，必要时同时给同数据量和同总成本结果。对不能严格匹配的条件明确解释。

**方法有提升，是哪个组件有效？** 按目标、估计器、系统调度拆消融。例如先固定权重测流水线，再固定流水线测 critic 加权，最后看组合及交互。

**你具体做了什么？** 用“提出/实现/训练/分析/维护”的真实动词，对应代码模块或实验记录；分别说明他人负责的环节。不要用“主要负责所有东西”回避边界。

**如果效果没有显著提升怎么办？** 先诚实报告，并分析预算、评价噪声和失败场景；一个排除了关键假设的实验同样能体现研究判断，但不能换指标制造成功。

## 项目怎么联系

准备三张卡：Cross-Tokenizer OPD/ESCD、任务能力合版、Agentic OPD 的 Infra 与打分。每张只填真实模型、任务、分工、方法、基线、结果、成本、失败案例和公开状态；面试先选最相关的一张，追问再切换。具体未公开实验数字留在你自己的准备记录中，不放到公开网页。

## 容易答错的点

- 把论文作者报告、CPU 数值测试、模拟 API 和真实 GPU 训练称作同一级复现。
- 将变化的 judge、推理长度、数据筛选成本隐藏在主结果后面。
- 只讲技术名词，不提供一个可回查的个人贡献或失败例子。
