## 60–90 秒回答

我会先冻结或回滚异常版本，保留复现批次与配置，再确认是生成、奖励还是训练链路的问题。第一层检查模板、EOS、token shift、loss mask、分母概率、奖励范围和模型权重是否正确同步。第二层看分域与长度分桶的 reward、熵、KL、ratio 尾部、clip fraction、梯度范数、有效 token 和有效组比例，区分奖励套利、探索塌缩、旧数据堆积及数值异常。确认实现无误后才调学习率、更新次数、KL、采样和课程。恢复要用独立验证和回归任务集，不能因训练曲线恢复平滑就立即宣布修复。

## 白板与例子

| 现象组合 | 候选原因，不是直接结论 | 最小检查 |
| --- | --- | --- |
| 训练 reward 升，独立成功率降 | 奖励套利或数据偏移 | 人工查成败变化、独立 verifier |
| 熵降、全错组增加、重复片段多 | 探索缩小或 EOS/模板错误 | 原始生成、EOS 分布、采样配置 |
| KL、ratio 尾部与 clip fraction 同升 | 更新过大、策略滞后、概率错配 | 同权重同输入重算 log-prob |
| Value loss 突增 | target、边界、回报尺度或分布改变 | 固定两步轨迹手算 return |
| 只在长响应出现 NaN/OOM | 数值、归约、激活或 KV 峰值 | 长度分桶及发生阶段 |

例如“新版本第一批 ratio 大量偏离 1”时，先核对分母对应的 behavior、模板与采样分布，而不是只把 learning rate 减半。

## 追问怎么接

**Entropy 降一定坏吗？** 不一定，模型变得确定也可能来自正确解法集中；结合任务成功、长度、重复和覆盖判断。熵定义是采样 token 估计还是全词表也要一致。

**KL 小就不会崩吗？** 不保证。小的平均 KL 可以掩盖局部尾部，奖励或 mask 错误也可能在低 KL 下损害能力。按域、位置和长度拆分。

**为什么优先同输入 log-prob 检查？** 训练与推理侧的模板、精度、并行后端或权重版本不同，会使 ratio 偏差与真正策略变化混在一起。需先量化可解释的数值差异。

## 项目怎么联系

可以从你的真实故障中选一个，按“观测—候选解释—排除实验—修复—回归”讲。没有日志时，把本题作为预案，不编造你曾遇到的曲线、崩溃原因和恢复百分比。

## 容易答错的点

- 同时改变五个超参，恢复后不知道哪个因素起作用。
- 把某个框架的经验阈值当成跨模型通用稳定条件。
- 只记录总体 reward，不保存原始回答、模型版本和错误类别。

## 闭卷自检

面试官说“第三十步开始复读，KL 仍很小”：先要哪三份证据？为模板故障和奖励套利分别设计一个最小排除实验。
