## 60–90 秒回答

我会先冻结或回滚异常版本，保留复现批次与配置，再确认是生成、奖励还是训练链路的问题。第一层检查模板、EOS、token shift、loss mask、分母概率、奖励范围和模型权重是否正确同步。第二层看分域与长度分桶的 reward、熵、KL、ratio 尾部、clip fraction、梯度范数、有效 token 和有效组比例，区分奖励套利、探索塌缩、旧数据堆积及数值异常。确认实现无误后才调学习率、更新次数、KL、采样和课程。恢复要用独立验证和回归任务集，不能因训练曲线恢复平滑就立即宣布修复。

## 原理拆解

### 先把故障定位在采样、评分还是更新

保存异常 checkpoint、原始请求、token、behavior 概率、奖励与训练配置，取同一批输入分别执行：冻结模型只生成、固定回答只评分、固定训练批次做一步更新。只生成已复读，查模型/模板/采样；评分对明显错误回答异常高，查 verifier/解析；一步更新后才突变，再查目标、mask、梯度和数值。这样每个实验只跨一条链路，避免所有模块一起变化。

权重版本相同也不意味着 log-prob 必定相同。先在同 token 历史上对齐模板、temperature、位置编码、精度、并行方式和 MoE 路由等配置，量化推理与训练后端差异。若尚未更新、ratio 就严重偏离 1，应优先解释这种不一致，而不是用更强 clip 把它遮住。

### 熵、KL 和 reward 各自遗漏了什么

全词表条件熵是 $H(p)=-\sum_ap(a)\log p(a)$；学生采样 token 的 $-\log p(a)$ 在正确采样条件下可估它，但 teacher-forced 旧 token 的均值并非同一个分布口径。只看总体熵也可能掩盖某个任务域或 EOS 概率的异常。平均 KL 同样可能被大量正常 token 稀释，应看长短响应、任务域和 ratio 尾部。

训练 reward 上升而独立正确率下降，优先检查奖励套利和评测漂移；熵下降但正确率上升、重复率稳定，可能只是有效策略集中。若模型延长回答却不增加有效解法，查看长度奖励、超长惩罚与归约。指标组合提出候选原因，仍需用具体样本和受控重放验证，不能把某条曲线当作因果证据。

### 数值排查要顺着实际计算图

依次检查奖励/advantage 是否有限，是否出现空 mask 分母，log-prob 是否来自规范化分布，log-ratio 的指数是否溢出，以及梯度范数是否在 optimizer step 前异常。大正 advantage 与极端 ratio 的乘积、低精度归约和未 detach 的目标都可能产生问题。先用短响应、单机或较高精度的最小批次确认公式，再恢复分布式和长上下文，逐步定位差异来源。

修复后同时复跑异常批次和未参与排障的回归集。若更改 KL、学习率或采样温度，分别记录哪项变化恢复了数值、哪项影响质量；若只是丢掉长任务后曲线平滑，必须再检查长任务覆盖。训练与生成的内存/吞吐调节需结合版本文档核对：[verl 性能指南](https://verl.readthedocs.io/en/latest/perf/perf_tuning.html)。

## 白板与例子

| 现象组合 | 候选原因，不是直接结论 | 最小检查 |
| --- | --- | --- |
| 训练 reward 升，独立成功率降 | 奖励套利或数据偏移 | 人工查成败变化、独立 verifier |
| 熵降、全错组增加、重复片段多 | 探索缩小或 EOS/模板错误 | 原始生成、EOS 分布、采样配置 |
| KL、ratio 尾部与 clip fraction 同升 | 更新过大、策略滞后、概率错配 | 同权重同输入重算 log-prob |
| Value loss 突增 | target、边界、回报尺度或分布改变 | 固定两步轨迹手算 return |
| 只在长响应出现 NaN/OOM | 数值、归约、激活或 KV 峰值 | 长度分桶及发生阶段 |

例如“新版本第一批 ratio 大量偏离 1”时，先核对分母对应的 behavior、模板与采样分布，而不是只把 learning rate 减半。

## 追问怎么接

**Entropy 降一定坏吗？** 不一定，模型变得确定也可能来自正确解法集中；结合任务成功、长度、重复和覆盖判断。熵定义是采样 token 估计还是全词表也要一致。

**KL 小就不会崩吗？** 不保证。小的平均 KL 可以掩盖局部尾部，奖励或 mask 错误也可能在低 KL 下损害能力。按域、位置和长度拆分。

**为什么优先同输入 log-prob 检查？** 训练与推理侧的模板、精度、并行后端或权重版本不同，会使 ratio 偏差与真正策略变化混在一起。需先量化可解释的数值差异。

## 项目怎么联系

可以从你的真实故障中选一个，按“观测—候选解释—排除实验—修复—回归”讲。没有日志时，把本题作为预案，不编造你曾遇到的曲线、崩溃原因和恢复百分比。

## 容易答错的点

- 同时改变五个超参，恢复后不知道哪个因素起作用。
- 把某个框架的经验阈值当成跨模型通用稳定条件。
- 只记录总体 reward，不保存原始回答、模型版本和错误类别。
