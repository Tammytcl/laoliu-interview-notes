## 当前定位与假设

已知偏好：覆盖 diffusion、LLM、agent、infra，以理解和学习为主，少量手撕代码，暂缓扩展项目论文和综合面试。尚未获得目标岗位、具体项目、可用 GPU 与个人贡献，所以先提供可替换的架构，而不假定你已经做过以下实验。

如果偏研究，优先推导和消融；如果偏模型工程，优先输入输出一致性和评测；如果偏 infra，优先容量账本和性能测量。四条主线保留共同接口，之后可以调整深度。

## 知识架构：四条主线 × 四个层次

| 主线 | 原理 | 实现 | 系统 | 验证 |
|---|---|---|---|---|
| Diffusion | 去噪与速度场 | 参数化、条件与采样器 | 分辨率、NFE、显存 | 覆盖、条件一致性、质量 |
| LLM | 自回归与 attention | mask、位置与 adapter | KV、并行、kernel | 正确率、长度、泛化 |
| Agent | 决策与反馈 | 工具、状态与轨迹 | 环境等待、并发、策略版本 | 任务成功、可靠性、成本 |
| Infra | 容量与通信 | 分片、重算、调度 | 阶段时间线与队列 | goodput、尾延迟、GPU-hour |

这张表避免某个方向只积累术语。每个新概念至少说明它位于哪一层，以及怎样验证它确实起作用。

## 两个小型实践支点

**支点 A：生成模型对照实验。** 从二维数据的 DDPM/Flow Matching 起步，再按资源选择现成图像模型采样。统一 seed、目标、时间约定与 NFE 日志，比较分布、质量和耗时。这能连接 diffusion 原理与性能观察，不要求训练大型模型。

**支点 B：可评测的工具 Agent。** 在少量公开文档或可重复的代码任务上，先做固定流程 baseline，再做有预算的工具循环。记录每轮真实输入/action/结果，评测最终产物与成本。需要训练时才加 SFT、OPD 或 RL，不在一开始把所有方法混到一起。

它们是可选的学习工程，不是新增的项目经历材料；先把一个支点做出可复现证据，再决定是否扩展。

## 代码架构示意

```text
configs/       模型、数据、预算、版本与 seed
models/        前向、参数化和 adapter；不混入任务判分
runners/       diffusion 采样 / llm 生成 / agent 循环
training/      数据构造、loss mask、概率重算与更新
systems/       profiling、队列、缓存与并行配置
evaluation/    数据划分、grader、指标聚合
artifacts/     配置快照、轨迹、曲线、失败案例与来源
```

上面是建议结构，不会在笔记站内创建空训练框架。采样器/模型/奖励/调度保持明确边界，便于换组件和做对照。

接口要包含状态与版本：样本 ID、模型版本、输入条件、token 或 latent 的约定、停止原因、资源用量和评分证据。目录名并不保证模块化，能否独立替换和核验才是重点。

## 一次实验的最小证据链

1. 问题：例如减少采样 NFE 是否损害条件一致性？
2. baseline：固定模型、prompt、seed 集与硬件。
3. 单变量：只改步数，或只改上下文策略。
4. 指标：质量 + 延迟/成本；同时保存失败样本。
5. 结论：描述适用条件，区分已验证、推测和未验证。

Agent 后训练中尤其检查训练与采样的上下文一致性；infra 中尤其检查测量边界和异步执行；diffusion 中尤其检查时间方向、日程与输出参数化。

## 如何贴合真实项目

后续用真实信息填：目标岗位与任务；数据/环境；可用硬件；采用的 baseline；个人负责的模块；一个可核验结果；尚未解决的失败。再将对应笔记链接放进项目索引，不重复复制理论，也不代造结果。

从 [学习路线](#q=learning-roadmap) 选一个当前最薄弱的环节开始，算法与综合面试暂不扩量。
